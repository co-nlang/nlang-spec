# n/ Language Specification - 代數憲法與標準庫 (Algebraic Constitution)

本章節定義 `n/` 預設提供的代數結構、型別、標籤與元資訊行為。
`n/` 的標準庫建立在 **量子化範疇論 (Quantum Category Theory)** 之上的純粹模型，所有的代數操作本質上都是對 Hilbert 子空間的投影或算子變換。

---

## 1. 核心代數公設 (Core Algebraic Axioms)

任何子空間，只要實作了對應的 `%meta` 欄位，即視為具備該代數結構。引擎在觀測管道演化（`|>`）時，會優先利用這些結構進行算子升寫。

### 1.1 函子 (Functor - `%fmap`)
*   **語義**：「子空間保全的態射」。
*   **實作範例 (@Box)**：
    ```nlang
    @Box: {
        %val: @any
        %fmap: (f: @morphism) -> { 
            %val: f $.%val    ;; 將算子應用於內部態向量
            %kind: #data 
        }
    }
    ```

### 1.2 可折疊 (Foldable - `%fold`)
*   **語義**：「子空間的聚合」。
*   **介面**：`(accumulator, operator) -> result`

### 1.3 幺半群 (Monoid - `%empty` + `%concat`)
*   **語義**：「可合併的子空間」。
*   **在 n/ 中的表現**：對於 Combo，`%concat` 預設同構於子空間的正交合併 `&`。

### 1.4 單子 (Monad - `%bind`)
*   **語義**：「幾何投影的鏈式組合」。
*   **介面**：`(f: @morphism) -> f $.%val` (自動解封與重投影)。

### 1.5 符號與算子映射 (Symbol Mapping)

為了保證語法的穩定性與使用者擴充性的平衡，核心符號運算子預設態射至對應的 `%meta` 介面。

| 運算子 | 維度 | 代數介面 | 說明 |
| :--- | :---: | :--- | :--- |
| **`+`** | 二元 | **`%concat`** | 優先調用幺半群合併。 |
| **`\`** | 二元 | **`%diff`** | 投影空間差集。 |
| **`-`** | 二元 | **`%sub`** | 數值或算子減法。 |
| **`-`** | 單元 | **`%neg`** | 負號：複數取負。 |
| **`!`** | 單元 | **`%compl`** | **正交補**：子空間的正交否定。 |
| **`*`** | 二元 | **`%mul`** | 數值乘法或張量積。 |
| **`/`** | 二元 | **`%div`** | 數值除法。 |

## 2. 內建型別系統 (Built-in Types)

`n/` 的內建型別建立在 **正交模格 (Orthomodular Lattice)** 的譜幾何之上。所有型別本質上都是對 Hilbert 空間子空間的幾何約束。

### 2.1 型別層次結構

```
@any  (⊤ 萬有型：所有子空間的幾何聯集)
  ├── @unit       (單元型：零維子空間，僅含 #unit)
  ├── @bool       (布爾型：兩點離散格 {⊥, ⊤})
  ├── @num        (譜數值型：複數域 ℂ 的投影)
  │     ├── @complex  (複數子空間：ℝ² 的連續幾何)
  │     │     └── @float   (實數軸投影：IEEE 754 雙精度)
  │     └── @int     (整數格：離散一維鏈 ℤ)
  │           └── @u8..@u256, @i8..@i256  (固定寬度投影，FFI 邊界)
  │
  ├── @str        (字符串：字符序列的張量積)
  ├── @list       (列表：同型子空間的直和)
  ├── @combo      (組合型：任意欄位結構的張量積)
  │     └── @record   (記錄型：封閉欄位集的直和)
  │
  ├── @morphism   (態射型：子空間間的連續映射)
  ├── @type       (型別型：型別本身的幾何元)
  └── @caid       (內容定址標識符：譜指紋)
```

### 2.2 數值型別的譜幾何

#### @num：譜萬有型 (Spectral Top)

*   **幾何定義**：複數平面 ℂ 的完整表示，作為所有數值子空間的萬有母空間。
*   **CAID 特徵**：`hash:sha256:v1:0005...`
*   **格論性質**：連續無限格，支援任意兩點間的凸組合。
*   **運算語義**：所有數值運算在 `@num` 層面於複數域進行，投影至子型別時可能發生相位坍縮。

#### @complex：複數子空間

*   **表示**：`{ re: @float, im: @float }` 的等價類
*   **幾何結構**：ℝ² 連續平面，具備旋轉對稱性
*   **運算**：完整的複數代數（加、乘、共軛、模、幅角）
*   **投影至 @float**：`complex -> sqrt(re² + im²)`（模長）或 `re`（實部）

#### @float：實數連續投影

*   **幾何定義**：實數軸 ℝ 的區間連續格
*   **IEEE 754 對應**：雙精度浮點（64-bit）
*   **特殊值映射**：
    *   `NaN` → `_|_` (%cause: #numerical_error)
    *   `+Inf` → `#_` (序位最大元)
    *   `-Inf` → `#_|_` (序位最小元)
*   **格論運算**：`<`、`>` 定義區間偏序；`&` 定義區間交集

#### @int：整數離散格

*   **幾何定義**：整數軸 ℤ 的離散一維鏈
*   **精度**：任意精度 (BigInt)
*   **格論運算**：
    *   `min` 作為 Meet (∧)
    *   `max` 作為 Join (∨)
    *   `gcd` 作為格論交錯運算
*   **位元運算**：僅在 `@int` 及其固定寬度子型別定義，視為離散格的對稱變換

### 2.3 型別間的偏序關係

| 子型別 | 父型別 | 關係說明 |
| :--- | :--- | :--- |
| `@int` | `@num` | 離散一維鏈嵌入連續複數平面（虛部恆為零） |
| `@float` | `@num` | 實數軸作為複數平面的實軸子空間 |
| `@complex` | `@num` | 同構關係（`@num` 的預設幾何實現） |
| `@u8` | `@int` | 有限區間 `[0, 255]` 作為整數格的子格 |
| `@i32` | `@int` | 有限區間 `[-2³¹, 2³¹-1]` 作為整數格的子格 |

### 2.4 型別投影與坍縮

當 `@num` 值被約束至子型別時，發生**幾何投影**。

#### 靜態約束 vs 動態投影

| 語法 | 語義 | 處理時機 |
| :--- | :--- | :--- |
| `@Type: value` | **靜態型別約束** | 定義時（解析階段） |
| `value & @Type` | **動態幾何投影** | 觀測時（執行階段） |

**關鍵區別**：
- `@int: 3.7`：引擎在**解析時**即確認型別邊界，可進行靜態優化與早期錯誤偵測
- `3.7 & @int`：在**觀測路徑抵達時**才執行合併與投影運算，允許延遲求值與條件分支

#### 數值投影範例

```nlang
;; 【靜態約束】解析時即確定型別
@int: 3.7      ;; 坍縮為 4（預設四捨五入）
@float: 2+3i   ;; 坍縮為 2.0（實部）或 3.605...（模）

;; 【動態投影】觀測時執行合併
123 & @float   ;; ✅ 成功：123 ∈ @float，結果為 123.0
               ;; 注意：123 預設為 @num，尚未約束為 @int

@int: 123 & @float  ;; ❌ 衝突：@int 與 @float 為正交子空間
                    ;; 結果：_|_ (%cause: #projection_conflict)
```

**設計原則**：靜態約束優先於動態投影，以支援編譯期檢查與優化。

#### 投影衝突

```nlang
;; 投影衝突：@int & @float 的合併
{ x: @int: 5 } & { x: @float: 5.5 }  ;; 結果：_|_ (%cause: #projection_conflict)
```

### 2.5 標準容器型別

| 型別 | 幾何結構 | 代數介面 |
| :--- | :--- | :--- |
| **`@list`** | 同型子空間的可數直和 | `%fmap`, `%fold`, `%concat` |
| **`@option`** | 值子空間與 ⊥ 的聯集 | Monad 結構 |
| **`@result`** | 成功子空間與錯誤子空間的聯集 | 錯誤傳播 Monad |
| **`@str`** | 字符代數的張量積 | 字典序偏序、正則匹配 |

---

核心規格預定義了一組標準型別，所有符合規格的引擎必須內建其定義並對齊其 CAID。

| 型別 | 核心幾何結構 (同構展開) | 創世 CAID (Placeholder) |
| :--- | :--- | :--- |
| **`@list`** | `{ %kind: #type, %fmap: ~%List./map, %fold: ~%List./fold, ... }` | `hash:sha256:v1:0001...` |
| **`@option`** | `@{ @Some \| #none }` | `hash:sha256:v1:0002...` |
| **`@result`** | `@{ @Ok \| @Err }` | `hash:sha256:v1:0003...` |
| **`@morphism`** | `{ %kind: #type, %morphism: #true }` | `hash:sha256:v1:0004...` |
| **`@num`** | `{ %kind: #type, %domain: @complex, %precision: #double }` | `hash:sha256:v1:0005...` |

### 2.6 容器型別：列表 (`@list`)
*   **`%fmap`**：態射所有元素，保持順序與長度。
*   **`%concat`**：列表串接（張量積的特例）。
*   **`%bind`**：即 `~%List./flatMap`。

### 2.7 標籤結構：選項 (`@option`)
*   **定義**：`@Some: { %val: @any } | #none`。
*   **用途**：在不觸發 `_|_` 的情況下處理空值。在量子語義中，`#none` 代表該子空間投影為零維。

### 2.8 邏輯結構：結果 (`@result`)
*   **定義**：`@Ok: { %val: @any } | @Err: { %cause: @any }`。
*   **語義**：`@Err` 攜帶的 `%cause` 可用於錯誤溯源，詳見 **[SPEC_08](./SPEC_08_Meta_and_Runtime.md)**。

### 2.9 數值基底：複數域 $\mathbb{C}$ (`@num`)

為了數學完備性與 EML 算子的自舉，`n/` 確立複數域 $\mathbb{C}$ 為其標準原子數值的物理實作。詳見本章 §2.2。
*   **@num**：代表複數平面上的特徵值。`5` 實質上是 `5 + 0i`。
*   **幾何相位**：所有的數值運算皆保留相位資訊，直到投影至實數觀測軸。
*   **格論性質**：支援數值比較與區間收斂。
*   **算術 Monoid**：加法 (`%empty: 0`) 與 乘法 (`%empty: 1`)，均在複數域上定義。

### 2.10 字串 (`@str`)
*   **格論性質**：支援與正則表達式 `@regex` 的交集運算。
*   **語義**：字串可視為字符的數值 Combo，具備字典序的偏序關係。

## 3. 數學 LUCA：EML 算子 (~%Math)

根據 [arXiv:2603.21852v2]，`n/` 採用單一二元算子 **EML (Exp-Minus-Log)** 配合常數 **`1`** 作為所有初等函數的最後共同祖先。

### 3.1 核心種子定義
```nlang
~%Math: {
    ;; 核心算子：eml(x, y) = exp(x) - ln(y)
    ;; 內部在複數域 ℂ 計算，對外投影至實數軸（虛部為零時返回實數，否則保留複數）
    /eml: (x: @num, y: @num) -> @num
    /eml.%effect: #pure
    one: 1
}
```

**語義說明**：
*   **複數域計算**：`exp(x)` 與 `ln(y)` 在複數域 $\mathbb{C}$ 上定義。例如 `ln(-1) = i\pi`，故 `/eml(1, -1)` 的內部計算為 $e^1 - i\pi$。
*   **實數投影**：結果型別 `@num` 表示最終觀測投影至實數軸。若虛部非零，引擎保留複數表示；若虛部為零（在容差範圍內），坍縮為實數。
*   **純粹性標記**：`%effect: #pure` 表示 EML 是純函數——相同輸入總是產生相同的譜特徵（雖然中間過程可能涉及複數，但觀測結果是確定性的）。

#### 奇異點處理與分支切割 (Singularities & Branch Cuts)

EML 運算在複數域中可能遭遇奇異點，引擎必須以 `#blur` 狀態回應，而非產生未定義行為：

| 運算情境 | 數學問題 | 處理方式 |
| :--- | :--- | :--- |
| `ln(0)` | 對數奇異點 | 回傳 `#blur`，標記 `%cause: #log_singularity` |
| `ln(-1)` 無 `%branch` | 分支跳躍 | 預設主分支（$-\pi < \arg \le \pi$），回傳 `iπ` |
| `eml(x, 0)` | `exp(x) - ln(0)` | 回傳 `#blur`，標記 `%cause: #eml_singularity` |
| `sqrt(-1)` | 虛數單位 | 回傳 `i`（複數表示）|

**分支層級宣告 (`%branch`)**：

觀測者可透過 `%branch` 元欄位顯式選擇 Riemann 面層級：

```nlang
complex_result: /eml(0, -1) {
    %branch: 0    ;; 主分支（預設）
}

next_sheet: /eml(0, -1) {
    %branch: 1    ;; 第一層 Riemann 面（arg + 2π）
}
```

*   **預設行為**：未宣告 `%branch` 時，使用主分支（Principal Branch）。
*   **觀測限制**：不同分支的結果無法在實數投影下區分，但在複數表示中具備不同虛部。
*   **格論語義**：分支選擇視為對複數子空間 `@complex` 的額外延拓約束，不改變 `@num` 層面的幾何本質。
*   **決定論要求（Invariant 1）**：主分支約定是跨引擎收斂決定論的必要條件。若引擎使用非主分支（如不同 Riemann 面或 arg 範圍），必須在 `%branch` 中顯式宣告，否則可能在負實軸附近產生高達 $2\pi i$ 的結果差異，違反 CAID 穩定性保證。

### 3.2 派生函數發育樹

所有的標準函數皆由 `/eml` 與 `1` 自舉產生，並作為幾何別名存在：
*   **`/exp`**, **`/ln`**, **`/add`**, **`/sub`**, **`/mul`**, **`/div`**, **`/sin`**, **`/cos`**, **`/sqrt`** 等。
*   **`/random`**：`(): @unit` -> **[#nondet]** 產生 [0, 1) 之間的隨機特徵值。

### 3.3 語義層與執行層的分離 (Semantic vs Execution)

**核心原則**：EML 樹是數學結構的「規範化原形」，原生指令執行是對此原形的「物理近似」。

#### 靜態語義層（CAID 計算）

EML 樹在**解析/編譯階段**即確定其結構身分：
- **結構決定論**：相同的 EML 樹拓撲產生相同的規範化表示
- **無數值計算**：此階段不進行實際浮點運算，僅建立結構
- **CAID 來源**：基於 EML 節點的結構雜湊，非執行結果
- **使用者視角**：呼叫 `/ln(x)` 時，語義上等同於 `eml(1, eml(eml(1, x), 1))`

#### 動態執行層（數值計算）

執行階段將 EML 樹「降級」為硬體指令（Operator Lowering）：
- **降級策略**：`eml(x,y)` → 展開為 `exp`, `ln` 等原生呼叫
- **誤差容許**：執行結果可能因策略而異，但必須符合 IEEE 754 規範的誤差範圍
- **效果標記**：若使用優化策略，引擎**應**標記 `%effect: #approximate`
- **CAID 不變**：無論執行策略如何，EML 樹的 CAID 保持穩定

#### 視角轉換

| 視角 | 方向 | 說明 |
| :--- | :--- | :--- |
| **規格視角** | EML 樹 → 原生指令 | EML 是原形，執行是近似 |
| **使用者視角** | 原生指令 → EML 樹 | `/ln(x)` 在語義上展開為 EML |
| **實作視角** | 雙向映射 | 引擎可識別 `/ln` 為 EML 結構的語法糖 |

**重要區分**：
- `/ln` 作為「態射名稱」是 `~%Math` 標準庫的介面
- `/ln` 的「語義定義」是 `eml(1, eml(eml(1, x), 1))`
- 引擎可選擇直接執行硬體 `log`，但必須保證結果在 EML 語義的誤差容限內

### 3.4 數學態射完整參考

`~%Math` 提供了一組純粹的數值態射。其中大部分態射與二元運算子（如 `+`, `-`）具備 1:1 的映射關係。

| 態射 (Morphism) | 參數型別 | 說明 |
| :--- | :--- | :--- |
| **`/add`** | `x y: @num` | 數值加法。等價於 `x + y`。 |
| **`/sub`** | `x y: @num` | 數值減法。等價於 `x - y`。 |
| **`/mul`** | `x y: @num` | 數值乘法。等價於 `x * y`。 |
| **`/div`** | `x y: @num` | 數值除法。等價於 `x / y`。 |
| **`/rem`** | `x y: @num` | 取餘數。等價於 `x % y`。 |
| **`/abs`** | `x: @num` | 絕對值（模）。複數返回 $\\sqrt{x^2 + y^2}$。 |
| **`/pow`** | `x y: @num` | 次方運算 $x^y$。 |
| **`/sqrt`** | `x: @num` | 平方根。 |
| **`/exp`** | `x: @num` | 指數函數 $e^x$。 |
| **`/ln`** | `x: @num` | 自然對數。 |
| **`/sin`** | `x: @num` | 正弦函數（弧度）。 |
| **`/cos`** | `x: @num` | 餘弦函數（弧度）。 |
| **`/bitAnd`** | `x y: @int` | 位元「與」運算（僅限整數投影）。 |
| **`/bitOr`** | `x y: @int` | 位元「或」運算。 |
| **`/bitXor`** | `x y: @int` | 位元「異或」運算。 |
| **`/bitNot`** | `x: @int` | 位元「非」運算。 |
| **`/shl`** | `x n: @int` | 位元左移。 |
| **`/shr`** | `x n: @int` | 位元右移。 |
| **`/random`** | `(): @unit` | **[#nondet]** 產生 [0, 1) 之間的隨機特徵值。需傳入 Unit 觸發。 |

*註：位元運算僅在數值投影至整數子空間時定義。若輸入為非整數複數，結果為 `_|_` (%cause: #fractional_bitwise)。*

## 4. 預設效果標籤 (#Effect)

| 標籤 | 語義 |
| :--- | :--- |
| **`#pure`** | 么正變換。不與環境糾纏。 |
| **`#io`** | 與外部子空間進行觀測交換。 |
| **`#nondet`** | 包含非決定性坍縮（如隨機數）。 |
| **`#state`** | 依賴或修改環境投影狀態（如 `~%repl`）。 |
| **`#cached`** | 曾有的干涉結果已被固化為穩定的 CAID 投影。 |

### 5.2 條件控制與惰性語義 (`~%Cond`)

`~%Cond` 提供顯式的條件分派態射，作為模式匹配的補充。所有條件態射均遵循**惰性求值 (Lazy Evaluation)** 語義：分支僅在被選中時才會被觀測與收斂。

| 態射 | 型別 | 說明 |
| :--- | :--- | :--- |
| **`./if`** | `(cond: @bool, then: (@any -> @any), else: (@any -> @any)) -> @any` | 顯式條件分派。`then` 與 `else` 參數為態射（通常以 `(@any -> body)` 形式傳入），確保分支惰性求值。 |
| **`./cond`** | `[@{ @any: (@any -> @any) }] -> @any` | 多條件鏈式分派。依序測試條件，返回第一個匹配分支的結果。 |
| **`./match`** | `(value: @any, patterns: @{ @any: (@any -> @any) }) -> @any` | 值模式匹配。將 `value` 與 `patterns` 中的每個模式進行合併嘗試，返回第一個成功匹配分支的結果。 |

#### 範例：使用 `~%Cond`

```nlang
_: ~%Cond  ;; 合併到當前根節點

;; /if: 基本條件分派
result: /if (@x > 0, (@any -> "positive"), (@any -> "non-positive"))

;; /cond: 多條件鏈式分派
grade: /cond [
    { @score & >= 90: (@any -> "A") }
    { @score & >= 80: (@any -> "B") }
    { @score & >= 60: (@any -> "C") }
    { _: (@any -> "F") }
]

;; /match: 值模式匹配
status: /match @http_code {
    200: (@any -> "OK")
    404: (@any -> "Not Found")
    @int: (@any -> "Other Error")
}
```

**語義說明**：
- `(@any -> @any)` 型別表示一個接受任意輸入、返回任意輸出的態射。在實際使用中，通常以 `(@any -> body)` 的匿名態射形式傳入。
- 惰性求值保證：若 `cond` 為 `#true`，則 `else` 分支完全不會被觀測；反之亦然。這對於避免無限遞迴或昂貴的副作用計算至關重要。

### 5.3 外部函數介面 (Foreign Function Interface)

為了支援與現實世界的互操作性，`n/` 允許態射由外部程式（如 C, Rust, JS）實作。詳見 **[REAL_01](./REAL_01_Ouroboros_Engineering.md)**。

*   **純粹性與沙箱**：若外部函數標記為 `#pure`，引擎**必須**遵循沙箱隔離義務，確保環境欄位與時間不影響觀測結果。
*   **效果傳播**：外部函數若標記為 `#io` 或 `#nondet`，其效果將透過態射傳染規則傳播至呼叫者。
