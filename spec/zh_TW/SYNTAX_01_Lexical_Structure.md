# SYNTAX_01：詞法結構 (Lexical Structure)

> [!NOTE] 定位
> 本章為**語法細則**（規範性，位階在 SPEC 之下；見 **[SYNTAX_00](./SYNTAX_00_Conventions.md)**）。文法上位規範見 **[SPEC_14](./SPEC_14_Formal_Grammar.md) §2.1–2.2**；語義以 SPEC 為準；範式背景見 **[APP_03](./APP_03_Paradigm_Comparison.md)**。本章釘死「原始字元流如何切成 token」這一層的所有歧義。

---

## 1. 語法 (Syntax)

詞法層把原始字元流切成 **token**。以下三條規則摘自 **SPEC_14 §2.1**（為上位文法，本章不改寫）：

```ebnf
WHITESPACE = _{ " " | "\t" | "\n" | "\r\n" | "\r" }
COMMENT    = _{ ";;" ~ (!("\n" | "\r\n" | "\r") ~ ANY)* }
field_sep  = _{ "," | ";" | WHITESPACE+ }
```

`_{ }` 表示**靜默規則 (silent rule)**：`WHITESPACE` 與 `COMMENT` 被自動略過，不進入 AST。

token 類別（細節各有專章，本章只定其為合法 token）：

| 類別 | 形式 | 詳見 |
| :--- | :--- | :--- |
| 識別碼 / 命名鍵 | `ident`（`XID_START`/`_` 起首，後接 `XID_CONTINUE`/`_`/`-`） | SPEC_14 §2.2 |
| 數字鍵 | `numeric`（`ASCII_DIGIT+`） | SYNTAX_02 |
| 前綴 | `@` `/` `%` `~%` `~`（可組合） | SYNTAX_05 |
| 引用鍵 | `quoted_key`（`"…"`，含空格或運算子的鍵） | SYNTAX_03 |
| 字面量 | `()`、`#tag`、數字、字串、`_`、`_\|_` | SYNTAX_02 |
| 運算子 | `&` `\|` `\` `\|>` `->` `==` … | SYNTAX_06 |
| 容器分隔符 | `{ }` `( )` `[ ]` `{{ }}` `@{ }` `#{ }` `< >` | SYNTAX_04 |

## 2. 語義 (Semantics)

詞法層**不**賦予意義——它只切 token，語義由 SPEC 決定。三條規範性事實：

1. **註解與空白是不顯著的 (insignificant)。** 兩者**必須**在進入語法分析前被略過，**不**出現在 AST，**不**影響任何觀測結果。
2. **`n/` 非縮排敏感。** 縮排與換行**不**表示結構；結構只由容器分隔符（`{}` 等）與路徑決定。空白僅作為 token／欄位的分隔。
3. **欄位分隔符語義等價於空白。** 在**欄位層**，`,`、`;`、空白、換行完全等價（SPEC_14 §2.1）；它們只分隔欄位，不攜帶語義。

---

## 3. 範例 (Examples)

```nlang
;; 註解可以出現在任何地方
   ;; 多個分號也合法
        ;;;;;;; 這樣也不算錯
a: #true   ;; 行尾註解
```

欄位分隔符的等價寫法（SPEC_14 §2.1）。**n/ 慣用換行分隔**——符合程式書寫習慣，且每欄一行對 `git` diff 最友善：

```nlang
;; n/ 慣用：換行分隔
{
    a: 1
    b: 2
    c: 3
}
```

以下三種與上式**完全等價**，只是分隔符不同：

```nlang
{a: 1, b: 2, c: 3}     ;; compact（JSON-like）
{a: 1; b: 2; c: 3}     ;; 分號分隔
{a: 1 b: 2 c: 3}       ;; 純空白分隔（單行）
```

## 4. 邊界情況 (Edge Cases)

> 本節是 SYNTAX 系列存在的理由——逐條釘死曾經模糊的詞法行為。

1. **只有行註解，沒有區塊註解。** `;;` 起始的註解**必須**延伸至**該行結尾**為止（`COMMENT` 規則止於換行）。`n/` **不**提供 `/* … */` 式跨行註解；跨行說明需逐行加 `;;`。
2. **`;` 的雙重身分（消歧義）。** `;` 既是欄位分隔符、`;;` 又是註解起首。規範：**連續兩個 `;` 一律解讀為註解起始**（最長匹配，`COMMENT` 優先），其後整行皆為註解；單獨一個 `;` 才是欄位分隔符。故 `a: 1 ; b: 2`（單 `;`）= 兩個欄位；`a: 1 ;; b: 2`（雙 `;`）= 一個欄位 `a: 1` 加一段註解 `b: 2`。
3. **分隔符只在欄位層，嚴禁在表達式層。** `,`／`;` 作為分隔符**僅**適用於 Combo／Cocoon 的欄位之間。在表達式內**嚴禁**用 `,` 分隔（如 `/add a, /sub b` **非法**），以免與態射應用的空白運算子衝突（SPEC_14 §2.1）。表達式層的多參數須用 tuple（見 SYNTAX_09）。
4. **多餘分隔符可被吸收。** 連續的逗號、分號或空行視為單一分隔；引擎**應**容忍並略過多餘分隔符，`oo fmt` 預設**會**移除多餘逗號（單行 compact 模式除外）。
5. **識別碼字元集。** 識別碼以字母或 `_` 起首，後續**可**含 `XID_CONTINUE`、`_` 與連字號 `-`；採 Unicode `XID_START`/`XID_CONTINUE`，故中／日／韓等非拉丁字元皆為合法座標名。含空格或運算子的鍵**必須**用引用鍵 `"…"`（見 SYNTAX_03）。
6. **空白在態射應用處雖非強制分隔符，仍規範保留。** `apply_expr` 的重複匹配允許零空白，故 `/f ()` 與 `/f()` **文法上解析相同**（皆為 `/f` 應用於 `()`）；但省略空格會讓 `/f()` 看起來像括號界定的呼叫語法（與 `n/` 空白即運算子的 juxtaposition 模型相悖），規範**建議**（SHOULD，非強制）保留空格以維持心像一致（此處點名，細則見 **SYNTAX_09**）。
7. **檔首與檔尾。** 一份程式為 `SOI ~ WHITESPACE* ~ (field ~ field_sep?)* ~ EOI`；檔首允許前導空白／註解，檔尾允許懸空分隔符。
8. **識別碼中的連字號 vs 中綴減法。** `ident` 允許 `-` 於中段（kebab-case：`max-retry` 是單一識別碼），且識別碼為 atomic 最長匹配——因此 **`a-1`／`a-b` 是單一識別碼，不是減法**。識別碼後的減法**必須**在 `-` 前留空白：`a - 1`、`a -1` 皆為減法（表達式層由 `!add_op` 前瞻與 juxtaposition 區隔，見 SYNTAX_02 §4.3）。以數字開頭的序列不受影響（`1-2` 仍為減法，因數字非識別碼起首）。`oo fmt`／診斷**宜**（SHOULD）在易混場景（如 `a-1` 與 `a` 皆有定義）提出警告。
