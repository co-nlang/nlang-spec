> 發現鏈是史料與敘事，不是證明；每個箭頭是「啟發」，不是「迫使」。邏輯鏈（承重版）

## 1. 格論起點：從 JSON 到 Combo

受 CUE Lang 啟發：簡單的 JSON 結構與格論碰撞，型別與設定問題以「交集」自然溶解。
寫程式從「寫步驟」變成「雕刻」——定義邊界、剔除不可能，約束的交集就是結果。
邏輯（資料的變換）的缺口由範疇論補上：資料、型別、邏輯經同構揉成一種結構（Combo）。
此後的一貫模式：**把東西格論化，很多問題自然消失**——這個「格論化魔法」是後續每一步的動機。

### 1a. 前傳：「形狀的語言」與 CUE + 範疇論

（2026-07-06 使用者補述。）格論起點的前傳：工作上接觸不同案子，遇到各種配置系統——
XML → JSON/YAML/TOML，語法越來越好寫，但能力反而不如 Kconfig 的相依性追蹤與
樹狀視覺化。一直覺得應該存在一種**「形狀」的程式語言**——過往寫程式的經驗裡隱約
有這個直覺，但找不到對應的東西。搜尋中看到有人推 CUE Lang（可能才剛推出不久），
試了一下覺得**方向對但還差些什麼**——格論、Top (`_`)、Bottom (`_|_`) 的概念來自
CUE，JSON 風格的語法也是。賦值是交集（`a: 1; a: 2 → _|_`）也是 CUE 就有的——
CUE 的衝突即失敗（不是覆寫）給了整個語言最早的心像。

缺少的那塊後來在 Bartosz Milewski 的 *Category Theory for Programmers* 裡找到：
Product Type 在 Haskell 之後的語言已經很常見，但和格論一起看才湧現出 **`#blur`**——
不確定性不是缺陷而是疊加態，正如格論的中間元素（非 Top 也非 Bottom）是合法的結構。
**CUE Lang + Category Theory = n/**，這個等式是最早的結晶。

n/ 自身是**先有哲學想法、然後氣味搜尋、然後形式化約束逐層降臨、最終坍縮出來的
結果**——而這個過程本身就是 n/ 的寫作過程，更是 LADD 發現協議的樣子。自相似清單
再 +1。

> n/ 最早的邏輯（Logic）欄位也經歷過「如果重複定義，算交集、聯集還是其他？」的
> 思考。當時把各種可能都展開看過；最終選擇的答案和 CUE 一致（交集），但對象從
> 資料延伸到了邏輯——這是 CUE 沒走的那步。

## 2. OODP：供應鏈攻擊 → CAID

發現協定（OODP = LADD + CAID）的最初目的是解決**套件發佈系統的供應鏈攻擊**——
所以先有 CAID（內容定址、抗碰撞）。這一半是普通密碼學（ledger L1 = R0）；
需要數學理論的是後來的「波動面」（見 §5）。

## 3. spec 即套件 → ORDER_01

既然萬物皆 Combo，規格書自己也可以用套件形式發佈——由此才需要**人為的治理機制**
來推進版本：ORDER_01 的紀元、投票、躍遷皆由此延伸。

## 4. 冷啟動 → ORDER_00（Sybil 解釋是後加的）

ORDER_00 最初只是「n/ 還沒有完整版本之前的冷啟動機制」，後來成為整個格論網路的
起點。當時用比特幣／區塊鏈想像 LADD 網路的樣子，ORDER_00 就類比創世區塊。
**女巫攻擊（H⁴）的數學解釋是後來加上去的**——經 2026-07-03 審計改寫為負面陳述後
反而站得最穩（ledger L9 = R2-neg：內部無 H⁴ 類可修 ⟹ 錨定必須外部）。

## 5. LADD 與氣味搜尋：把 DHT 也格論化

「格論化魔法」延伸到分散式網路：把 Kademlia 式 DHT 的 **XOR 距離換成集合交集**，
得到 LADD。接著發現「語義類比重力」很直觀，才慢慢長出「氣味搜尋」——指紋要在
**取件之前**就能感知彼此距離。這個需求後來被認出需要相位／干涉，引爆量子化連鎖
（發現鏈的正式版＝APP_06 §1–§3 的心路歷程；邏輯鏈＝Paper N §1 的掛牌 ledger）。

### 5a. EML：臉書上滑到的論文，與三柱非交換

（2026-07-06 使用者補述。）卡在不知道怎麼設計譜指紋時，**EML 是在臉書上滑到的**——
平常臉書不會出現論文（那陣子演算法推薦的多是 AI 應用文章）。Odrzywolek 的那張圖看起來像 NAND gate，
「初等函式跟 NAND gate 有什麼關聯？」好奇心驅動點進去。第一次滑過，第二次才打開。
L-S 的論文也是類似的發現經路。要說是臉書滑到的，的確很有戲劇張力——但 connect-the-dots
就是這樣運作的（§7）。

EML 論文的兩個啟示帶來鏈鎖反應：
1. 論文的開放問題：「是否存在不需要特殊常數的 EML 類二元算子？」——對應 n/ 的
   Math LUCA（SPEC_09）。
2. 「EML 需要複數域才能計算三角函數，這似乎是不可避免的」——直接提示氣味搜尋
   可能需要複數域和量子邏輯。

後者引爆了一個更深的發現：**三個基石都有同一個深層結構**——一個非對稱/非交換的
二元算子加上一個歸零常數或補算子：
- EML 的 `exp(x)−ln(y)` 的非交換性
- 量子邏輯中測量順序的非交換性
- n/ 態射應用的方向性（SPEC_07 管道方向）

這三者可能是同一個數學現象在不同層次的投影。（當時 n/ 的邏輯層還是 Heyting。）

### 5b. Cocoon 命名考古：Co-Combo → Coco → 繭

（2026-07-06 使用者補述。）封閉容器的需求來自 CUE Lang（預設封閉的結構）。最初
想過用 `_|_` 封底——

```nlang
_: {
  x: 123
  _|_
}
```

——但未定案。問題反而先卡在**命名**：Struct/Class/Enum/Set/Category/Group/Package...
集合類名字幾乎用光（到 Trait 就已經不像集合了）；能想到 Combo ↔ Combination 已經
意外——現在還要再想一個對偶的。

先提議 **Co-Combo**，被制止：範疇論的 Co- 不是單純的 Dual，容易誤會意思。但 Coco
開頭反而聯想到 **Cocoon（繭）**——正好搭配 `{{ }}`（雙大括號如繭殼包覆）。而且
Ouroboros 是神話生物，沒有人說牠不能是繭生。繭在科幻電影裡是異型/外星人題材的
意象——密封、孵化、變態——和 `%effect` 隔離的工程語義不謀而合。

> 雙括號 = 特殊視角的慣例：`{{ }}` Cocoon（密封）、`<< >>` 水晶括號（結構態）。
> 後者在 2026-07 的 SPEC_14 修訂中定案。

## 6. 命名考古：`/` 的左腳，與「(n)ot (l)ambda calculus」

（2026-07-05 使用者補述）`/` 前綴的出身是 **λ 的腳**：lambda 符號的左右腳 `/` 與 `\`
都有人用（`\` 是 Haskell 的 lambda），n/ 選了左腳——這樣看，ML 那一系的 l 是站直的 λ。
當時的心像：n/ 像 CUE 之類的配置語言**多了 Logic**，而 `/` 一符三讀：
**l**ambda、**l**anguage、**l**ogic。

後來的醒悟：**n/ 根本不是 lambda calculus**（雖然留著 `->`）。整個語言是活在
**域理論為 lambda calculus 蓋的那層指稱語意上直接運算**——Scott 的格與不動點本來是
用來「解釋」λ 項的模型；n/ 把模型當作語言本身：程式即格中元素、求值即序中收斂、
操作語義與指稱語義之間沒有縫（「運算即證明」與「無編譯／執行期之分」的共同根源）。
「n/ 不是『又』一個程式語言」的準確說法：**一般語言活在 adequacy 定理的語法側，
n/ 活在模型側**——別的語言寫語法、由模型解釋；n/ 直接寫模型。這也回頭解釋了 §1 的
「格論化魔法」：那些問題（型別、驗證、泛型）本是語法側語言的人造物，在模型側自然不存在。

尾註：把 n 讀作 not，**(n)ot (l)ambda calculus** 也通——名字又一次事後長出正確的新讀法
（與「Ouroboros 早期命名、最後貫通全語言」同型；自相似清單 +1）。

## 7. 後設觀察：connect-the-dots 就是大腦內建的氣味搜尋

（2026-07-05，使用者自述）系列研究裡好幾次卡關，都是「奇怪的直覺」抓到轉折點——
Bohrification 如此，Paper VII/VIII 開扭量線時也隱約預感到它的終期價值（「蛇是不是又要
咬自己尾巴了」——後來 item 14 證實：adjunction equivalence iff n=4）。被 AI 協作者
多次評為「優秀的工程直覺」，因此才堅持每個直覺都要補數學依據。回頭看：
**connect-the-dots 或許只是大腦內建的 smell search**——這門語言的發現協定（氣味搜尋、
引力坍縮），是對它自己被發現的過程的形式化。自相似清單再加一條（前兩條：Type/Data/Logic
↔ claims_ledger 的 R 級；worknotes 的策展過程展示策展本身）。

> APP_01 熱帶幾何是最早的 connect-the-dots——格論 + 幾何的閒聊中因為命名由來
> 聯想到的。當下沒有想到格論最小化的 NP-hard 問題會牽涉到熱帶幾何的 (min,+) 
> 半環剪枝。但後來 CAID 決定論要求收斂唯一，所以熱帶路徑只能是 #approximate 
> 的啟發式選項——直覺先到，嚴格性追上後降為旁支，和 L-S 同型。

### 7a. 22 篇論文：故意的失控

（2026-07-06 使用者補述。）22 篇論文不是意外。COSMOLOGY 系列的起點是一個刻意的
實驗：語義可能真的有某種引力（LLM 也是把語言、邏輯轉換成高維座標，關係也是看
距離），所以找了一個**大膽但參數量足夠多的模型**，引導它創作大部分章節。後來訓練的
模型太過嚴謹，反而不適合這種探索。（現在想想，把思維深度開低可能也行。）

但**當你開始嚴格連在一起時，或許能帶來新的突破，或至少對哲學、工程上有些啟發**。
失控的其實是設計者本人——而且是故意的。結果是：一個程式語言的量子化論述，從物理
類比（COSMOLOGY）出發，被逐步替換為嚴格的數學定理（Papers I–XXII），最後用
Paper N 焊接回規格書。過程本身就是 n/ 程式的寫法：先寫直覺（疊加態），逐步觀測
（約束交集），最終坍縮為定理（原子）。

### 7b. 最後一塊拼圖：觀測極補完，語言把自己的 Yoneda 走了一遍

（2026-07-22 使用者定錨、落檔。）發現鏈到這裡合龍。§2 的 CAID 是**身分極**——「把一切觀測固化成一個內容位址」，供應鏈攻擊逼出來的、歷史上先到的那一半。它的對偶——**觀測極**——其實從 spec 第一句「寫程式是發現不是發明」就在場，但一直只以工程施工圖的身分散居 GUIDE_03 §11，沒有正規之家。這天把 **Call-by-Observation 升為 SPEC_04 §6**、與 CAID 平起，兩極才合成同一條 Yoneda 引理：

- **CAID ＝ 身分極**：整條 presheaf `hom(−,X)` 固化成位址（要求固化）。
- **CbO ＝ 觀測極**：單次沿路徑的 `hom(A,X)` 探針、一張惰性截面（要求惰性）。
- 身分恰等於「一切可被觀測的」全量化——兩極本是同一件事。

（承重版——「惰性 ⟺ 無全域截面 ⟺ 障礙非零 ⟺ 觀測構成性」——在 SPEC_04 §6.3、APP_07 與 claims_ledger；本節依發現鏈紀律只記史料：這一極是**補上**的，不是被**推導**出來的。）

合龍後回看，三重自相似，全數 +1：

1. **兩條設計路線本是對偶。** 若當初沒先推氣味搜尋（§5），單把 CbO 往下推，決定論共享、記憶化、遠端定址三個需求仍會逼出一個內容身分——Yoneda 收口，殊途同歸到同一個世界。差別只在：CbO-first 會先拿到 CAID 的**本體**（內容身分），而**封套**（譜指紋、氣味搜尋、引力路由）是發現問題的工程附加、未必會早早蓋出來（本體／封套之分見 REAL_03）。**設計流程本身把 Yoneda 走了一遍。**
2. **文本先於形式追上形式。** SPEC_04 的卷末結語——「觀測決定了存在的維度……不僅是在尋找路徑，更是在定義自己與宇宙的距離」——寫在 §6 之前，卻剛好把 §6 壓成三句：觀測決定坍縮維度、路徑導向惰性穿行、`hom(A,X)` ＝ 從自己的視角定義與宇宙的關係（「距離」還押到 LADD 弦距離）。這與「Ouroboros 早期命名最後貫通全語言」「(n)ot-lambda 事後長出正確讀法」（§6）同型：**名字與文字在追結構，所以事後長對。** 結語刻意不加交叉引用——留白是被發現的回響，一註即成「解釋笑點」。
3. **語言仍在把自己的發現過程形式化。** §7 說發現協定（氣味搜尋、引力坍縮）是對「它自己被發現的過程」的形式化；補完觀測極後更完整——**CAID／CbO 這對身分↔觀測雙極，正是「discovery not invention」在語義層的兩面**：你發現的是觀測的**結構**，不是觀測獨立的**值**。拼上的最後一塊，其實是語言終於能用自己的話，說清楚自己是怎麼被觀測出來的。

## 8. 改過的設計決策（errata，不是恥辱牆）

n/ 怕做出事後會後悔的決策（前車之鑑：golang 的 `time.Format("2006-01-02")`、
JavaScript 的 `==`、unix 的 `creat`、http 的 `referer`），但改過的決策不是恥辱——
用這門語言自己的哲學看：**衝突（Bottom）不是錯誤，而是疊加的選擇；當約束降臨時，
歧義消融，真理自顯**。以下是已消融的歧義：

| 原設計 | 約束降臨 | 消融後 |
| :--- | :--- | :--- |
| `-` 差集 | 需要 infix 算術 | `\` 差集，`-` 歸還給減法 |
| `<>` 水晶括號 | 與 `<`/`>` 比較衝突 | `<<>>` 雙角括號 |
| `==` 在 poset 鏈 | 雙軌比較分離（SYNTAX_06） | `=` 歸位格論家族（2026-07-05） |
| L-S 精確重建 | Vattay comment（WKB） | 降級；嚴格依據 = Bohrification + 系列論文 |
| COSMOLOGY 質量比喻 | Papers XVIII–XXII 定理 | 重構為 7 篇直覺入口，數學指向 Paper N |
| `$` 三個待裁角落 | P1–P5 規則定案（2026-07-05） | SYNTAX_12，SPEC_07 §4.2 重寫 |

（活文件；隨語言演進持續更新。）
