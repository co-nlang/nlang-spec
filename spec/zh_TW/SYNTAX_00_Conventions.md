# SYNTAX_00：語法細則總則與慣例 (Syntax Series — Conventions)

> [!NOTE] 定位
> **SYNTAX 系列是 `n/` 語法的「施行細則」。** SPEC 系列是憲法層級的*語義純粹*規範——它定義邊界（Type 層的法），刻意不展開語法細節。但語義純粹在語法上留下了模糊空間（多數已被 **[SPEC_14](./SPEC_14_Formal_Grammar.md)** 綁死，仍有縫隙）。SYNTAX 系列把這些縫隙逐一**釘死為規範**，消除未定義行為——同時補上規格書一直著墨太少的一面：`n/` 終究是一門程式語言。

---

## 1. 為什麼有這個系列：從邊界 (Type) 到存在 (Data)

`n/` 的本體論是「觀測讓邊界坍縮為存在」：**Type（`@a`）是幾何邊界，Data（`a`）是該座標的存在與狀態**。整部規格書的分工正沿著這條軸：

- **SPEC 系列** 定義**邊界**—格論、Combo、導航、收斂的*語義法則*。它回答「這個構造*是什麼*」，並維持憲法級的語義純粹（工程在 REAL、數學在 APP、物理直覺在 COSMOLOGY）。
- **SYNTAX 系列** 把邊界**坍縮為存在**—你實際*寫下*的具體形式、它的逐構造行為、以及邊界情況。它回答「這個構造*怎麼寫、會怎麼坍縮*」。

換句話說：讀完 SPEC 系列，你會知道 `n/` 的法理；讀完 SYNTAX 系列，你能無歧義地把一段 `n/` 寫出來、並預測引擎如何觀測它。這也是 `n/` 本身的縮影—把抽象的 Type 觀測成具體的 Data。

> [!IMPORTANT]
> SYNTAX 系列 **只**釘語法—形式、坍縮行為、邊界情況。不解釋「為什麼 `n/` 的範式這麼不一樣」，或是「衝突 `_|_` 不是錯誤」、「觀測對偶」這類思維/範式轉換；進階範式歸 **[APP_03：範式比較與遷移](./APP_03_Paradigm_Comparison.md)**。 
> *遇到範式層的疑問，SYNTAX 各章以一句 cross-reference 指回 APP_03，不重述。*

---

## 2. 位階與權威 (Rank & Authority)

SYNTAX 系列具**規範性**，但位階在 SPEC 系列**之下**。權威由高至低：

1. **SPEC 系列（含 [SPEC_14](./SPEC_14_Formal_Grammar.md) 正式語法）** — 憲法級。語義法則（SPEC_01–18）與「什麼能被解析」的正式文法（SPEC_14）。
2. **SYNTAX 系列（本系列）** — 細則級。在 SPEC 劃定的範圍內，把*寫法、坍縮行為、邊界情況*釘死為規範。
3. **REAL / GUIDE 系列** — 實作與風格。

**衝突解決（防火牆）：** 若 SYNTAX 的任何條文與 SPEC（尤其 SPEC_14 文法、或某 SPEC_xx 的語義）牴觸，**一律以 SPEC 為準**，並視為本系列的缺陷待修。SYNTAX 條文**不得**擴張或改寫語義；它只能在 SPEC 允許的解釋空間內*消除歧義*。

**三者分工（同一構造，三種權威）：**

| 文件 | 對什麼有權威 | 角色 |
| :--- | :--- | :--- |
| **SPEC_14** | *什麼能被解析*（EBNF、優先權、邊界保護） | 正式文法 |
| **SPEC_01–18** | *語義為何*（格論／Combo／收斂法則） | 語義憲法 |
| **SYNTAX_XX** | *怎麼寫、會怎麼坍縮、邊界情況* | 施行細則（本系列） |

每一章 SYNTAX **必須**指回它所依據的 SPEC_14 文法規則與相關 SPEC_xx 語義；本系列不重述、不取代上位規範。

## 3. 規範用語 (Normative Keywords)

本系列沿用 SPEC 的規範用語：**必須 / 嚴禁 (MUST / MUST NOT)**、**應 / 不應 (SHOULD / SHOULD NOT)**、**可 (MAY)**。未標規範用語的散文為解釋性說明，不構成額外義務。範例中以 `;;` 註解標示預期的觀測結果。

**系統反映命名（2026-07-23 正規化）**：`~%` 系統反映（引擎鑄造的系統軸物件，SPEC_09 §6）一律 **TitleCase 單首字大寫**——`~%Config`／`~%Engine`／`~%Math`／`~%Repl`／`~%System` 等；縮寫亦然（`~%Csv`，非 `~%CSV`；`~%Repl`，非 `~%REPL`）。測試欄前綴 `~%test`／`test_` 屬**測試標記**（與 `test_` 平行），非系統反映，維持小寫，不受此律。

## 4. 每章格式 (Per-Chapter Template)

為維持一致性，每章 SYNTAX **必須**採固定結構（風格參照 Rust Reference：逐構造、語法＋語義＋範例＋邊界情況）：

```
# SYNTAX_NN：<構造名稱>
> 定位註：本章為細則；文法見 SPEC_14 §x，語義見 SPEC_yy。

## 1. 語法 (Syntax)        — 形式與它所實例化的 SPEC_14 規則
## 2. 語義 (Semantics)     — 簡述意義並指回 SPEC_yy（不重述證明）
## 3. 範例 (Examples)      — 標註觀測結果
## 4. 邊界情況 (Edge Cases) — 釘死歧義（可選逗號、%kind 衝突、_|_ 吸收…）
## 5. 對應 (See Also)      — SPEC_14 / SPEC_xx / 鄰章 SYNTAX
```

§4「邊界情況」是本系列存在的核心理由——**每一條曾經是「未定義行為」的縫隙，都應在此被點名並釘死。**

## 6. 與其他系列的關係

- **[SPEC_14：正式語法](./SPEC_14_Formal_Grammar.md)** — 本系列的文法上位規範；每章釘死的寫法都必須是 SPEC_14 文法的合法實例。
- **[SPEC_01–18]** — 語義上位規範；本系列只描述語法坍縮，語義以 SPEC 為準。
- **[APP_03：範式比較與遷移](./APP_03_Paradigm_Comparison.md)** — `n/` 特殊範式與思維轉換的家（衝突≠錯誤、觀測對偶、從他語言遷移）。SYNTAX 釘語法、APP_03 講範式；遇進階範式問題指回此處，**互不重述**。
- **[GUIDE_01：風格與格式](./GUIDE_01_Style_and_Formatting.md)** — 風格建議（非規範），與本系列的規範性條文互補。

> **總則：** SYNTAX 把 `n/` 從「邊界上的法」帶到「紙面上的存在」。它不發明語義，只讓既有語義在語法層**無歧義地坍縮**。
