# n/ Language Specification - 導航與詞法視界 (Navigation & Lexical Horizon)
本章節定義如何觀測 Combo 結構、導航幾何路徑，以及由嵌套結構形成的**詞法視界 (Lexical Horizon)** 內的符號解析規則。

---

## 1. 觀測對偶性 (Observation Duality)

在 `n/` 中，同一個幾何物件根據觀測濾鏡的不同，展現出兩種投影狀態。

### 1.1 坍縮態 (Collapsed)
直接引用路徑（如 `x`）時，引擎返回的是該節點在格論下的**最優收斂值**（原子或型別）。
*   這是運算子的預設輸入狀態。

### 1.2 結構態 (Structural) —— 水晶括號 `<...>`
使用 `<...>` 包裹節點時，觀測到的是該節點的 **Combo 幾何本體**。
*   **中立性**：結構態觀測是「角色中立」的。它不偏向 Data、Type 或 Logic 中的任何一面，而是展示其最原始的定義結構。
*   **角色判定**：觀測者可透過查詢其元資訊（如 `<x>.%kind`）來判定該節點在宇宙中扮演的主要本體論角色（詳見 **[SPEC_05](./SPEC_05_The_Trinity_Isomorphism.md)**）。
*   **用途**：元資訊查詢、態射傳遞、演化管道輸入。

## 2. 詞法視界優先解析 (Lexical Horizon-first Resolution)

`n/` 使用**動態詞法視界溯源**來解析符號。這確保了定義的局部性與直覺。

### 2.1 裸名稱解析 (Bare Name Resolution)
解析一個不帶根前綴的符號 $s$ 時，引擎在**詞法視界 (Lexical Horizon)** 內執行遞迴搜尋。其形式化演算法如下：

**Algorithm: `resolve_bare_name(s, H)`**
1.  **While** $H \neq \perp$ (未超出根宇宙邊限)：
    - **If** $s \in fields(H)$ **Then** Return $H.s$ (解析成功)
    - **Else** $H \leftarrow parent(H)$ (視界提升)
2.  **Return** $\top$ (若遍歷所有視界仍未匹配，返回萬有集合 `_`)

**語義說明**：
- **$fields(H)$**：包含 $H$ 節點中所有 Data, Type, Logic 與 Meta 欄位。
- **視界提升**：這是一個單向的向上溯源過程，確保了子視界能繼承父視界的上下文。
- **開放世界假設**：最終返回 $\top$ 而非 $\bot$ 的原因在於，`n/` 視「未定義」為「尚未受約束的可能性」。

### 2.2 強制座標前綴
座標前綴用於錨定搜尋起點，阻斷視界提升：
- **`_.` (絕對座標)**：直接從根宇宙開始搜尋。
- **`^.` (相對座標)**：從當前視界開始導航，不進行視界提升。`^^.` 代表從父輩視界開始且不進一步提升。
- **`~.` (私有座標)**：僅在當前路徑及其祖先的私有區域（Local Home）中搜尋。

## 3. 封裝邊界與私有視界 (Encapsulation Boundary)

`n/` 的封裝性不是基於權限控制，而是基於**幾何可達性 (Geometric Reachability)**。

### 3.1 `~` (Local) 欄位的可視性法則
私有欄位 `~key` 的觀測遵循以下嚴格的幾何約束：

1.  **向內可見 (Inward Visibility)**：在定義 `~key` 的 Combo 及其所有子節點、子視界中，該欄位是完全可見且可參與收斂的。
2.  **向外阻斷 (Outward Blockage)**：任何位於該 Combo 外部（父層、兄弟層或跨宇宙路徑）的觀測者，皆無法透過路徑導航直接定位 `~key`。
3.  **違規坍縮**：若外部路徑試圖強制存取（如 `target.~private`），該路徑在觀測時立即收斂為 `_|_` (Bottom)，並標記 `%cause: #private_access_violation`。

### 3.2 視界提升的單向性
*   **子對父 (向外)**：子節點在解析裸名稱時，可以透過「視界提升」觀測到父節點的 `~` 欄位。這允許父節點為所有子節點提供共享的私有狀態（類似物件導向中的 `protected` 或 closure）。
    ```nlang
    ;; 父子共享私有狀態 (Shared Privacy) 範例
    factory: {
        ~secret_seed: 42
        product_a: { val: ~secret_seed + 1 }
        product_b: { val: ~secret_seed + 2 }
    }
    ;; 外部無法存取 factory.~secret_seed
    ```
### 3.3 跨層級穿透警告 (Shadowing Caution)
雖然子節點可以透過視界提升（`^`）存取祖先的 `~` 欄位，但過深的路徑引用（如 `^^^.~secret`）會導致強耦合。
*   **最佳實踐**：除非該欄位被標記為 `%protected` (研究中語法)，否則引擎應在靜態分析時發出警告，建議優先透過態射參數傳遞而非視界穿透。這確保了子節點在重構或移動時不至於因路徑斷裂而坍縮。

## 4. 動態導航：透鏡 (Lens `[]`)

當路徑名本身是觀測的結果時，使用 `[]` 語法。

### 4.1 運作規則：二階坍縮
1.  **內層坍縮**：先觀測 `[]` 內的表達式，並將其收斂為一個 **CAID 或原子**。
2.  **外層導航**：將坍縮結果作為路徑名，對目標節點進行存取。

### 4.2 代數分配律 (Distributivity)
若透鏡內部的表達式為聯集，導航操作對聯集分支具備分配性：
$A[B \mid C] \equiv A[B] \mid A[C]$

## 5. 模式導航 (Pattern Pathing `@{}`)

這是一種「廣播式」的約束，它不是精確定位，而是對符合幾何特徵的一組節點施加集體觀測。
- **語法**：`Combo.@{ Pattern }`
- **語義**：對於 Combo 中所有滿足 `Pattern`（型別或正則）的欄位，併發執行約束。
