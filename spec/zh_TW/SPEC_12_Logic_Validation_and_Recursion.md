# n/ Language Specification - 遞迴、驗證與歧義 (Logic Validation & Recursion)

本章節定義 `n/` 宇宙如何處理循環定義、遞迴邏輯以及在觀測過程中可能產生的歧義狀態。
在格論模型中，遞迴不是傳統的態射呼叫堆疊，而是**不動點 (Fixed-point)** 的收斂過程。

---

## 1. 循環定義與靜止狀態

當兩個或多個節點相互引用且不涉及任何變換（Morphism）時，稱為**靜止循環**。

### 1.1 靜止循環判定 (Static Cycle Detection)
*   **判定規則**：
    1.  **CAID 一致性**：若當前正在觀測的節點路徑已在當前觀測堆疊中，且輸入的幾何指紋（CAID）完全未變。
    2.  **無變換介入**：在閉環路徑中，不包含任何 `/` 態射的應用或遞迴管道演化。
*   **格論語義**：由於缺乏額外資訊，`a` 與 `b` 無法收斂至任何原子，處於**所有可能值的量子疊加態**。
*   **解析結果**：引擎將其判定為 **`_` (Top)**。這意味著「在當前資訊下，它們可以是任何東西」——如同量子系統在未被觀測前保持全部可能性，因為它沒有提供任何額外的資訊量來縮小集合範圍，故維持最大疊加態。

---

## 2. 不動點收斂 (Fixed-point Convergence)

遞迴態射的執行實質上是在尋找該邏輯的不動點。

### 2.1 遞迴與資訊單調性
每一次遞迴展開都必須符合 Invariant 2 (單調性)：資訊量只能增加（精煉），這對應於量子測量中資訊的不可逆獲取。
*   **收斂**：若遞迴路徑最終坍縮為原子或受限型別，則觀測成功。
*   **發散**：若遞迴導致資訊量無限膨脹（如 `a: a + 1`），如同量子系統陷入無限疊加而無法坍縮，則觸發發散守護機制。
*   **規格義務 (Linguistic Invariant)**：
    - **單調性保全**：任何引擎優化技術**嚴禁**破壞格論的單調精煉性質。
    - **等價性要求**：不同實作對同一發散定義的判定結果必須具備一致的 CAID 指紋（包含因果鏈標籤）。

### 2.2 發散判定 (Divergence Detection)
當循環中包含變換（如 `/f: x -> x + 1`），且該變換導致資訊量不斷增加（格論高度不斷下降）卻永遠無法抵達原子終點時，稱為**發散**。
- **處理**：結果坍縮為 **`_|_` (Bottom)**，標記 `%cause: #divergent`。

---

## 3. 遞迴分類與觀測策略 (Recursion Taxonomy)

為了確保宇宙的可觀測性，`n/` 區分兩類性質截然不同的遞迴：

### 3.1 運算遞迴 (Computational Recursion)
*   **特徵**：涉及顯式的態射變換與積極展開。
*   **規格要求**：引擎必須提供發散保護機制。若觀測過程觸及物理視界邊緣且無法判定收斂，必須按照 `%strategy` 返回穩定結果或掛起態。
*   **終止保證**：鼓勵透過靜態證明（`%termination_proof`）來繞過動態監測。

### 3.2 結構遞迴 (Structural Recursion)
*   **特徵**：定義幾何結構的無窮可能性（如 `@List`）。
*   **觀測策略**：遵循**惰性收斂 (Lazy Convergence)** 原則。結構遞迴在語義上不具備停機問題，因為其本體是靜止的幾何定義。

## 4. 停機判定、發散與計算視界 (Termination & Divergence)

在 `n/` 的語義模型中，必須嚴格區分「邏輯上的發散」與「物理上的中斷」。

### 4.1 發散的邏輯本質 (#divergent 與 #branching)

基於 Lohmiller & Slotine (2024) 的多值作用量理論，我們必須嚴格區分「多值解的分支」與「真正的無界發散」。在量子力學中，分支點 (branch points) 是合法的幾何現象——它們代表系統存在多個古典極值路徑，需要更多約束才能坍縮。

#### 4.1.1 多值分支 (#branching)

**分支 (Branching)** 是當遞迴路徑產生多個可能的收斂結果，且資訊增長有上界，但當前約束不足以選擇單一值時的狀態。

*   **判定標準**：
    1.  資訊量持續增加，但增長率有界（非指數/無限）
    2.  同一運算路徑反覆出現，但每次攜帶的資訊不同（相位累積）
    3.  存在潛在的收斂不動點，但需要更多觀測約束才能確定

*   **因果標記**：`%cause: #branching`
*   **格論值**：維持聯集態 `A | B | C`（多個可能分支）
*   **物理類比**：對應論文中「多值古典作用量」的疊加態 $\psi = \sum_j \sqrt{\rho_j} e^{i\phi_j/\hbar}$，每個分支都是合法的解，等待測量坍縮

*   **典型案例**：雙縫實驗的量子路徑選擇、多重繼承的型別解析、未定義優先順序的運算子組合

#### 4.1.2 無界發散 (#divergent)

**發散 (Divergence)** 是節點的一種本體論屬性。當一個定義在幾何上不存在穩定的不動點，或其資訊量單調增長卻永遠無法坍縮為原子時，該節點在邏輯上等價於 **`_|_` (Bottom)**。

*   **因果標記**：發散產生的衝突必須標記為 `%cause: #divergent`。
*   **典型案例**：`a: a + 1`。由於數值無限增長，不存在任何原子能同時滿足此等式，故其真值為空集合。

#### 4.1.3 分支與發散的區分判據

| 特徵 | #branching | #divergent |
| :--- | :--- | :--- |
| **資訊增長** | 有界（可預測的上限） | 無界（持續無限增長） |
| **不動點** | 存在（等待約束選擇） | 不存在（邏輯衝突） |
| **格論值** | 聯集態 `A \| B` | `_|_` (Bottom) |
| **處理策略** | 維持疊加，等待更多約束 | 立即終止，標記衝突 |
| **物理類比** | 量子疊加（波函數） | 能量發散（奇點） |

### 4.2 觀測的不完全性 (#incomplete)
**不完全 (Incompletion)** 不是一種邏輯狀態，而是一種**觀測掛起 (Suspended Observation)**。它發生在運算尚未判定為收斂或發散，但已觸及計算視界（`%fuel` 或 `%timeout`）之時。
*   **語義隔離**：`#incomplete` 僅代表「觀測者目前的能量不足以看清真理」，不代表該路徑本身存在衝突。
*   **增量義務**：若後續觀測提供了更多燃料，引擎必須能從掛起處繼續精煉。

### 4.3 判定規則與引擎義務
為了確保宇宙的決定論，符合規格的 Ouroboros 引擎必須遵循下列判定優先序：

1.  **優先判定無界發散**：若引擎透過循環偵測或靜態分析判定定義必將無界發散（資訊無限增長），必須立即回傳 `_|_` (%cause: #divergent)。
2.  **識別多值分支**：若引擎偵測到資訊增長有界但存在多個可能收斂路徑，應標記為 `%cause: #branching`，維持聯集態等待進一步約束。
3.  **誠實掛起**：若引擎無法在視界內判定發散或分支，且燃料耗盡，**必須**返回 `#incomplete`。
4.  **嚴禁偽裝**：引擎嚴禁將未完成的遞迴運算結果偽裝成穩定的原子或 Top。
5.  **因果溯源**：當判定為 `#divergent` 或 `#branching` 時，引擎應盡可能在因果鏈中指出導致循環的關鍵路徑。

> **與 Lohmiller & Slotine 理論的對應**：上述優先序反映了論文中「分支點 ≠ 錯誤」的核心洞見。多值分支 (#branching) 對應古典作用量的多值解，是合法的幾何現象；只有無界發散 (#divergent) 才是真正的不動點不存在。

#### 發散、分支、靜止與不完全之判定表 (Semantic vs Physical)

| 狀態 (Status) | 本質維度 | 偵測特徵 | 格論值 | %cause / 說明 |
| :--- | :--- | :--- | :--- | :--- |
| **靜止 (Static)** | 邏輯 | 純路徑環繞（如 `a: b, b: a`），無運算介入。 | `_` (Top) | 資訊不足，維持**疊加態**（開放）。 |
| **分支 (Branching)** | 邏輯 | 多值解存在，資訊增長有界，等待約束選擇。 | `A \| B` (聯集) | `#branching` (多值幾何) |
| **發散 (Divergent)** | 邏輯 | 資訊量持續增長且無界，無原子終點。 | `_\|_` (Bottom) | `#divergent` (邏輯衝突) |
| **衝突 (Conflict)** | 邏輯 | 原子互斥或型別不相容（如 `1 & 2`）。 | `_\|_` (Bottom) | `#conflict` (靜態衝突) |
| **不完全 (Incomplete)** | 物理 | 燃料耗盡時運算仍在進行，尚未判定。 | `#incomplete` | `#fuel_exhausted` (觀測中斷) |
| **結構遞迴** | 幾何 | 符合型別定義的無窮可能性（如 `@List`）。 | `#recursive_lazy` | 惰性展開，不觸發發散。 |


#### 語義定論：分支、發散與衝突

在 `n/` 的理想數學模型中，我們必須區分三種本質不同的狀態：

*   **分支 (#branching)** 是「多值幾何」——如同量子疊加 $\psi = \sum_j \sqrt{\rho_j} e^{i\phi_j/\hbar}$，多個解同時存在且合法，等待觀測約束坍縮。這是 **資訊不足** 的表現，而非錯誤。

*   **發散 (#divergent)** 是「動態衝突」——如同 `a: a + 1` 的無限增長，資訊量單調增長卻永無終點，不存在不動點。這是 **時間演化上的不相容**，最終引向空集合 `_|_`。

*   **衝突 (#conflict)** 是「靜態衝突」——如同 `1 & 2` 的空間互斥，原子在同一座標無法共存。這是 **空間上的不相容**，同樣引向 `_|_`。

## 5. 手動終止證明 (%termination_proof)

當演化邏輯超出了引擎自動判定的視界範圍時，開發者可以提供顯式的終止證明。

### 5.1 階段性實作路徑
1.  **短期 (Phase 2)：信任標記 (Trust Marker)**
    *   使用 `%termination_proof: #safe`。
    *   **語義**：這是一個「信任我 (Trust Me)」標記。引擎將停止保守的發散檢查，改為允許觀測者耗盡所有 `%fuel` 進行深度收斂。開發者需承擔收斂失敗導致的資源損耗風險。
2.  **長期 (Phase 3+)：形式化證明綁定 (Formal Binding)**
    *   使用 `%termination_proof: "hash:lean4:..."`。
    *   **語義**：指向一個包含機器可驗證證明（如 Lean 4 的源碼或證明對象）的 Combo 節點。符合規格的引擎可選地整合證明驗證器，在編譯時自動檢核態射的全態射性 (Totality)。詳細的驗證路線圖請參閱 **[APP_02](./APP_02_Formal_Verification.md)**。

## 6. 歧義管理與強行收斂 (Ambiguity Management)

當邏輯演化產生聯集分支（`|`）且引擎無法自動修剪時，開發者可以採取以下策略：

### 6.1 偵測歧義
利用 `%branches` 元資訊觀測分歧程度。
```nlang
/handle: {
    @{ $ & %branches > 1 }: $ |> /first  ;; 偵測到分歧時強行取第一個
    _: $
}
```

### 6.2 局部放寬物理限制
對於已知的高複雜度運算，可以對邏輯節點疊加元資訊配置：
```nlang
heavy_calc: </very_heavy_logic> & {
    %max_branches: 1000
    %fuel: 1000000
}
```

## 7. 總結：遞迴與歧義判定表

| 情況 | 型別 | 結果 | 備註 |
| :--- | :--- | :--- | :--- |
| `a: b, b: a` | 靜止循環 | `_` (Top) | 資訊不足，不代表錯誤。 |
| `path: left \| right` | 多值分支 | `left \| right` (`#branching`) | 多條極值路徑，等待約束坍縮。 |
| `a: a + 1` | 數值發散 | `_\|_` (`#divergent`) | 邏輯衝突，不存在不動點。 |
| `List: {..., next: List}` | 結構遞迴 | `#recursive_lazy` | 合法定義，按需觀測。 |
| `/f: x -> /f x` | 邏輯發散 | `_\|_` (`#divergent`) | 耗盡燃料後判定為衝突。 |
| `1 \| 2` | 邏輯歧義 | `1 \| 2` | 資訊不足以收斂，維持聯集。 |
| `(1 \| 2) \|> /pick`| 強行收斂 | `1` | 使用內建工具手動降維。 |
| `1 & 2` | 原子衝突 | `_\|_` (`#conflict`) | 靜態邏輯不相容。 |
| `{a: 1} & {{a: 1, b: 2}}` | 封閉性衝突 | `_\|_` (`#missing_key`) | Cocoon 缺少必要欄位。 |
