# 引用鍵 —— 原則已經寫下來了，實作只做了一部分

> 2026-08-19。弧 D 的**前置項**（`address_literal.md` §7.1／§7.3）。
> 起因：用戶記得早期提過「路徑名稱含特殊符號時可用 `""` 包起來」，
> 想確認有沒有列入實作。**答案：有，而且原則是規範性的；缺的是三塊實作與一塊文法。**

---

## 1. 規格已經有的（挖出來的）

| 出處 | 內容 |
| :--- | :--- |
| SYNTAX_03 §1 | `field_key = { anon_set \| path \| named_key \| quoted_key \| tag }`；`quoted_key = @{ "\"" ~ (!"\"" ~ ANY)* ~ "\"" }` |
| SYNTAX_03 §104 #6 | **何時需要引用鍵**：鍵名含空白、**運算子**或以數字起首時**必須**用 `"…"`。純識別碼鍵**不應**多餘加引號 |
| **SYNTAX_03 §106 #8** | **點在鍵名 vs 點在路徑**：`a.b: v` 的 `.` 是路徑分隔；「名字裡真的有點」**必須**用 `"a.b": v`——**前者單一座標、後者巢狀** |
| SYNTAX_01 §82 | 含空格或運算子的鍵**必須**用引用鍵 |
| SYNTAX_02 §106 #11 | `quoted_key` **無跳脫序列** ⟹ 鍵名**無法**含 `"` 字元 |

**§106 #8 就是用戶要的原則，只是講的是 `.`**：

> **引號內的字元屬於名字，不是結構分隔符。**

用戶的 `"~123"`（名字就叫 `~123`）與 `~"123"`（local `~`，名字叫 `123`）之區分，
**是這條原則在前綴 sigil 上的同一句話**。

## 2. 實測：原則被實作了一部分（v0.26.1）

| 寫法 | `refl.keys` | 判定 |
| :--- | :--- | :--- |
| `{ "a.b": 1 }` | `["a.b"]` | ✅ §8 兌現——單一座標 |
| `{ "a+b": 3 }` | `["a+b"]` | ✅ §6 兌現——運算子 |
| `{ "a b": 1 }` | 可定義 | ✅ §6 兌現——空白 |
| **`{ "~abc": 7 }`** | **`[]`** | ❌ **`~` 被當成前綴吃掉**，值落在 local 軸（`x.~abc` 回 `⊥ #private_access_violation`） |

**讀取端不是缺口——我先前判斷錯了。**〔量〕`x["a b"]`、`x["a.b"]` 皆有效；
`x."a b"` 是 parse error，**而那符合規格**：`path` 的 `.` 之後只收 `named_key`，
中括號 `"[" ~ expr ~ "]"` 才是被認可的形式。

---

## 3. 三個缺陷

### 3.1 印出端從不加引號 —— 而 `.` 那一格是**靜默改語義**

〔量〕

| 源碼 | 印出 | 讀回去 |
| :--- | :--- | :--- |
| `{ "a b": 1 }` | `a b: 1` | **parse error**（吵著失敗） |
| `{ "a.b": 1 }` | `a.b: 1` | **`keys` 變成 `["a"]`，`x.a` 是 `{ b: 1 }`** |

**第二列是嚴重的那一列**：一次來回把**一個座標變成兩個**，不報錯，
而 §106 #8 明文說這兩者語義不同。

> **與 Q-033 審計 §5 同族**：那裡量到 `%differential.1/.2/.3`
> （265 個欄名裡不是合法識別字的 3 個）使 `to_nlang()` 無法接回。
> **兩者是同一條規則的兩個病徵**：**輸入端接受、輸出端沒有對應的引法。**
> 修的是類別：**凡是需要引號才寫得出的鍵，印出時必須被引號包回去。**

**這一項直接影響 Q-033 D3**（規範 artifact 的格式）：偵察當時的結論是
「printer 不可 round-trip」，現在知道更糟——**它可以 round-trip 成一個不同的值**。

### 3.2 前綴 sigil 在引號內仍被解讀

〔量〕`"~abc"` ⟹ local `abc`。**與 §106 #8 的原則相矛盾**，且與同一個引擎對
`.` 與 `+` 的處理不一致。

⚠ **這是規格未明文的一格**：`quoted_key` 的文法把內容當不透明
（`(!"\"" ~ ANY)*`），**沒有任何條款說內容要再被掃一次前綴**。
所以引擎的行為不是照規格做，也不是明確違規——**是一個沒有人裁過的空隙**。

### 3.3 `~"123"` 沒有文法

〔讀〕`named_key = @{ (prefix? ~ ident) | numeric_key }`——**前綴只接 `ident`**；
而 `quoted_key` **沒有前綴槽**。⟹ 用戶要的「local 但名字要引用」**寫不出來**。

補法是文法層的一行：`named_key = @{ (prefix? ~ (ident | quoted_key)) | numeric_key }`。
**但這要裁**，因為它讓 `"…"` 出現在兩個位置（獨立鍵／前綴之後）。

---

### 3.4 補量：引號對前綴是**完全的** no-op，對 `.` 是承重的

〔量〕

| | CAID | `=` |
| :--- | :--- | :--- |
| `{ "@t": 1 }` vs `{ @t: 1 }` | **相同**（`28b12fac…`） | `#true` |
| `{ "a.b": 6 }` vs `{ a: { b: 6 } }` | **不同** | `#false` |

且四個前綴**全部**被吃掉並路由到各自的軸：`"@t"`→型別、`"/l"`→邏輯、
`"%m"`→元、`"~h"`→local〔量，`refl.keys` 與整值顯示交叉確認〕。

⟹ **現況是一個乾淨的分裂：引號解決分隔符（`.`、空白、運算子），對前綴無效。**

### 3.5 補量：改動的成本為零

〔量 2026-08-19〕**沒有任何一份 n/ 程式碼寫過帶前綴的引用鍵**：

| 掃描範圍 | 命中 |
| :--- | :--- |
| `conformance/`（286 向量） | **0** |
| `spec/zh_TW/*.md` 全部範例 | **0** |
| 引擎測試 `crates/*/tests/*.rs` | 2 處，但皆為**線上協定的 JSON payload**（`s.write_all(b"{\"%status\"…")`），非 n/ 源碼 |

## 4. 裁定（用戶 2026-08-19）

### 4.1 ✅ Q1 ＝「算」：引號內的字元屬於名字，前綴不例外

**理由（三條，前兩條為量測）**：

1.  **n/ 自己已經在做這件事。** `.` 那一格的引號是承重的（§3.4）。
    **前綴是唯一的例外，不是相反** ⟹ 裁「算」是收掉一個例外，不是引進新規則。
2.  **成本為零**（§3.5）。**這是做此事最便宜的時刻，且只會越來越貴。**
3.  裁「不算」則 SYNTAX_03 §106 #8 必須加一句例外，明說**為何 `.` 算而 `~` 不算**
    ——該句寫不出不像事後辯解的版本。

> **旁證（一般知識，非量測）**：sigil 用在**變數**上很常見（Perl／Ruby／PHP），
> 用在**記錄欄位**上罕見；最接近者為 XPath 的 `@attr`（屬性 vs 元素＝同名兩面向）。
> 而**逃逸的先例存在**：Ruby 的 `:"@foo"` 是一個名字字面上就是 `@foo` 的 symbol，
> 與 ivar `@foo` 不同。反向教訓為 MongoDB 的 `$` 鍵與運算子相撞。
> **設計罕見反而是把逃逸做對的理由**——沒有現成直覺可依賴時，規則不能有例外格。

### 4.2 ✅ Q3 必須與 Q1 同批

**一旦 `"@t"` 與 `@t` 是兩個值，印出端就必須加引號。** 否則 §3.1 那個
**靜默 round-trip** 缺陷會多四個 sigil 的表面積。

**歸屬：規格的鍋。**〔讀〕SYNTAX_03 §104 #6／§106 #8 規定了**輸入端何時必須引用**，
**沒有任何條款規定輸出端何時必須引用** ⟹ 任何符合規格的實作都會撞上，
不是這個引擎的實作缺陷。**先補規格的 MUST，再由引擎兌現。**

**建議的正準形（待寫成條文）**：**非純識別碼即加引號**——單純、可機械檢查、
且與 §104 #6 的輸入端規則互為逆。

### 4.3 ✅ Q2 分開處理

`~"123"`（前綴 ＋ 引用名）是**加一個新形式**，與**修正既有不一致**是兩件事。
文法補丁為 `named_key = @{ (prefix? ~ (ident | quoted_key)) | numeric_key }`，
但它讓 `"…"` 出現在兩個位置，**該獨立裁**。
