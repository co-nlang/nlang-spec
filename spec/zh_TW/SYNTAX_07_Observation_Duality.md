# SYNTAX_07：觀測對偶 (Observation Duality)

> [!NOTE] 定位
> 本章為**語法細則**（規範性，位階在 SPEC 之下；見 **[SYNTAX_00](./SYNTAX_00_Conventions.md)**）。文法上位規範見 **[SPEC_14](./SPEC_14_Formal_Grammar.md) §2.4**；觀測對偶語義以 **[SPEC_04](./SPEC_04_Navigation_and_Duality.md)** 為準；「觀測而非執行」範式見 **[APP_03](./APP_03_Paradigm_Comparison.md)**。本章釘死**坍縮態 `x` 與結構態 `<<x>>` 的寫法與區分**。

---

## 1. 語法 (Syntax)

同一座標依**觀測濾鏡**呈現兩態。結構態用**雙角括號 `<< … >>`**（水晶／稜鏡意象；與 cocoon `{{}}` 同為「雙括號＝特殊視角」慣例），摘自 **SPEC_14 §2.4**：

```ebnf
structural = { "<<" ~ expr ~ ">>" }   ;; 結構態（primary 之一）
```

| 寫法 | 態 | 取得 |
| :--- | :--- | :--- |
| `x` | **坍縮態 (Collapsed)** | 收斂後的原子／資料值（隱藏 `%` 元資訊不顯） |
| `<<x>>` | **結構態 (Structural)** | 該節點的 **Combo 幾何本體**（含 `%id`、`%kind` 等隱藏元資訊） |

---

## 2. 語義 (Semantics)

1. **坍縮態 `x` 是預設。** 直接引用路徑會回傳**收斂後**的原子或資料值——最常用的運算輸入。它丟棄隱藏的 `%` 元資訊。
2. **結構態 `<<x>>` 回傳幾何本體。** 雙角括號要求引擎回傳該節點的完整 Combo（含所有 `%` 元欄位），用於**自省 (self-reflection)**——在程式內部觀察結構，**不**觸發非預期的資料坍縮。
3. **兩態是同一物件的兩個濾鏡。** 不是兩個不同的值，而是同一幾何在「坍縮」與「結構」兩種觀測下的投影；語義以 **SPEC_04** 為準（觀測對偶）。這是 `n/`「觀測而非執行」的語法面（範式見 APP_03）。
4. **路徑運算元的結構態＝符號引用（活引用，非快照）。**（2026-07-07 裁決）當 `<<…>>` 的運算元是**路徑**時，「不坍縮」取字面義：結構態是對該**座標**的符號引用——不在建構時定值，**綁定發生於觀測時**。透過引用觀測，看到的是觀測當下的座標內容（含之後才定義的欄位；自指因此可能成立）。引用的 CAID ＝ 路徑的語法幾何（與 SPEC_07 §4.2 P3 的開放項 CAID 原則一致）。`<<_.>>` ＝ 根宇宙的活引用——正典向量 `v: <<_.>> |> <<_.>>` 由此成立：`v.w.x.a` 路徑導向觀測有限步；`v` 全量觀測自指迴歸、於 `%fuel` 視界誠實截斷（視界是語義截斷，非錯誤）。非路徑運算元（字面量／複合表達式）的結構態維持 §2.2 語義（值的幾何本體）。

---

## 3. 範例 (Examples)

坍縮態 vs 結構態：

```nlang
user: { name: "Alice" }

a1: user          ;; { name: "Alice" }（資料落點）
a2: <<user>>      ;; { name: "Alice", %id: "...", %kind: #data, ... }（幾何本體）
```

自省——不觸發資料坍縮地讀取元資訊：

```nlang
id:   <<user_data>>.%id     ;; 內容雜湊 (CAID)
kind: <<@User>>.%kind       ;; 本體角色 (#type)
len:  <<[1, 2, 3]>>.%len    ;; 容器長度
```

## 4. 邊界情況 (Edge Cases)

> 逐條釘死觀測對偶層的寫法。

1. **`<<x>>` 結構態 vs `<`／`>`／`<=` 比較——以雙括號徹底分離（無歧義）。** 結構態用**雙角括號** `<<` … `>>`；比較運算子是單角 `<`／`>`／`<=`／`>=`（SYNTAX_06）。詞法以最長匹配區分：`<<` → 結構態開、`>>` → 結構態閉、`<=`／`>=` → 比較、單 `<`／`>` → 比較。故 `a < b` 是比較、`<<a>>` 是結構態，**不共用符號、無 `a<b>c` 之類歧義**。（早期單角 `<x>` 與 `<`／`>` 衝突——`a < b > c` 會被誤解為態射應用——此問題已由改用雙角括號解決，2026-06 修訂 SPEC_14 §2.4。）
2. **結構態是坍縮態的子型別。** 結構態資訊更多（帶 `%` 元資訊），故更受約束、子集更小：
   ```nlang
   _: <<user_data>> <= user_data    ;; #true（本體含其坍縮值）
   _: user_data <= <<user_data>>    ;; #false（坍縮值丟失了 %id 等元資訊）
   ```
   呼應 SYNTAX_06「資訊愈多 ＝ 子型別」。
3. **以結構態讀 `%` 元資訊。** 自省 `%id`／`%kind`／`%len` 等的標準寫法是 `<<x>>.%field`（先取本體再取元欄位）；`%` 欄位的可寫性與一致性細則見 **SYNTAX_08**。
4. **結構態內是完整 expr。** `<<expr>>` 內可放任意表達式（不限單一路徑），如 `<<a & b>>`；其後可接 postfix 導航（`<<x>>.foo`、`<<x>>[i]`）。
5. **與合併的互動（進階）。** 把結構態當合併運算元會**注入身分／結構**：如 `user_data & <<User>>` 會把 `User` 的本體特徵（`%id`、`%kind`）注入資料。完整合併語義見 SYNTAX_06 與 SPEC_04／SPEC_06，本章不展開。
6. **`<<>>` 只約束它直接包住的表達式；`>>` 之後的 `.field` 一律坍縮（常見陷阱）。** `<<expr>>` 求的是 `expr` 這個**最終節點**的結構本體；一旦跨出 `>>`，後續的 `.field` 是普通 postfix 導航（#4），與坍縮態的規則相同——**一律坍縮**，不因左側曾經結構化而改變。故 `<<x>>.field` 與 `x.field` 等價（皆坍縮讀取 `field`），**不是**「取 `field` 的結構態」。若某欄位本身也具備對偶性（如 `%cause`，見 **SYNTAX_08** 邊界 #3），要拿到它自己的結構本體，必須把**整條路徑**一併納入 `<<...>>`（如 `<<x.field>>`），而非在外層包一次 `<<x>>` 就了事。（現行文法沒有「`.` 後接 `<<field>>`」的中綴結構化步驟；若要支援，需擴充 SPEC_14 postfix_op，屬未決設計，暫不採用。）
