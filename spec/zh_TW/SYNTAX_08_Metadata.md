# SYNTAX_08：元數據 (Metadata)

> [!NOTE] 定位
> 本章為**語法細則**（規範性，位階在 SPEC 之下；見 **[SYNTAX_00](./SYNTAX_00_Conventions.md)**）。`%` 前綴文法見 **[SPEC_14](./SPEC_14_Formal_Grammar.md) §2.2**；虛擬欄位機制語義以 **[SPEC_08](./SPEC_08_Meta_and_Runtime.md) §1**、字典與創世預設值以 **[SPEC_09](./SPEC_09_Standard_Library.md) §6** 為準。本章釘死**`%` 欄位的宣告／讀取寫法，以及寫入的一致性邊界**。

---

## 1. 語法 (Syntax)

`%` 欄位沒有獨立文法——它複用一般欄位／postfix 導航規則，`%` 只是 `named_key` 的合法前綴之一（**SPEC_14 §2.2**）：

```ebnf
named_key = @{ (prefix? ~ ident) | numeric_key }   ;; prefix 含 "%"
field     = { (field_key ~ ":" ~ expr) | spread_expr }  ;; 宣告：field_key = %ident（spread 分支見 SYNTAX_04 §4.8）
postfix_op = { ("." ~ named_key) | ("[" ~ expr ~ "]") }  ;; 讀取：x.%ident
```

| 寫法 | 動作 |
| :--- | :--- |
| `%kind: #data`（Combo 欄位） | **宣告**——與其他欄位語法相同，無特殊符號。 |
| `x.%kind` | **坍縮態讀取**——回傳該元欄位的（坍縮）值。 |
| `<<x>>.%kind` | **結構態讀取**——先取完整 Combo 本體再取元欄位（**SYNTAX_07** 慣用寫法，避免非預期坍縮）。 |

---

## 2. 語義 (Semantics)

1. **兩類欄位（依寫入一致性保證分類，SPEC_08 §1.1/1.2）：**

   | 類別 | 範例 | 使用者可宣告？ | 引擎角色 |
   | :--- | :--- | :--- | :--- |
   | **自省屬性 (Reflection)** | `%id`、`%len`、`%cause` | 語法上不禁止書寫，但**嚴禁**依賴其被採納 | 觀測時即時計算，反映物理／邏輯狀態 |
   | **特徵屬性 (Trait)** | `%kind`、`%fmap`、`%bind`、`%strategy`、`%fuel` | **可以**，且會覆蓋引擎預設推斷 | 態射應用／管道演化時優先查詢 |

2. **寫入是「協商」，不是「賦值」。** 所有 `%` 欄位語法上皆可寫，但保證等級不同：
   - **自省屬性**：保證**讀取一致性**（觀測必回傳實相）；**不**保證**寫入一致性**（引擎可自由決定如何處理使用者寫入值，見 §4 #1）。
   - **特徵屬性**：保證**寫入一致性**（引擎必須尊重宣告，作為計算依據）。

3. **完整字典見 SPEC_09 §6。** 本章不重複列出欄位清單與創世預設值；只釘寫法與一致性邊界。

4. **SPEC_08 的二分類與 SPEC_09 §6.1 的五分類是兩條正交的切法，不衝突。** SPEC_08 §1 按「寫入一致性保證」二分（自省 vs 特徵）；SPEC_09 §6.1 按「主題」五分（自省屬性／特徵屬性／視界參數／相容與遷移／證明與安全）。例如 `%fuel` 在 SPEC_08 屬「特徵屬性」大類（可宣告、寫入一致），在 SPEC_09 §6.1 因主題另分入「視界參數」小類——兩者描述同一欄位的不同切面，非牴觸。

## 3. 範例 (Examples)

宣告特徵屬性（覆蓋引擎推斷）：

```nlang
node: {
    %kind: #data          ;; 強制視角角色
    %fuel: 5000            ;; 覆蓋創世預設 10000
    val: 42
}
```

結構態讀取自省屬性（自省，見 SYNTAX_07）：

```nlang
id:  <<node>>.%id     ;; CAID（內容雜湊）
len: <<[1, 2, 3]>>.%len   ;; 3
```

寫入協商——對自省屬性賦值不保證被採納：

```nlang
x: { %id: "fake_hash", val: 1 }
;; 引擎可能：
;;   (a) 斷言：驗證 "fake_hash" 是否與計算值相符，不符則 _|_
;;   (b) 忽略：靜默接受寫入，但 <<x>>.%id 仍回傳計算值
;;   (c) 禁止：直接坍縮為 _|_，%cause: #privileged_required
;; 三者皆合法引擎行為（見 §4 #1）；使用者程式碼不應依賴特定選擇。
```

---

## 4. 邊界情況 (Edge Cases)

> 逐條釘死元數據層的寫法。

1. **自省屬性寫入的三種合法引擎行為：斷言 / 忽略 / 禁止。** 對 `%id`、`%len` 等自省屬性賦值時，引擎**可以**：(a) **斷言 (Assertion)**——驗證值是否相符，不符則坍縮為 `_|_`；(b) **忽略 (Ignore)**——靜默接受寫入，但觀測時仍回傳計算值；(c) **禁止 (Forbidden)**——直接坍縮為 `_|_`，`%cause: #privileged_required`。三者皆合法，規格層**不**統一。使用者程式碼**嚴禁**假設任何一種特定行為；若需確認，應查詢引擎文件或 `~%Engine./profile`（見 SPEC_08 §3.1.1）。
2. **`%cause` 只在 `%val` 坍縮為 `_|_` 時才由引擎產生；否則讀取為 `_`。** 未衝突的節點沒有「原因」可報——`_` 表達的是「無事實可回報的預設疊加態」，**不是**查詢本身又製造了一個新衝突（見 SPEC_08 §2.2）。
   ```nlang
   a: 123
   a: 456        ;; 二次賦值衝突（123 & 456 = _|_）
   b: 123
   b: { c: 456 } ;; 原子 & Combo → 混血節點（SYNTAX_06 邊界 #6），非衝突

   a          ;; _|_
   a.%cause   ;; #conflict
   b          ;; 123
   b.%cause   ;; _   （b 從未坍縮為 _|_，無因可溯）
   ```
3. **`%cause` 自身也是對偶的——但 `<<>>` 必須包住整條路徑，包住前面的節點沒有用。** `%cause` 的坍縮值是標籤（如 `#conflict`）；其結構態才是詳細因果鏈。取得後者的**唯一（現行文法下）寫法**是把整條路徑一起包進 `<<...>>`：
   ```nlang
   a.%cause      ;; #conflict            （坍縮：標籤）
   <<a>>.%cause  ;; #conflict            （與上式等價！陷阱：見下）
   <<a.%cause>>  ;; { %val: #conflict, ... }   （結構：因果鏈細節，REAL_04）
   ```
   **陷阱**：`<<a>>.%cause` 看起來像「結構態讀取」，實際上與 `a.%cause` 完全等價——因為 `<<a>>` 只結構化了 `a` 這一步，其後的 `.%cause` 是**未加 `<<>>` 的一般 postfix 導航，一律坍縮**，與其左側是否已結構化無關（`.` 導航本身不繼承、也不查詢左側的觀測濾鏡）。`<<>>` 只對它**直接包住的整個表達式**的**最終節點**生效；要結構化路徑中段或末端的某一步，必須把該步驟一併納入 `<<...>>` 內，**不能**事後用 `.field` 追加。

4. **特權模式可繞過協商。** `#pin` 模式下，特權觀測者**可以**強制覆蓋自省屬性，跳過上述三選一協商（見 **SPEC_08 §6**）。一般使用者路徑（無 `%privilege_token`）不可及此行為；勿與 §4 #1 的一般協商混淆。
5. **`%` 只有 Data／Combo 面向。** 沒有 `%@a`／`%/a`——`%` 本身是獨立的 Combo 面向，不與三位一體 `{Data, @, /}` 組合（自 **SYNTAX_05** 遞延，該章已釘死前綴合法組合，本章不重述）。
6. **未知／自訂 `%` 欄位視為一般特徵屬性資料。** SPEC_08 §1.3 允許引擎自訂 `%` 欄位（規格保留給實作的彈性）。使用者宣告規格未定義的 `%foo` 欄位時，除非目標引擎剛好識別該名稱，否則它只是一個普通可讀寫欄位，不觸發任何特殊語義；創世預設值（SPEC_09 §6 表）僅保證核心視界／自省參數的跨引擎一致性，**不**延伸至自訂欄位。
