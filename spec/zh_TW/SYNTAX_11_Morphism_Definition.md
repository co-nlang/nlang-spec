# SYNTAX_11：態射定義 (Morphism Definition)

> [!NOTE] 定位
> 本章為**語法細則**（規範性，位階在 SPEC 之下；見 **[SYNTAX_00](./SYNTAX_00_Conventions.md)**）。文法上位規範見 **[SPEC_14](./SPEC_14_Formal_Grammar.md) §2.3**（`morphism_expr`，L15）；定義／分派／匿名態射語義以 **[SPEC_07](./SPEC_07_Logic_and_Pipe.md) §1、§5** 為準。本章釘死**態射如何被定義**——`->`、分派表、匿名態射、柯里化參數。**應用**見 SYNTAX_09。（2026-07-05 新寫，補齊 09 文末預告的缺章。）

---

## 1. 語法 (Syntax)

```ebnf
morphism_expr = { ternary_expr ~ (!field_start ~ "->" ~ ternary_expr)* } ;; Level 15
;; 註：AST Builder 必須將 `->` 鏈手動摺疊為右結合樹（SPEC_14 §2.3）
```

| 寫法 | 形式 |
| :--- | :--- |
| `/name: input -> output` | 具名態射定義 |
| `/name: { @{ pat₁ }: out₁, pat₂: out₂ }` | **分派表**（有模式鍵 `@{ … }:` 的 Combo；鍵＝輸入約束、值＝輸出；SPEC_07 §1、§1.1.2）。舊名「Combo-as-Union」於 2026-10-11 撤下：表不是它各分支箭頭的 `|`（§2 #6，D104） |
| `(x -> body)` | 匿名態射（未綁定路徑的 Logic Combo） |
| `(x y -> body)` | 柯里化多參數（空白分隔，自動柯里化） |
| `x @int -> body` | 參數帶型別註記（`@` 為 L3 型別註解）：`@int` 是該分支的模式，`x` 綁定輸入 |

---

## 2. 語義 (Semantics)

1. **`->` 是 L15、右結合。** `a -> b -> c` ≡ `a -> (b -> c)`（柯里化鏈）；文法迭代層由 AST Builder 摺疊為右結合（SPEC_14 §2.3 註）。
2. **有模式鍵的 Combo＝分派定義**（不必賦給 `/` 欄位；2026-10-09，D97）。表內其餘非 meta 鍵也是約束（數字／標籤／字串，`_:` 為預設分支）；**裸 `@T:` 鍵是型別面向，不是約束**，約束寫 `@{ @T }:`（D96）。一張表是**一個**態射：施用時各分支在表內互比特定性（極小元素規則，SPEC_07 §1.1／SPEC_06 §1.5）。**表不是它各分支箭頭的 `|`**（§2 #6）；原文「引擎將該 Combo 同構展開為態射聯集」與 D104 相反，2026-10-11 改寫。分支值中的 `$` 指向**被匹配的輸入**（如 `/fib` 的 `@{ @int }: (/fib ($ - 1)) + (/fib ($ - 2))`；`$` 細則見 **SYNTAX_12**）。
3. **匿名態射＝未綁路徑的 Logic Combo**（SPEC_07 §5.2 定義 1）：`(x -> x + 1)` ≡ `{ %kind: #logic, %morphism: #true, %rules: { x: x + 1 } }`。可直接應用、可賦值（`f: (x -> x + 1)` 後 `f 5` → 6）。
4. **匿名態射的限制**（SPEC_07 §5.2）：無路徑名稱（**遞迴必須用具名態射**）、無 `%compat`、無 `%migration`。簡單變換用匿名、複雜／遞迴用具名（SHOULD）。
5. **未註記參數＝動態推導。** `x -> x + 1` 的輸入型別由呼叫端決定（多型別呼叫時等價於聯集型別態射，SPEC_07 §5.2 定義 6）。
6. **箭頭的 Combo 形；態射的 `|` 就是 Combo 的 `|`（2026-10-11，D104）。** 一支箭頭 `p -> body` 是**一個** Logic Combo，恰有一條規則（SPEC_07 §5.2 定義 1）：`p` 是這條規則的輸入約束，`p` 裡的綁定名在 `body` 中指向被匹配的輸入。它與分派表的一列對應如下〔量，Q-080 交付：每對施用於相符與不相符的輸入，答案逐格相同〕：

    | 箭頭 | 表的一列 |
    | :--- | :--- |
    | `x @int -> x + 1`（帶模式） | `@{ @int }: $ + 1` |
    | `5 -> "five"`、`#a -> 1`（字面模式） | `5: "five"`、`#a: 1` |
    | `x -> x * 2`（只有綁定名：沒有模式，約束是 Top） | `@{ _ }: $ * 2`；在已有模式鍵的表裡也可寫 `_:` 預設分支 |
    | `_ -> 1` | `@{ _ }: 1` |

    綁定名換成 `$`（SYNTAX_12 §4 #5）。只有 `_:` 的 Combo **不是**表（沒有模式鍵，#2）：`{ _: $ * 2 }` 是帶預設鍵的記錄，其中的 `$` 是自由的（`{ _: $ * 2 } 5` ⟹ `#no_context`）。
    **柯里化** `x -> y -> body` 是一條規則，輸出是另一支箭頭（#1 右結合）；施用一次得到那支箭頭，`x` 留在它的閉包裡。**今天沒有對應的表寫法**〔量，v0.81.0 與 Q-080 交付相同〕：模式鍵那一列的值若是態射，表被施用時拿同一個輸入再施用它（`{ @{ @int }: (y -> y * 100) } 3` ⟹ `300`），字面鍵那一列則回傳態射本身（`{ 3: (y -> y * 100) } 3` ⟹ 該態射）——已列佇列待裁。定義 1 寫出來的那個字面（`{ %kind: #logic, … }`）今天施用得 `#no_matching_branch`，亦在佇列；本款說的 Combo 形是箭頭求值得到的值，不是那個字面。
    兩支箭頭的 `|` 是兩個這樣的 Combo 的 `|`：被施用時逐支分配，各成員以自己被施用，**成員之間不比特定性**（SPEC_07 §5.2 定義 4）。所以表不是它各分支的 `|`：`{ @{ @int }: "int", 5: "five" } 5` ⟹ `"five"`，`((x @int -> "int") | (5 -> "five")) 5` ⟹ `"int" | "five"`。要跨分支比特定性，寫成一張表。

## 3. 範例 (Examples)

```nlang
;; 具名 + 分派定義（SPEC_07 §1）
/fib: {
    0: 0
    1: 1
    @{ @int }: (/fib ($ - 1)) + (/fib ($ - 2))
}

;; 匿名 + 柯里化
inc:  (x -> x + 1)
add2: (x y -> x + y)
_: add2 2 3            ;; 5

;; 分支聯集（各分支必須括號，見 §4 #1）
/fmt: (x @int -> x + 1) | (x @str -> x + "!")   ;; /fmt 5 ⟹ 6；/fmt "a" ⟹ "a!"（逐支施用，不中的支剪掉）
```

## 4. 邊界情況 (Edge Cases)

1. **分支聯集必須各自括號（重要）。** `->`（L15）比 `|`（L12）**鬆**，裸寫 `A -> B | C -> D` 解析為 `A -> ((B | C) -> D)`——**不是**兩個分支！態射聯集的正典寫法是括號各分支：`(A -> B) | (C -> D)`。（SPEC_07 §5.2 定義 4 的裸寫範例應照此讀；語義「態射聯集」不變，僅寫法釘死。）
2. **`|>` 比 `->` 緊（刻意設計，SPEC_07 §4.5）。** `/f: x -> x |> /g` ≡ `x -> (x |> /g)`（態射體自然含演化鏈，無需括號）；反向——把演化對象接進匿名態射——**必須**括號：`data |> (x -> x + 1)`。
3. **參數型別註記建議帶空白：`x @int ->`。** `x@int` 與 `x @int` 解析相同（`@` 是 L3 中綴），規範**建議**（SHOULD）空白形式，與 `123 @int |> /process`（SPEC_14 §4 範例 B）風格一致。
4. **柯里化參數是 juxtaposition，不是 tuple。** `(x y -> …)` 是兩個柯里化參數；`((x, y) -> …)` 是**一個** tuple 參數（位置解構）。與 [SYNTAX_09](./SYNTAX_09_Morphism_Application.md) **§4 #2** 的應用側區分嚴格對偶——定義側選了哪種，應用側就得用哪種。〔更正 2026-08-26〕原文誤記為「§4.2」，而該章 §4 是無編號子項的條列，指的是其中第 2 條；此誤記曾使人讀成「應用側從未寫下」。**本款是 SYNTAX_09 §2 #1「態射必須宣告它綁定哪些鍵」的推論，不是獨立規則**：`(x y -> …)` 宣告的是逐次單引數，`((x, y) -> …)` 宣告的是鍵 `0`、`1` 的單一 Combo。
5. **`->` 的左手邊是模式，不是表達式求值。** `input` 位置的內容（識別碼、型別約束、原子）是**輸入約束**，以值保存於該分支（SPEC_07 §1.1.2；只有綁定名的左手邊沒有模式）；在分派定義中鍵位同理（SYNTAX_03 的鍵規則適用；`@{ … }` 鍵可寫複合約束，SPEC_07 §1.1 情境 C）。
6. **態射也服從合併。** `/h: /f & /g` 是輸出側雙重約束（`(f & g)(x) ≡ f(x) & g(x)`，SPEC_07 §5.3）；衝突在**應用時**坍縮，定義時不檢查。
7. **`->` 鏈跨行。** 右結合鏈的換行慣例：在 `->` **之後**換行縮排（讓每行以模式開頭）；`!field_start` 護欄照常終止欄位（單行鍵限制見 SYNTAX_03 §4.9）。
8. **遞迴不要寫成箭頭的 `|`（2026-10-11，D104）。** `|` 的成員不互比特定性，每支都會走：`g: (0 -> 0) | (n -> g (n - 1))` 的 `g 3` ⟹ `0 | #blur { %cause: #max_depth_exceeded, … }`——遞迴那支在 `0` 也照走。基底要壓過遞迴，寫成一張表：`f: { 0: 0, @{ @int }: f ($ - 1) }` 的 `f 3` ⟹ `0`。
