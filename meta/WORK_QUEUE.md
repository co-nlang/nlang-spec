## 2. 流程規則

### 2.1 狀態只有五種

| 狀態 | 意義 |
| :--- | :--- |
| **Active** | 已開工；全專案同時最多一弧 |
| **Ready** | 已有射程、依賴與驗收形狀，可以開單 |
| **Blocked** | 真問題，但等裁定、量測或前置弧 |
| **Inbox** | 新發現或舊帳候選；尚未取得排序權 |
| **Closed** | 已切版或明文撤回；只留短索引，詳情在 `ENGINE_SYNC` |

### 2.2 新發現不得自動插隊

一弧途中撞見新問題時，依下列順序判定：

1. **不修就不能證明本弧的主張**：留在原工單的 repair round；不是新弧。
2. **可造成資料損壞／遺失、可由輸入觸發宿主 abort、偽造安全裁決，或使同一 CHS
   得不同身分**：進 Inbox，標 `interrupt-candidate`；須明文比較目前 Active 後才可
   搶占，不因「剛發現」自動升首位。
3. **其餘**：進 Inbox，記來源、證據、影響與下一個判別實驗；不給施工序號。
4. **只在舊紀錄看見**：先對現版重現。未重現前不得從 `ENGINE_SYNC` 直接抄入 Ready。

只有 `interrupt-candidate` 能中斷 Active；中斷時必須在本檔記下「為何原弧可以停、
恢復條件是什麼」。一般 P1/P2 不以嚴重度名稱互相競價，靠依賴與可開工性排序。

### 2.3 每張佇列卡最少六欄

`ID／狀態／一句主張／證據或來源／依賴／完成條件`。若缺「完成條件」，它是討論題，
只能待在 Inbox 或 `STATUS` 的 O 帳。

### 2.4 第三個入口：規格寫了 MUST 而引擎未兌現（2026-08-13 補）

本檔建檔時的原料是 `STATUS`（設計帳）與 `ENGINE_SYNC`（交付史）。但有一整類帳
**兩處都不住**：它們產生於**規格收尾**，落在 `CHANGELOG` 與規格條文裡——

> 驗收量到某實作做錯了某件事 ⟹ 該弧射程不含它 ⟹ 於是寫成一條 MUST／MUST NOT，
> 期待「以後」有人來兌現。而那個「以後」沒有佇列位置。

**這是最危險的一類**：符合性宣稱會因此變成假的，而且它不會在任何一弧的偵察裡自己
跳出來。〔量 2026-08-13〕首次清掃即找到三筆（見 §6），全部不在本檔任何一節。

⟹ **規則**：規格收尾若新增一條 MUST／MUST NOT 而參考引擎當下未兌現，**必須同時
在本檔 Inbox 開一列**，`下一個判別` 一律寫「對現版重現」。收弧協議 §8 已加入此步。

⟹ **另一個同族漏洞**：工單裡新開的 O 編號若未回寫 `STATUS`，就只活在
`nlang-tools/docs/*_handover.md` 裡。O43–O47 即為此例（2026-08-13 已回寫）。

### 2.5 第四個入口：引擎兌現了規格沒寫的性質，而且已有人依賴它（2026-08-21 補）

§2.4 治的是「規格寫了 MUST 而引擎未兌現」。**它的鏡像同樣要有位置**——

> 引擎做出了一個**對的**行為，規格從未描述它，conformance 從未釘它，
> 而樹上已經有東西靠著它綠著。

兩者的失敗形不同：§2.4 使**符合性宣稱變成假的**；本類使**符合性宣稱變成空的**
——第二個實作做出相反的選擇，仍然通得過全部向量。

⟹ **規則**：凡在偵察或裁定過程中發現「引擎的答案是對的，但規格沒說、向量沒釘」，
**必須在 Inbox 開一列**，並記下**是誰在依賴它**（測試、其他條文、或某個待裁的設計題）。
**判別法**：去 conformance `grep` 那個現象；零命中即為本類。


三條互不阻塞，但**線內有嚴格順序**，而且**前兩條有一個交點**（§9.0）。

### 9.0 標準根線與 `%effect` 線的交點：身分只該搬一次

〔量 2026-08-16〕**`%effect` 今天沒有守任何門。** `oo run` 不帶任何 `--grant`
即可 `~%Io./write_file` 並真的寫出檔案、`~%Env./get` 讀出環境變數；
`--grant effect_override` 管的是**覆寫已宣告的效果**，不是**准許做 IO**。

⟹ `%effect` 目前是**一句宣告的誠實性**，`#effect_violation` 是**測謊器不是閘**。
**§9.2 三扇門因此都不是活的漏洞**——它們是「這個機制沒做到它名字說的事」，
而之所以不咬人，正是因為 `%effect` 還沒接到任何東西上。

**但這使順序變重要，理由不是嚴重度而是身分：**

*   **洞 A** 要修 ⟹ `%effect` 進耐久形 ⟹ 標準根 digest 移動 ⟹
    **每一個根的位址移動**（標準根是 ⊕ 進根之身分的，見 O58）。
*   **O58 拆開** ⟹ 標準根不再 ⊕ 進根 ⟹ **每一個根的位址移動**。

**兩者移動的是同一個東西。分開做付兩次。** 而「移動所有既有根的身分」的機會不多——
v0.23.0 的多重具備就是為了讓它付得起。

⟹ **這則裁定已做：O61（2026-08-16）＝「進值裡」。**

〔量〕`%effect` 有**兩個家**——`ComboVal.meta`（**寫下來的**，進雜湊）與 `ComboVal.effect`
（**引擎傳染上來的**，不進）。SPEC_08 §4.1 的 MUST 指的是後者也算，理由有二：
**該條款 2026-04-01 寫成，而讓「只指 meta entry」說得出口的儲存詞彙是 2026-08-13/14 才到的**
（時代錯置）；且依 **disc 023 §3**，效果標籤是**這個值對「我的 CAID 夠不夠決定我」所作的陳述**，
故「只指寫下來的」會讓有截面與無截面的兩個值取得同一個位址。

⟹ **O58 的射程要含它，一次搬完。** 詳見 `meta/oo/STATUS.md` O61。

**射程比原估窄**：不是「把效果加進雜湊」，是**把傳染值從錯的家搬到對的家**——meta 軸本來
就進雜湊，不必新增機制。**循環不成立**：§4.2.4／§4.3 已分開「原始定義」與「觀測結果」，
落的是定義側。
