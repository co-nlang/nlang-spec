# n/ Language Specification - 運行時與計算視界 (Runtime & Computational Horizon)

本章節定義 Ouroboros 引擎的核心行為：虛擬欄位機制、錯誤處理，以及由 **Kochen-Specker 定理** 所定義的**計算視界 (Computational Horizon)** 的物理收斂策略。

---

## 1. 虛擬欄位機制 (Virtual Fields %)

使用 `%` 前綴的欄位代表節點的 **元幾何特徵 (Meta Geometry)**。為了確保實作一致性，規格將其分為兩類：

### 1.1 自省屬性 (Reflection - 唯讀)
這些欄位由 Ouroboros 引擎在觀測時即時計算，反映節點的物理與邏輯狀態。使用者**嚴禁**對其進行賦值。
- **範例**：`%id` (CAID / 譜幾何指紋), `%len` (容器長度), `%cause` (正交衝突歸因)。
- **行為**：任何試圖對其賦值的行為，在收斂時會被引擎忽略或判定為 `#privileged_required`。
- **對偶性觀測**：`%cause` 自身具備對偶特質——`node.%cause` 坍縮為衝突標籤（如 `#type_mismatch`）；`<<node.%cause>>`（結構態觀測**整條路徑**，非僅 `node`）則可獲取詳細的衝突上下文（詳見 **[REAL_04：因果結構](./REAL_04_Causal_Chain_Protocol.md)**）。`<<node>>.%cause`（先結構化 `node` 再坍縮讀取）與 `node.%cause` 等價——皆回傳標籤，因為未加 `<<>>` 的 `.` 導航一律坍縮，無論其左側是否已結構化。
- **生成條件**：`%cause` 僅在 `%val` 坍縮為 `_|_` 時由引擎產生；否則讀取為 `_`（未受約束的預設疊加態，語義是「無事實可回報」，**非**新的衝突）。
- **溯源能力**：在複雜的合併中，`%cause` 應指向第一個導致空集合的原子操作，以協助開發者定位邏輯斷裂點。
- **實作建議**：為了節省儲存成本，引擎可將 `%cause` 實作為**惰性（Lazy）**的。僅當觀測者顯式查詢該元欄位時，才回溯計算完整的因果鏈；同時，實作可選擇性地限制因果鏈的深度。

### 1.2 特徵屬性 (Trait - 可宣告)
這些欄位定義了節點的代數行為與本體論角色。使用者**可以**顯式宣告這些欄位，以覆蓋引擎的預設推斷。
- **範例**：`%kind` (強制視角角色), `%fmap` (定義算子行為), `%bind` (定義單子行為), `%termination_proof` (手動終止證明), `%fuel` (觀測能量配額)。
- **行為**：引擎在執行態射應用或管道演化時，會優先查詢這些 Trait 欄位。

### 1.3 字典與授權
元資訊的完整字典與創世預設值請見 **[SPEC_09](./SPEC_09_Standard_Library.md)**。
*   **意象**：`%` 象徵 Ouroboros 纏繞在權杖上，代表系統的自省與自省後的自我轉化。
*   **特權介入**：在 `#pin` 模式下，特權觀測者可強制修改特定的自省屬性（詳見 §6）。

## 2. 錯誤處理：正交衝突與邏輯防火牆 (Orthogonal Conflict)

`n/` 採用非嚴格（Non-strict）的錯誤處理模型。當觀測導致子空間坍縮至零維（Bottom）時，發生衝突。

### 2.1 可觀測與可恢復的衝突 (Catchable Conflicts)
觀測者可以使用子型別判定 `x <= _|_` 或三元運算 `? :` 在邏輯層建立防火牆。

**可恢復範圍**：
- **`#conflict`**：因合併不同原子或不相交型別產生的邏輯衝突（正交子空間交集為零）。
- **`#missing_key`**：存取封閉結構（Cocoon）中不存在的欄位。
- **`#caid_mismatch`**：發現過程中的內容驗證失敗。
- **`#blocking`**：違反系統級合規性或安全性限制（見 **[REAL_05](./REAL_05_Compliance_and_MVP.md)**）。
- **`#type_mismatch`**：輸入值不符合態射或型別約束。

**不可恢復範圍 (Unrecoverable Physical Limits)**：
- **`#divergent`**：因偵測到發散遞迴而觸發的保護。
- **`#fuel_exhausted`**：因觸及計算視界燃料限制而導致的觀測中斷。
- **`#timeout`**：因觸及物理時間限制而導致的觀測中斷。
- **`#max_lifting_exceeded`**：超過最大態射升寫深度。
- **`#cocoon_isolation_violation`**：試圖穿透 Cocoon 邊界進行自動升寫。

**判定理由**：實體物理限制（燃料、時間）與發散屬於「宇宙觀測能力」的缺失，無法透過內部的幾何邏輯進行自我補償。

```nlang
;; 合法：攔截型別衝突
safe_val: (input & @int <= _|_ ) ? 0 : input
```

*註：`? :` 為模式匹配的語法縮寫，詳見 **[SPEC_07](./SPEC_07_Logic_and_Pipe.md) §1.2 條件收斂語法糖**。*

### 2.2 崩潰診斷與溯源 (`%cause`)

當一個節點收斂為 `_|_` 時，Ouroboros 引擎會保留導致衝突的**因果鏈 (Causal Chain)**，並透過 `%cause` 元欄位提供給觀測者。

*   **對偶性觀測**：`%cause` 自身具備對偶特質——`node.%cause` 坍縮為衝突標籤（如 `#type_mismatch`）；`<<node.%cause>>`（結構態觀測**整條路徑**，非僅 `node`）則可獲取詳細的衝突上下文（詳見 **[REAL_04：因果結構](./REAL_04_Causal_Chain_Protocol.md)**）。`<<node>>.%cause`（先結構化 `node` 再坍縮讀取）與 `node.%cause` 等價——皆回傳標籤，因為未加 `<<>>` 的 `.` 導航一律坍縮，無論其左側是否已結構化。
*   **生成條件**：`%cause` 僅在 `%val` 坍縮為 `_|_` 時由引擎產生；否則讀取為 `_`（未受約束的預設疊加態，語義是「無事實可回報」，**非**新的衝突）。
*   **溯源能力**：在複雜的合併中，`%cause` 應指向第一個導致空集合的原子操作，以協助開發者定位邏輯斷裂點。
*   **實作建議**：為了節省儲存成本，引擎可將 `%cause` 實作為**惰性（Lazy）**的。僅當觀測者顯式查詢該元欄位時，才回溯計算完整的因果鏈；同時，實作可選擇性地限制因果鏈的深度。

## 3. Ouroboros 引擎行為：計算視界與 KS 定理

收斂受限於觀測者的物理能量。這一限制的底層法理由 **Kochen-Specker (KS) 定理** 提供：

*   **非全域性公設**：KS 定理證明了在維度 $\ge 3$ 的 Hilbert 空間中，不存在一個全域截面（Global Section）能同時賦予所有非交換觀測量確定的真值。這意味著「上帝視角」在數學上是不存在的（詳見 **[APP_04](./APP_04_Mathematical_Foundations.md)**）。
*   **局部性必然性**：由於全域真值的不存在，觀測行為必然是**上下文相關（Contextual）**的。這為 `n/` 的 **Bohrification**（將量子本體投影至交換視角）提供了數學必然性。
*   **視界作為對價**：計算視界（`%fuel`）並非單純的工程限制，而是觀測者在特定視角下，為了將「潛在可能性」坍縮為「局部真實」所必須支付的**幾何代價**。當燃料耗盡，觀測者觸及的是該視角下的物理邊界（KS 定理所定義的觀測極限），而非技術瓶頸。
*   **視界的拓撲深度（Papers IV, XX–XXII）**：視界不只是 KS（$H^2$，全域截面不存在）的對價，它還有一個**確切的拓撲深度**。對稱／Pauli（雙線性）資料的互文性障礙*截斷於* $H^3$（Paper XXII arity-resonance ceiling），所以視界的幾何內容恰好封頂於 $H^3$ 一層、不再更深——**這一半（封頂）是定理**，且不依賴下述比較。另一半須誠實標記：**16-cell 關聯子斷層**（視界的幾何內容，見 **[APP_07](./APP_07_The_Obstruction_Ladder.md)** §5 L3 列）與 cross-context anticommutation 的 modulus $[n_a]$ 指向*同一個 $H^3$ 現象*（同一個 $n=4/n\ge5$ 邊界、同一台 nerve-collapse 機器），但「同一個類」目前是**現象級證據而非定理**：IV↔XX **comparison map**（Paper XX §future work 明文 deferred，含 Čech/$\mathbb{Z}$ 係數的 Dixmier–Douady lift）需要兩條垂直腿——五角星腿已由 **self-representation map** 接上 ambient 類（item 23，closed mod Kudo）；16-cell 腿仍 open（RESEARCH_FRONTIER items 1、7）。因此「視界深度 = $H^3$ 拓撲」的精確狀態是 **await**（等 16-cell 腿）；`%fuel` 量的是把 $H^3$ bulk 坍縮為局部真實所需的能量，其**封頂**照 $\hbar_{n/}$ ceiling 讀（**[APP_06](./APP_06_Unified_Field_Theory.md)** §6.5），該 ceiling 為定理級。（2026-07-03 修正：先前版本把 self-representation map 與 comparison map 當同一物、宣稱「已焊接、為定理」——兩者同名不同物：前者是垂直橋 $\partial\Delta^4\to BV$，後者是水平比較。）

### 3.1 視界半徑與物理防線

引擎遵循由元資訊定義的物理限制，這被視為觀測者的「視界半徑」。規格層僅定義元欄位的 **語義功能**，不強制要求統一的物理單位或預設值。

> **視界參數的規範家 = `~%Config`（2026-07-13 裁定）**：視界屬於**觀測
> 行為**，不屬於被觀測的節點（本節「觀測者的視界半徑」之言下之義，
> 至此明文）。引擎**必須**實作系統軸模組 **`~%Config`**，其欄位以
> **裸名**拼寫（`~%Config.fuel`、`~%Config.timeout`、`~%Config.strategy`、
> `~%Config.max_branches`、`~%Config.max_unification_depth`、
> `~%Config.max_lifting_depth`、`~%Config.max_pattern_nodes`），對
> **單次觀測**全域生效；創世預設值見 SPEC_09 §6。`%` 拼法保留給節點
> 元資訊——`~%Config` 的欄位是觀測參數，不是任何節點的 `%`-meta。
>
> **節點級 `%fuel`／`%strategy` 等 = 參考性提示，非硬性**：`%` 特徵
> 屬性本有引擎實作彈性（SYNTAX_08 §1「寫入是協商」），引擎**可以**
> 採納節點級視界提示（如子樹沙箱燃料帽），**可以**忽略。採納者必須
> 依 §3.2.1 既有義務把**實際生效**的視界參數序列化入 `#blur` CAID
> ——單引擎決定論不受影響；**跨引擎** CAID 一致性僅在 `~%Config` 面
> ＋ MBU 計費表（REAL_01 §10）上保證。節點級預算的轉發代數（min／
> 扣抵／退款）未立法——採納提示的引擎自負其相容性聲明。

> **視界本質**：在 `n/` 宇宙中，視界是 **觀測精度的對價**。燃料的消耗量與目標幾何物件的 **結構複雜度** 成正比。觀測者必須投入與其 **幾何厚度** 相對應的能量，才能將其坍縮為確定的原子。詳見 **[COSMOLOGY/05](./COSMOLOGY/05_PHYSICS_Horizons_and_Uncertainty.md)**。

| 元欄位 | 語義定義 |
| :--- | :--- |
| **`%fuel`** | **空間資源控制**：限制單次收斂觀測涉及的節點展開與遞迴總量（MBU）。 |
| **`%timeout`** | **時間資源控制**：限制單次收斂觀測允許的最大觀測時長（毫秒）。 |
| **`%max_branches`** | **複雜度限制 (分支)**：防止聯集分支過度膨脹導致的狀態空間爆炸。 |
| **`%max_unification_depth`** | **複雜度限制 (深度)**：防止遞迴 Combo 合併或態射應用導致的堆疊溢位。 |
| **`%max_lifting_depth`** | **複雜度限制 (升寫)**：防止管道 `|>` 在處理巢狀容器時發生無限遞迴升寫。 |
| **`%max_pattern_nodes`** | **複雜度限制 (匹配)**：限制單次模式匹配涉及的 AST 節點總量。 |

> **AST 有界工作不計 MBU（2026-08-11 裁定；理由見 O41）**：凡其工作量已由提供給引擎的 AST
> 有限界定者，例如 AST 走訪、字面算術與結構建構，**不得**僅因節點數或語法
> 運算子而扣 `%fuel`。`%fuel` 的責任是保證觀測終止：它計量來源程式可在格上
> 放大的展開、遞迴、態射應用與其他 REAL_01 §9.1 的語義工作；來源 AST 的大小
> 與深度則由剖析器的界線處理。AST 有界工作若實際觸發該等語義工作，仍須按觸發
> 的操作計費。

**規格義務 (Specification Obligations)**：
*   **優先級判定 (Priority Axiom)**：
    - **`%fuel` 優先**：若觀測因耗盡燃料而中斷，引擎 **可以** 根據策略回傳具備決定論 CAID 的 `#blur` 快照。
    - **`%timeout` 降級**：若觀測因物理超時而中斷，引擎 **嚴禁** 回傳 `#blur` 狀態，必須回傳無 CAID 的 `#incomplete` 暫態。這確保了不同運算速率的硬體對同一路徑的觀測事實保持一致。
*   **一致性要求**：在相同的視界參數輸入下，引擎產生的 `#blur` CAID **必須**具備決定論（詳見 **[SPEC_13](./SPEC_13_Ouroboros_Discovery_Protocol.md)**）。
*   **規範化計費 (Standardized Billing)**：為了確保跨引擎的 CAID 決定論，實作者**必須**遵循 **[REAL_01](./REAL_01_Ouroboros_Engineering.md) §9.1** 定義的最小計費單位 (MBU) 進行 `%fuel` 扣除。
*   **配額異常處理 (Quota Validation)**：
    *   **無效配額**：若觀測者設定了非數值、負數或超過物理極限的 `%fuel` 或 `%timeout`，引擎**必須**將其視為 `0` (即立即中斷觀測)，並回傳 `#incomplete` 或 `_|_` (視 `%strategy` 而定)。
    *   **資源繼承**：在遞迴觀測或 `./fetch` 過程中，若未顯式覆蓋配額，子觀測**必須**繼承並共用父觀測的剩餘配額。嚴禁在子觀測中「非法獲取」額外的隱性燃料。
*   **燃料消耗時機 (Consumption Timing)**：僅在**觀測階段 (Observation)** 消耗資源。當觀測者引發格論收斂或態射應用時，引擎開始對涉及的遞迴、分派、驗證或展開操作進行計費。

#### 3.1.1 最小計費單位 (Minimum Billing Unit, MBU) **[Core Requirement]**

為了確保跨引擎的 CAID 決定論與 OODP 互通性，本節定義標準的燃料消耗表。引擎**必須**遵循以下權重進行 `%fuel` 扣除：

| 操作 | MBU 消耗 | 說明 |
| :--- | :---: | :--- |
| **原子合併 (`&`)** | 1 | 兩個原子值的基礎合併。 |
| **Combo 欄位對齊** | 1 + 0.1 × n | 欄位數 n（無前綴 + @ + % + / + ~ + ~%）。 |
| **態射應用 (`/f x`)** | 10 + 5 × (模式深度) | 基礎 10，每層嵌套模式 +5。 |
| **函子升寫 (`%fmap`)** | 5 × 容器深度 | 深度從 1 開始計算。 |
| **單子綁定 (`%bind`)** | 8 × 管道長度 | 管道中每個態射消耗 8 MBU。 |
| **聯集展開 (`\|`)** | 2 × n | n 為展開後的分支數。 |
| **譜幾何計算 (LADD)** | 50 + 100 × dim | dim 為投影算子維度（以 64 為單位）。 |
| **ω/q 指紋知識證明驗證 (STARK)** | 500 | 每次 STARK 驗證的固定開銷。數字基於舊複數電路估計；待 $\mathbb{F}_2$ 指紋電路（APP_02 §6）校準，預期下修。〔2026-07-28 更名，原「GPP 驗證」；且該驗證現屬**選用**——持有屬執行軌，見 REAL_02 §7〕 |
| **外部 FFI 調用** | 100 + 50 × 參數量 | 基礎 100，每個參數 +50。 |
| **CAID 計算** | 20 + 5 × 節點數 | 規範化與雜湊計算。 |
| **Binary-n/ 序列化** | 2 × byte 數 | 將 AST 轉換為位元流。 |

##### 計費累積與溢出

- **累積原則**：所有操作消耗採用**無條件進位 (Ceiling)**，最小消耗為 1 MBU。
- **溢出判定**：當累積消耗 ≥ `%fuel` 時，觀測立即中止，回傳 `#fuel_exhausted`。
- **部分計費**：觸及視界時，已消耗 MBU **不會**退還。

##### 引擎差異容許範圍

由於硬體架構差異，實作允許以下容許範圍：
- **標準作業**：實際消耗必須在表中值的 ±10% 範圍內。
- **證明驗證 (STARK)**：實際消耗必須在 ±20% 範圍內（因 GPU/CPU 差異）。
- **報告義務**：引擎必須在 `~%Engine./profile` 中提供實際消耗統計，供開發者校準。

### 3.2 觀測狀態機 (Observation State Machine)

引擎在增量收斂過程中，必須遵循以下狀態變遷規律：

| 狀態 | 屬性 | 說明 |
| :--- | :--- | :--- |
| **未觀測 (Lazy)** | 潛在 (Potential) | 節點已定義但尚未被任何路徑抵達。不消耗燃料。 |
| **已收斂 (Exact)** | 穩定 (Stable) | 運算已終止，結果為原子、Combo 或 Cocoon。具備唯一 CAID。 |
| **衝突 (Conflict / `_\|_`)** | 終態 (Terminal) | 偵測到邏輯不相容或發散。具備帶有因果鏈的穩定 CAID。 |
| **不完全 (#incomplete)** | **暫態 (Transient)** | 觀測因觸及視界（燃料/時間耗盡）而中斷。**不具備 CAID**，嚴禁提交 (Commit)。 |
| **模糊 (#blur)** | **快照 (Snapshot)** | 視界截面。**具備決定論 CAID**，可參與發現與提交。代表特定限制下的觀測事實。 |

*註：`#incomplete` 僅存在於主動觀測的內存中。若引擎根據 `%strategy: #blur` 決定將中斷點轉化為可傳遞狀態，則該節點從 `#incomplete` 提升（Lift）為 `#blur`。*

#### 3.2.1 語義邊界：暫態與快照

> **軸的定義已移出本節（2026-08-09）**：「狀態／原因／來歷」與載體分類的規範性定義在 **[TAG_REGISTRY](./TAG_REGISTRY.md) §0**。本節保留的是這條軸在**值面**的兩個具體成員（`#incomplete` 與 `#blur`）及其定址義務。此前本節與 **[REAL_02](./REAL_02_Ouroboros_Protocols.md) §3.2.1** 各自獨立地定義了同一個二分——**連節號都相同**。
*   **#incomplete (不完全)**：代表觀測精度的「掛起」。它不是一種數據，而是一種「計算請求的餘額」。由於其結果隨時會隨燃料增加而變動，因此不具備內容定址的合法性。任何將 `#incomplete` 標記為 Commit 內容的行為都必須導致 `#privileged_commit` 權限校驗或直接坍縮為 `_|_`。
*   **#blur (模糊)**：代表觀測精度的「凍結」。它是對「當前視界參數 + 局部收斂結果」的內容雜湊。在 LADD 協議中，`#blur` 扮演了真理的預留空間。
    - **CAID 計算義務**：`#blur` 的 CAID **必須**包含序列化後的視界參數（%fuel 等，見 **[REAL_03](./REAL_03_CAID_Protocol.md)**）。

#### 3.2.2 視界傳播律（值語境；2026-07-13 裁定，G3）

視界值一旦產生，**任何後續消費不得改寫其本體地位**——`#blur` 是快照、
`_|_` 是衝突，二者不可互鑄：

1. **值語境吸收**：值語境（算術運算元、原子比較 `==`／`!=` 運算元、
   一元運算、態射體內的任何值語境）遇 `#blur` → 結果為**該 `#blur`
   原樣傳出**（cause／CAID／視界參數保全；效果標籤照 max 合併；
   `partial` 快照不參與後續運算）。與 `_|_` 吸收律同構——**不得**鑄成
   `_|_ #conflict`、**不得**默默回傳布林。
2. **引數是載體，不是消費者**：態射應用／管道的引數綁定只**攜帶**
   `#blur`，不消費；吸收發生於體內第一個值語境。綁定／force 邊界
   不得將 `#blur` 改鑄。
3. **cause 誠實**（2026-08-09 改寫，見下方按語）：視界 cause **必須**是
   **實際耗盡者**的名字，且 Strict 之 `_|_` 與 `#blur` 之 `%cause` **同拼**。
   燃料耗盡 → `#fuel_exhausted`；觀測／統一化深度耗盡 → `#max_depth_exceeded`；
   時限超出 → `#timeout`。`#divergent` **保留給偵測到的循環**（如座標自指
   `a: a + 1`）；不可判定的 runaway（引數遞增之無界遞迴）**不得**被僭稱為發散
   ——它**必須**回報實際耗盡的那一項資源。

   > **按語（2026-08-09）**：本款原文寫「不可判定的 runaway ＝誠實
   > `#fuel_exhausted`」。**該處方在 2026-08-09 被量測推翻**：語料向量
   > `L2-21 runaway-cause-honest`（`/recursive: x -> /recursive (x + 1)`）
   > 在參考實作中先耗盡的是**深度**而非燃料，故「誠實」的名字不是
   > `#fuel_exhausted`。本款原文成立於一個只設想 CPU／時間兩種資源的時期；
   > 而依 **[TAG_REGISTRY](./TAG_REGISTRY.md) §0.1**，**原因集是開放的、只增不減**
   > ——把處方綁在某一個原因名上，每新增一種資源就要改寫一次本款。
   > 改為「依實際耗盡者」之後，本款不再隨資源種類增長而過期。
   > **本款真正在守的那條線未變**：資源耗盡**不得**被說成語義裁決
   > （`#divergent` 是「我看見了循環」，不是「我停了」）。
4. **meta 觀測**：`#blur` 之 `%cause` 觀測回其 BlurCause 標籤(`%type`
   讀法 2026-07-19 隨 REAL_04 §1 調和退役——化石別名;`#blur` 上的
   `.%type` 依 #5 座標吸收律吸收)；
   `%caid` 觀測回快照 CAID 字串（2026-07-14 增——快照身分之全可判
   比較入口：`x.%caid == y.%caid` 為字串原子比，無需新語法）。
    - **穩定性承諾**：一旦固化為 `#blur` 的 Commit，其語義不再隨物理環境變動。它代表「在特定限制下的觀測事實」。
5. **座標語境吸收**（2026-07-14 裁定）：非 meta 段導航遇 `#blur` →
   該 `#blur` 原樣傳出——視界後的座標不可知，**不得**鑄
   `_|_ #invalid_path`（那是「知道路徑無效」的僭稱）。聯集逐支導航下，
   `#blur` 支投影仍為 `#blur` 支而**存活**於結果（僅 `_|_` 支剔除，
   SPEC_07 投影律不變）——視界不得因窄化而靜默消失。
6. **集合家族 `=` 二段律**（2026-07-14 裁定）：固化後任一側為 `#blur`：
   (a) 兩側皆 `#blur` 且 CAID 相同 → **`#true`**（觀測決定論：同快照
   ⟹ 同真值；與聯集去重之合併判準同一關係——G1 唯一等值之延伸）；

   > **可達性按語（2026-08-10）**：(a) 自 2026-07-14 訂立起至 2026-08-09 為止
   > **從未可達**。當時的 `#blur` CAID 收了實例鹽與剩餘燃料兩個執行期讀數，
   > 於是同一支程式裡兩個**逐字相同**的運算式也拿到不同的 CAID，判定一律落入 (b)。
   > REAL_03 §7.3 之下的 CHS 使 (a) 第一次成為可以打到的分支
   > （實測：`p == q` 於兩個相同的 `#blur` 上回 `#true`）。
   > 記此，因為**一條沒有任何程式能執行到的條款，與一條不存在的條款在證據上無法區分**
   > ——它不會失敗，所以它不會被發現。
   (b) 其餘（異 CAID 雙 `#blur`、`#blur` 對定值）→ 判定本身在視界後 →
   左側優先之 `#blur` 原樣傳出（**不得** `#false`——同文異綁定之雙快照
   可證同值，「確定不等」為謊）。序判定 `<`／`<=` 於 combo／union
   全域未實作（另案），不在本款。

#### 3.2.2 觀測狀態遷移邏輯 (Transition Logic)

引擎在增量收斂過程中，必須遵循以下狀態變遷規律：

1.  **`Lazy` → `Incomplete`**：首次觀測節點，但計算因觸及視界限制（`%fuel` 耗盡或 `%timeout` 超時）而中斷。
2.  **`Incomplete` → `Exact`**：後續觀測提供了額外燃料，且計算成功收斂至穩定值。
3.  **`Incomplete` → `Conflict`**：後續觀測提供了額外燃料，但偵測到邏輯矛盾（如正交子空間合併）。
4.  **`Incomplete` → `Blur`**：根據策略（`%strategy: #blur`），將掛起的不完全態轉化為具備決定論 CAID 的可傳遞狀態。
5.  **`Blur` → `Exact` / `Conflict`**：當更高精度的 Commit（精煉）被導入宇宙時，動態觀測視窗透過「自動重定向」轉化為精確態或衝突態。

**不變性要求**：
- **單調性**：一旦進入 `Exact` 或 `Conflict` 狀態，嚴禁退回 `Incomplete` 或 `Blur`（除非切換 Commit 歷史）。
- **快取一致性**：`Exact` 結果的優先權永遠高於 `Blur` 與 `Incomplete`。
- **固化隔離 (Commit Isolation)**：自動重定向**嚴禁**影響已固化歷史 Commit 中的節點語義。精煉僅作為一種「建議」，必須透過顯式的演化管道進入歷史。

#### 3.2.3 觀測視窗與重定向邊界 (Observation Window)

為了平衡「開發時的靈活性」與「歷史的不可變性」，引擎必須明確界定 **觀測視窗** 的生命週期：

*   **開啟時機 (Window Open)**：
    1.  進入演化管道 (`|>`) 的求值過程。
    2.  執行系統原語 `~%Engine./observe` 或 `~%Discovery./fetch`。
    3.  處於 REPL 的互動式暫存區 (Staged Area)。
*   **重定向特權**：在視窗開啟期間，引擎獲取 **「幾何重定向特權」**。若觀測到 $ID_{blur}$ 且系統已知其對應的 $ID_{exact}$，則在內存中執行靜默替換。這確保了觀測者總是能看到當前燃料下最精確的真實。
*   **關閉時機 (Window Close)**：
    1.  觀測結果被寫入 **Commit (固化)**。一旦寫入歷史，該節點的 CAID 即被凍結，不再受後續精煉影響。
    2.  觀測結果被返回給外部系統（如 FFI 或 CLI 輸出）。
*   **語義隔離義務**：引擎必須確保關閉後的靜態數據 **嚴禁** 發生追溯性的重定向。這保護了內容定址宇宙的因果一致性。

#### 3.2.4 視界邊緣的狀態坍縮 (Strategy)

當運算觸及視界邊緣（燃料耗盡、超時、或超過最大分支/深度限制）時，節點會根據 `%strategy` 進行語義選擇：

| 策略 | 行為 |
| :--- | :--- |
| **`#blur` (預設)** | 容許將 `#incomplete` 作為有效狀態傳遞，讓宇宙維持在「部分觀測」的聯集狀態。具備決定論 CAID，可參與發現與提交。 |
| **`#strict`** | 任何觸及視界邊緣的運算立即判定為衝突 `_\|_`，確保宇宙的絕對清晰度。適合需要嚴格確定性的關鍵路徑。 |
| **`#approximate` (近似收斂)** | 允許引擎在資源不足或分支過多時，切換至啟發式收斂策略，以犧牲部分幾何精確度換取在有限資源內的近似解答。具備決定論 CAID，但標記為 `#approximate` 以區別於 `#exact`。 |

*   **實作義務**：近似算法的具體細節（如隨機性種子與版本化）由環境層定義，詳見 **[GUIDE_02: 引擎優化指南](./GUIDE_02_Engine_Optimization.md)**。

#### 3.2.5 執行差異與 CAID 穩定性 (Execution Variation & CAID Stability)

**核心原則**：CAID 的決定論僅保證「結構身分」的穩定性，不保證「數值結果」的位元級一致性。

| 層面 | 決定論來源 | 是否受執行策略影響 |
| :--- | :--- | :--- |
| **結構身分（CAID）** | EML 樹/AST 的規範化結構（靜態） | ❌ 否 |
| **數值結果（觀測）** | 硬體浮點運算（動態） | ✅ 是（在容差內） |
| **譜特徵（Sketch）** | 投影算子的幾何特徵 | ⚠️ 穩定（誤差在量子化閾值內視為相同） |

**EML 執行範例**：

```nlang
;; EML 樹結構（靜態）
/ln: 2.0    ;; 語義上等價於 eml(1, eml(eml(1, 2.0), 1))

;; 觀測結果（動態）
#eml_native 策略: 0.6931471805599453    ;; 純 EML 計算，誤差較大
#expanded_opt 策略: 0.6931471805599453  ;; 硬體 log 指令，誤差較小
```

**重要區分**：
- 兩種策略產生的 **CAID 相同**（因為結構相同）
- 兩種策略產生的 **數值結果可能微異**（在 IEEE 754 容差範圍內）
- 這是預期行為，非錯誤

**數值比較語義**：
```nlang
/ln(2.0) == /ln(2.0)     ;; ✅ 結構相等（比較 CAID）
/ln(2.0) === /ln(2.0)    ;; ⚠️ 數值相等（可能因執行差異而 #false）

;; 推薦：使用誤差容忍比較
abs(/ln(2.0) - 0.693) < 1e-10   ;; ✅ 數值近似相等
```

**效果標記**：
- 引擎使用優化執行時，**應**標記 `%effect: #approximate`
- 這允許下游觀測者識別「數值結果可能因硬體/策略而異」的情況

### 3.3 增量收斂與視界快取

Ouroboros 維護有向無環圖（DAG）來追蹤視界內的依賴關係。
*   **局部無效化**：當視界內的某個定義改變時，僅重新觀測受影響的下游。
*   **惰性求值**：只有當觀測者試圖穿透視界看向某個節點時，該節點才會從「潛在狀態」坍縮為「觀測狀態」。

### 3.4 系統反映 (System Reflection)

除了虛擬元欄位 (`%`) 提供的靜態幾何自省外，Ouroboros 引擎透過**系統物件 (`~%`)** 向觀測者反映其當前的會話狀態、提示符與特權層級。

*   **語義區分**：`%` 欄位描述「節點是什麼」；`~%` 物件描述「引擎正在做什麼」。
*   **交互參照**：關於 `~%Repl` 的詳細結構、環境合成 (%import) 以及控制介面的規格，詳見 **[SPEC_11: 反映與合成](./SPEC_11_Reflection_and_Synthesis.md)**。

### 3.5 Bohrification 投射 ($Q \dashv B$)

Bohrification 伴隨（Paper VI）描述了全域量子代數 $Q$ 與其古典語境 sheaf $B = \Gamma(\mathcal{C}(A))$ 之間的雙向投射。引擎提供兩個內建操作：

| 操作 | 方向 | 功能 | 對應 |
|:---|:---:|:---|:---:|
| `~%Engine./project_down` | $Q \to B$ | 將量子 Combo 投影到指定 MASA 語境，產生 `#blur` 局部截面 | Bohrification |
| `~%Engine./project_up` | $B \to Q$ | 從多個古典語境的局部截面重建全域量子疊加態 | L-S reconstruction |

**`project_down` 行為：**

```nlang
~%Engine./project_down {
    target: @Combo         ;; 要投影的量子態
    masa:   @caid          ;; 目標 MASA 的 CAID（REAL_03 v2 格式）
}
;; 結果：target 在 masa 語境下的局部截面（#blur）
```

**`project_up` 行為：**

```nlang
~%Engine./project_up {
    sections: [@Combo]     ;; 從多個 MASA 取得的局部截面
}
;; 結果：各截面的量子疊加態（#exact or union of #blur）
```

> **數學保證注意**：`project_up` 的理論基礎是 $Q \dashv B$ 伴隨的 left adjoint $\mathcal{Q}$，其顯式構造目前為開放問題（系列論文 Paper VI, Conjecture）。
> 當輸入截面來自不相容的量子態時，輸出可能為無物理意義的疊加——引擎應以 `#blur` 標記此類情況。此限制不影響向下操作的 `project_down`（其數學保證來自 Bohrification 的標準結果）。

**限制：**
- `project_down` 需要目標 MASA 的 CAID 具有 `<masa_ref>`（v2 格式）。
- `project_up` 的輸入截面必須來自不同的 MASA（同一 MASA 的多個截面無疊加意義）。
- 兩者皆受當前 `%fuel` 視界限制：`project_up` 需要至少 $2 \times$ 標準 meet 的燃料。

## 4. 代數效果系統 (Algebraic Effect System)

`n/` 的副作用追蹤基於格論聯集。效果（Effect）被視為一種特殊的標籤集合，隨觀測路徑向上傳播，追蹤子空間的干涉與糾纏。

### 4.1 效果的多重性與組合 (Multiplicity)

*   **基礎標籤**：`#pure` (預設), `#io`, `#nondet`, `#state`, `#cached`。
    - `#pure`：么正變換，不與環境糾纏。
    - `#io`：與外部子空間進行觀測交換。
    - `#nondet`：包含非決定性坍縮（如隨機數）。
    - `#state`：依賴或修改環境投影狀態。
    - `#cached`：曾有干涉結果已被固化為穩定 CAID 投影。

*   **組合矩陣 (Effect Composition Table)**：
    當兩個節點（或態射與參數）的效果進行組合時，結果標籤遵循「資訊疊加」原則。`#pure` 為單位元。

| & | #pure | #io | #nondet | #state | #cached |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **#pure** | #pure | #io | #nondet | #state | #cached |
| **#io** | #io | #io | #io \| #nondet | #io \| #state | **#io \| #cached** |
| **#nondet** | #nondet | #io \| #nondet | #nondet | #nondet \| #state | **#nondet \| #cached** |
| **#state** | #state | #io \| #state | #nondet \| #state | #state | **#state \| #cached** |
| **#cached** | #cached | #io \| #cached | #nondet \| #cached | #state \| #cached | #cached |

*註：`#io` 與 `#nondet` 為「活動副作用 (Active Effects)」，代表尚待物理執行的不確定性。`#cached` 為「固化副作用 (Solidified Effects)」，代表其歷史因果雖包含 IO，但結果已錨定於穩定 CAID。兩者組合時應並行標註，以利於引擎執行部分快取重用與增量收斂。*

*   **效果冪等律 (Effect Idempotency)**：效果標籤的組合遵循格論聯集性質。在任何觀測路徑下，$E \mid E = E$。引擎在合成 `%effect` 欄位時，必須對標籤集合進行去重化簡，嚴禁產生如 `#io | #io` 的冗餘描述。

*   **CAID 參與義務**：`%effect` 欄位被視為節點幾何本體的一部分，**必須**參與 CAID 的規範化計算。這確保了語義上不純的程式無法透過偽裝為 `#pure` 來獲取相同的內容標識。
    - **參與範圍**（2026-07-25 釐清）：參與者為**核心標籤集合**（`#pure`／`#io`／`#nondet`／`#state`／`#cached`）。`#ext:` 的**識別碼**不參與（見下條），僅其活動語義位入 CAID——上述目的不受影響。

    - **兩個住處是一個欄位（MUST，2026-08-17 新增）**：實作**得**在內部把「使用者寫下的
      `%effect`」與「引擎沿 §4.2 傳染算出的效果」分開保存，但二者是**同一個欄位的兩個來源**，
      而本條的參與義務治的是**有效值**（即 `.%effect` 所讀者）。**傳染而得的效果不得因為
      住在別處而不進 CAID。**
      〔量 2026-08-16，某實作〕`app: { v: "written-down" }` 與 `app: { v: ~%Env./get(…) }`
      （同值）提交後**位址相同** ⟹ **一個從外部讀進來的值與一個打進去的值，位址無法區分**——
      本條上方所寫的目的因此未達成，而那個程式甚至不需要「偽裝」。
    - **正準形：欄位缺席即 `#pure`（MUST，2026-08-17 新增）**：`#pure` 是效果格的單位元，
      故**只有非單位元的效果得落成欄位**；有效效果為 `#pure` 時**必須**不帶該欄位。
      〔量〕此前 `{ %effect: #pure, v: 1 }` 與 `{ v: 1 }` 的 `.%effect` 皆讀 `#pure` 而**位址不同**，
      違反 [REAL_03](./REAL_03_CAID_Protocol.md) §6.7「位元組為值之函數」。
      **兩條界線**：
      **①** 判準是**格的 ⊥**——`#cached` **不是**單位元（§4.2.4 的固化語義靠它），**必須**落成欄位；
      **②** 正規化**必須**在 §4.3 宣告守護**之後**，且**僅當有效效果確為 `#pure` 時**才得去欄位。
      顯式寫入優先於引擎標籤（見下）意味著使用者寫得出一個**假的** `#pure`，而那正是守衛要抓的謊；
      **搶在守衛之前去欄位，等於消滅那個謊而不是抓到它。**

*   **元欄觀測（`.%effect` 讀取）**（2026-07-20 增訂）：任何非 `_|_` 節點的效果標籤得經 Lens 讀取：`x.%effect` → 標籤原子；未標注者預設 `#pure`。開放 Combo 讀得 §4.2.1 傳染 join 之結果；Cocoon 依屏蔽讀得 `#pure`；聯集依投影律逐支分配（SPEC_07）；顯式寫入的 `%effect` 欄位（SYNTAX_08 可寫元欄）優先於引擎標籤。`_|_` 之元讀白名單（`%cause`/`%caid`）**不變**——`%effect` 不在其中，⊥ 照 F1 傳過；`#blur` 同（吸收）。觀測顯示之效果尾註見 SPEC_11 §3.4（診斷註解層）。

*   **自訂效果標籤 (`#ext:`)**（2026-07-25 降級裁定 A）：`#ext:` 是**引擎本地的出處（provenance）標籤**，
    **不是**核心格元素。引擎**得**（非必須）為其外部邊界操作附加之，以利審計與診斷；不行使此許可
    的引擎完全合規（`oo` 現不行使）。
    - **格式**：`#ext:<identifier>`（例如 `#ext:file_write`、`#ext:db_query`）。
    - **語義貢獻＝僅「活動」一位**：`#ext:` 標籤在效果格中**等同於它所依附的活動標籤**（預設 `#io`；
      提供者得指定 `#nondet`／`#state`）。它**不引入新的障礙種類**——`#ext:file_write` 與 `#ext:db_query`
      同屬「值不由內容決定、依賴外部子空間」這**同一個**障礙，差別僅在出處。故傳染（§4.2）、聯集
      （§4.1）、固化（§4.2.4）、宣告守護（§4.3）與 `runPure` discharge（§4.3）一律**按其依附的活動標籤
      處理**，不因識別碼而分歧；引擎**不得**在識別碼上分派語義。
    - **不入 CAID**：識別碼**不參與** CAID 規範化計算，與 **REAL_03 §7**「嚴禁納入任何非標準 `#ext:`
      標籤」對齊。理由＝**跨引擎決定性**：識別碼屬引擎本地詞彙，未實作該邊界的引擎無法重算同一
      CAID。僅其活動語義位入 CAID——故本節 CAID 參與義務的目的（不純程式不得偽裝 `#pure` 取得相同
      標識）**完整保存**；而僅出處相異者（`#ext:a` vs `#ext:b`）**不產生 CAID 位移**。
    - **顯示歸診斷層**：識別碼經 **SPEC_11 §3.4 診斷註解層**呈現（效果尾註已在該層）；正式觀測通道
      `.%effect` 回報其**依附的活動標籤**。依 §3.4 不可見性義務，識別碼**不得**為任何具語義地位資訊的
      唯一載體。
    - **關聯**：跨引擎自訂詞彙的一般問題（同 `%predicate` 之處置）歸 **R2 帳**。

### 4.2 傳染與傳播規則 (Propagation)

1.  **結構傳染**：若 Combo 的任一欄位具備效果 $E$，則該 Combo 自身的 `%effect = parent.%effect | E$。這確保了外部觀測者在接觸容器時就能預知其內部的潛在副作用。
    *   **Cocoon 隔離 (Shield)**：若容器為 **Cocoon `{{ }}`**，則上述傳染規則在 Cocoon 邊界停止。Cocoon 自身的 `%effect` 保持為 `#pure` (或其定義層級的效果)，內部的副作用被「封印」在視界內，扮演量子退相干屏蔽。
2.  **態射傳染**：態射 $f$ 應用於 $x$ 時，結果的效果為 $Effect(f) \mid Effect(x)$。這防止了純態射在處理不純輸入時遺失效果標記。
3.  **解封傳染 (Unboxing)**：使用 `...` 運算子展開一個具色 Cocoon 時，其內部的效果標籤將立即污染目標作用域。
4.  **停止邊界與固化 (Solidification)**：
    - **轉化規則**：一旦數據被坍縮並獲得穩定 CAID，其 `%effect` 欄位中的 **活動標籤 (#io, #nondet, #state)** 必須在觀測結果中被轉化（固化）為 **#cached** 標籤。
    - **語義**：這象徵著該資訊的「不確定性」已被歷史固化。
    - **重新激活**：若一個 `#cached` 節點參與了新的態射運算，且該態射本身具備活動副作用，則結果將重新獲得活動標籤（見 §4.1 組合矩陣）。

### 4.3 效果遮蔽與處理 (Masking / Handlers)

為了讓帶副作用的程式碼能在純粹語境下安全運行，`n/` 提供以下機制：

*   **`~%Effect./runPure`**：這是一個特殊的系統態射，用於將特定的副作用「坍縮」為穩定數據。
    *   **授權條件**：此操作**僅能**在目前視界具備有效的 `%privilege_token`（即特權模式）時被呼叫，且該視界之能力**必須**涵蓋 `#effect_override`（§6.1.4 能力格）。
    *   **選擇性 discharge（2026-07-25 裁定 Q1/Q2）**：授權是**逐標籤**的。設視界之 `#effect_override` 能力集為 $C$、傳入節點強制執行後的**活動**效應集為 $E$：
        - $C \supseteq E$ → discharge，結果 `%effect` 固化為 `#pure`。
        - $E \not\subseteq C$ → 坍縮 `_|_`（含 `%cause: #privileged_required`），**不做部分 discharge**。名為 `runPure` 的態射**絕不得回傳非純值**（命名誠實；同 §4.3 宣告守護「說謊即崩潰」之紀律）。
        - **僅活動標籤參與覆蓋判定**：`#cached`（§4.2.4 已固化歷史）不是 discharge 對象，不得因其存在而拒絕授權。
        - **閘是能力而非參數**：未獲 `#effect_override` 能力時，**連純參數亦拒**——discharge 是一個特權**操作**，而非對參數的條件加工。
    *   **語義固化**：它將傳入的含副作用節點強制執行，並將結果節點的 `%effect` 標籤「固化」為 `#pure`。這向引擎承諾：「此處產生的 `#io` 已被外部環境代理，對後續的格論觀測可視為純粹且決定性的數據」。此操作不影響原始定義的 CAID，僅影響觀測結果。
*   **宣告守護（Declaration Guard）** **[2026-08-25 改寫，O74；本版之前稱「靜態守護」]**：
    顯式的 `%effect: #pure` 宣告，若被該值**實際帶有的活動效應**反證，引擎**必須**將其阻擋並坍縮為 `_|_`（含 `%cause: #effect_violation`）。

    *   **判準是障礙，不是可見性（MUST）**：被檢查的是「**這個值的障礙是不是零**」——`#pure` 的意義是**該值完全由其 CAID 決定，全域截面存在**（[REAL_03](./REAL_03_CAID_Protocol.md) §6.9 之「位址決定值」，對這個值成立且無格外的觀測座標）。**靜態可見性只是今日實作查得到的子集，不是判準。** 舊稱「靜態守護」把**實作手段**寫成了**本體**，本版更正；「靜態」一詞此後只作為實作註記出現。
    *   **施用即觀測（MUST，O74 ①）**：凡內建**施用呼叫者所提供的態射**者，該次施用所觀測到的效應**必須**併入結果的效應，**不論該態射的回傳值是否被留在結果裡**。**障礙不是資料流性質**：一個謂詞為了決定去留而讀了時鐘，把回傳的布林丟掉**不會使那次觀測沒有發生**。
    *   **`_|_` 不得被折疊為假（MUST，2026-08-26 用戶裁定；D33 射程，O77）**：凡內建**施用呼叫者所提供的態射**者，若該次施用坍縮為 `_|_`，引擎**不得**將該結果與「該態射回傳 `#false`（或任何其他非真值）」折疊為同一個答案。塌陷**必須可分辨**——最低限度是結果本身或其 `%cause` 足以讓觀測者判定「有一次施用坍縮了」。**本款不要求中止**：同 [SPEC_10](./SPEC_10_Evolution_and_Commit.md) §4.1.2，要修的是**報告**不是中止。**本款與「施用即觀測」是同一條責任的兩面**——那一款治「觀測發生了卻沒被記下」，本款治「觀測崩了卻被當成一個答案」。

        > **判例（實測，引擎 v0.36.0）**：`~%List./count` 對同一份清單 `[1,2,3]`，謂詞回
        > `#true` → **3**；回 `#false` → **0**；回 `5` → **0**；**回 `_|_` → 0**
        > ——後三者**同一格**。〔讀 `builtins/list.rs`〕實作逐字以
        > `result.to_string_plain().trim_start_matches('#') == "true"` 判真 ⟹
        > **它問的是「印出來是不是字串 `true`」，不是「是不是真」**；同一行亦使字串
        > `"true"` 與原子 `#true` 同格（謂詞回 `"true"` → **3**）。
        > **對照**：普通施用路徑做得對——`~%Math./add ((1 2), 1)`、態射體回 `_|_`、
        > 引數為 `_|_`，三者皆得 `_|_` ⟹ 折疊只發生在內建自己寫的 callback 迴圈裡。
        >
        > **⚠ 未兌現宣告（§2.4）**：本款於本版無實作兌現，已於
        > `meta/WORK_QUEUE.md` Inbox 開列並升為 Ready。
        >
        > **為什麼這不是「現況其實沒錯」**：現況在格論上**是**單調的——`_|_` 不是 `#true`，
        > 故不計數。缺陷不在答案，在**不可分辨**：觀測者分不出「謂詞說不」「謂詞塌了」
        > 「引數放反了」。這正是 CALM 那一格已裁的形狀（`meta/oo/commit.md` §1.1.7）——
        > 格與判準都分不出正當與不正當的塌陷，**回報是那個區分唯一能住的地方**。

    *   **繭是 discharge，不是漏洞**：`{{ }}` 屏蔽副作用（其實際效應即 `#pure`）是**逃生門而非缺陷**——繭是一個**自帶截面的局部 frame**，傳染在其邊界停止。
    *   **未宣告者不受本款拘束**：未宣告的活動值照常追蹤流通。本款治的是**謊**，不是效應本身。

    > **判例（實測，引擎 v0.34.0 → v0.35.0）**：守護此前看不穿**一層態射應用**。
    > 〔量〕`{ %effect: #pure, v: ~%Time.now _ }`／巢狀／進 list **三者皆坍縮**，
    > 而 `{ %effect: #pure, v: ((x -> ~%Time.now _) 1) }` **被收下**。
    > 最鋒利的一格：`~%List./map ([1,2,3], (x -> { t: ~%Time.now _, r: 1 }.r))` 的每個元素
    > **都印著 `;; %effect: #io`**、`.%effect` 答 `#io`，**而站在旁邊的守衛說沒問題**。
    >
    > **「把守衛改成去讀值」單獨並不足夠**〔量〕：效應此前只在**態射的回傳值被實際放進結果**時存活
    > （`~%List./map` 放進去了，故 `#io`；`~%List./filter`／`/take_while` 把謂詞的布林用完就丟，
    > 故值**自己**答 `#pure`）⟹ 守衛就算去讀，也讀到一個假的值。**兩款必須一起做**。
    >
    > **保守宣告不是替代品**〔量〕：`~%Query./where` 此前以無條件的 IO 底線擋下不純謂詞，
    > 代價是 `~%Query./where ([{ a: 1 }], (r -> #true))` ——一個**什麼都沒觀測**的謂詞——
    > 在 `%effect: #pure` 之下同樣坍縮。**擋得住不等於判得對**；施用即觀測成立之後該底線即移除。

### 4.4 觀測配額預設行為 (Quotas Default)

若觀測過程中耗盡了 `%fuel` 或 `%timeout`：
*   **預設行為**：引擎採用 **`#blur`** 策略，返回一個包含已知資訊與 `#incomplete` 標記的聯集態。這能保證互動式環境（如 REPL）不會因為單個複雜節點而完全鎖死。
*   **生產建議**：在關鍵的業務路徑中，建議顯式設定 `%strategy: #strict`，確保只有完整收斂的結果才能被提交。

## 5. 外部邊界與 FFI 異常處理

`n/` 的格論模型與現實世界的互動是透過 **外部邊界 (External Boundary)** 實現的。外部世界（HTTP、SQL、傳統函式庫）被視為一種「不穩定的聯集來源」。

### 5.1 副作用的坍縮 (IO Collapse)

1.  **非決定性映射**：一個 `#io` 請求（如 HTTP GET）在 `n/` 中被視為對該 CAID 內容的觀測請求。
2.  **物理合成**：引擎負責進行物理層操作，並將回傳結果轉換（Synthesize）為 `n/` 的 Combo。
3.  **格論固化**：一旦結果進入 `n/` 視界並被觀測，該結果必須被 **坍縮 (Collapse)** 為一個帶有 CAID 的靜態定義，才能與其他節點進行交集合併。這防止了外部世界的變動破壞 `n/` 的不變性。

### 5.2 外接系統介面 (Foreign Interface)

*   **SQL 合成**：數據庫查詢結果被合成為包含數值索引的 List 或帶有 Key 的 Combo。
*   **HTTP 映射**：請求與回應模型被對齊為特定的型別邊界。

### 5.3 FFI 異常處理 (FFI Panic Handling)

外部邊界（FFI）是 `n/` 決定論宇宙的最脆弱點。

*   **純粹性與沙箱**：若外部函數標記為 `#pure`，引擎**必須**遵循 **[REAL_01](./REAL_01_Ouroboros_Engineering.md) §5.2.1** 定義的沙箱隔離義務，確保環境欄位與時間不影響觀測結果。
*   **物理崩潰 (Panic)**：若外部程式發生段錯誤 (Segfault) 或未捕獲的異常，引擎**必須**捕獲此崩潰，並將該觀測節點坍縮為 `_|_`，標記 `%cause: #ffi_panic`。
*   **惡意回傳 (Malformation)**：若外部程式回傳了與預期型別不符或物理格式錯誤的 Combo 結構，引擎將其判定為 `_|_`，標記 `%cause: #ffi_malformed`。
*   **安全性原則**：外部邊界的錯誤**嚴禁**導致 `n/` 引擎本身的程序退出（Exit）。引擎必須維持物理穩定性，僅讓發生錯誤的邏輯路徑坍縮。

## 6. 權限與特權模式 (Privileged Mode)

特權模式提供繞過格論約束的能力。為了守護宇宙完整性，其安全管理被視為**核心規格義務 (Core Requirement)**。

### 6.1 准入與安全義務

1.  **實體隔離**：引擎實作者**必須**保證特權指令與普通收斂指令在物理線程或內存空間上具備可審計的隔離。
2.  **令牌強制化**：執行特權操作**必須**提供有效的 `%privilege_token`。嚴禁進行任何「隱式」或「無令牌」的特權後門。
3.  **因果標記**：由特權操作產生的所有變更，其 `%cause` **必須**標記為 `#privileged_*` 標籤，以維持全域溯源透明度。
4.  **能力格（2026-07-25 裁定 Q1）**：特權**不是布林,是一個格值**。視界持有的能力由 §6.2 各操作分別授予——授予某一操作**不蘊含**授予其他操作。其中 `#effect_override` 的能力**再攜一個效應標籤集**（可 discharge 哪些活動標籤，見 §4.3）；其餘操作目前為布林。**兩軸**：軸一 = 哪個操作，軸二 = `#effect_override` 內哪些標籤。
    *   **能力的格運算**：能力之**聯集**（多次授予累加）與**交集**（權限收緊）皆為逐欄運算；`#pure`/無能力為單位元。精煉能力即收緊權限。
    *   **不可觀測**：能力屬視界（horizon）而非節點——**不參與 CAID、不可由程式讀取**（可讀將構成視界依賴的旁通道）。它改變的是「收斂過程」而非「幾何指紋」（同 §6.2 語義保證）。
    *   **僅可信通道**：能力**只**能經程式外的可信通道建立（如 CLI 旗標、引擎初始化）。程式內**無**任何路徑可自授權或提升能力（§6.1.2 無後門）。旗標拼法與令牌生命週期屬 **REAL_02**，非語言規格。
    *   **軸一涵蓋對外撥號（MUST，2026-07-30 擴充）**：能力格原僅治理**格與歷史操作**（§6.3 亦如此陳述）。本次擴充加入第三類:**使引擎主動對外連線者**——目前為 `~%Discovery./connect` 之遠端形式（**[REAL_02](./REAL_02_Ouroboros_Protocols.md)** §4.2.6）。
        - **理由**：其他兩類治的是「這個宇宙會變成什麼」，此類治的是**「誰得以花這個節點的時間、誰得以知道它在找什麼」**。二者不同族，但需要的機制同一個:逐次出示、帶外、不留存、不可自授權。以能力格承載，比另立一套弱機制正確。
        - **不蘊含（MUST NOT）**：依本節「授予某一操作**不蘊含**授予其他操作」，出示 `#pin` 等**不得**解鎖撥號，反之亦然。
        - **界限**：本擴充**不**觸及 §6.3 的儲存邊界，該邊界仍為**無條件**、不受任何能力解鎖。

### 6.2 特權操作清單與審計

| 操作 | 說明 | 審計標籤 (%cause) |
| :--- | :--- | :--- |
| `#pin` | 直接覆蓋節點值，跳過收斂邏輯（**唯一動及格本體的特權操作**）。 | `#privileged_pin` |
| `#rollback` | 移動 HEAD 指標至任意歷史 Commit。 | **放棄紀錄**（見下，2026-07-26 修訂） |
| `#squash` | 壓縮 Commit 歷史片段，使其脫離可達鏈。 | `#privileged_squash` |
| `#effect_override` | 強制將含副作用節點標記為 `#pure`。 | `#privileged_effect` |
| `#gc` | **回收本地儲存中不可達之物件位元組**(2026-07-29 新設,見 §6.2.1)。 | 無標記——它不入鏈,見下 |

> **`#commit`（含衝突）之退役**（2026-07-26 裁定）：原列有 `#commit`＝「強制提交含有 `_|_` 的 Staged 狀態」。量測顯示該描述無對應閘位：**含 `_|_` 值的欄位本就可正常提交、不需特權**（`#blur`／部分觀測允許 `_|_` 進入宇宙，§4.4）；而真正被拒的是**根與 staged 的衝突**，且拒於 **evolve 邊界**（演化軸），非提交期。若要在該邊界強制覆寫，那就是 `#pin` 本身——故 `#commit` 為重複條目，移除。提交期的特權義務改由下列**授權時點**條款承擔。

> **`#rollback` 的審計＝放棄紀錄**（2026-07-26 裁定 R1，修訂原「無（由歷史鏈追蹤）」）：原條文所稱之「由歷史鏈追蹤」在 `n/` **不成立**——回溯後歷史自新 HEAD 沿 parent 走，**被放棄的整段離開歷史**；其物件雖仍存於 store，卻**無任何介面能列舉之**。（git 得以如此宣稱是因其另有 reflog；`n/` 無，且 `n/` 中歷史鏈的地位遠高於 git——**鏈本身即紀錄**。）
> *   **義務**：`#rollback` **本身不產生 Commit**（它只移動指標），但**回溯之後的下一個 Commit 必須記錄被放棄的 HEAD**（一次或多次回溯則全數記錄）。此紀錄存於 **Commit 元資訊**，**不得**寫入任何節點值（§6.2 幾何指紋）。該時點即分歧真正進入鏈之時。
> *   **推論（歷史圖的兩種邊）**：歷史自此具備兩類邊——`parent`（收斂血緣）與**放棄邊**（分歧標記）。二者共存仍為 DAG（無環、無合併歧義）。放棄邊即**反單調操作在歷史上的顯影**。

> **`#squash` ＝ 遺忘的唯一入口**（2026-07-26 裁定 R2）：
> *   **得壓過放棄紀錄**：`#squash` **得**壓縮掉區間內的放棄紀錄；其自身之 `#privileged_squash` 標記將該事實承接下去。故**細節（granularity）可失，事實不可失**——鏈上永遠留有「此處發生過特權移除」。壓縮一個壓縮，結果仍帶標記。
> *   **須同時斷開兩類邊**：`#squash` **必須**同時使區間內的 `parent` 邊與**放棄邊**脫離可達鏈（**【2026-08-31 射程更正，D52】**本款寫於 `Commit.parent` 是唯一祖先載體之時。D52 之後新的 Commit **不再設定** `parent`，祖先改由 Savepoint 上的祖先邊承載（**[SPEC_10](./SPEC_10_Evolution_and_Commit.md)** §3.1）。**本款所拘束的是「承載祖先的那條邊」，不是欄位的名字**——舊物件仍為 `parent`，新的為祖先邊，兩者皆在射程內。**要求未變，只有它指名的載體變了。**）；否則被放棄的 Commit 因放棄邊而**永久可達**，任何以可達性為準的回收都將永不生效。
> *   **推論（規範性）**：`#squash` 是**唯一**能使物件成為不可達的操作。故「使之不可達」永遠是一次**受特權且自我標記**的行為，而其後真正回收位元組者，得為**機械且無特權**的可達性掃描。**遺忘不得自動發生**。
>     *   **【2026-07-29 修訂,本條兩處已被 §6.2.1 之裁定推翻】** 上文假定**放棄邊賦予可達性**(故要求 `#squash` 必須連放棄邊一併斷開,否則被放棄之 Commit 永久可達)。§6.2.1 裁定**放棄邊不是可達性根**,於是:
>         1.  「`#squash` 是**唯一**能使物件成為不可達的操作」**不再成立**——`#rollback` 亦然,且**立即**如此,不必等 `#squash`。**應讀作:`#squash` 與 `#rollback` 是使物件成為不可達的兩個操作。**
>         2.  「回收者**得為無特權**」**不再適用**——見 §6.2.1「為何回收本身也是特權」。
>     *   **未被推翻者,且正是本條要保護的**:**使之不可達永遠是一次受特權且自我標記的行為**。二操作皆需能力(`--grant squash` / `--grant rollback`),皆於鏈上留下標記或放棄紀錄。**不可達從來不是任何程序的副作用**——這一句不因操作從一個變成兩個而改變。
>     *   「`#squash` 必須同時斷開兩類邊」之要求**予以保留但改其理由**:不再是「否則永久可達」(放棄邊本就不賦予可達性),而是**壓縮之後,那些放棄紀錄所指之物在鏈上已無任何一處提及,留著邊即留下一個指向無名者的指標**。
> *   **審計可查驗性**：審計標記與人類訊息**必須可資區辨**。若觀測者無法憑檢視分辨「引擎設定之標記」與「恰好如此書寫之訊息」，該審計面即不成其為審計面。
>     *   **推廣（2026-07-27 新增，規範性）**：本條適用於**使用者所能供給之全部文字，而非僅其首行**。實作**必須**確保呈現審計面時，使用者供給之文字（提交訊息、作者、路徑等）**無法產生任何一行與引擎標記相同之輸出**。量測判例：某實作為提交訊息加上前綴以資區辨，但僅加於首行，故 `-m $'x\n    privileged_effect'` 之次行原樣輸出，與真標記逐位元組相同——而該次提交未持有任何能力。**訊息不是一行**；逐行處理，或改由標記側採使用者無從產生之形式。

**語義保證**：
*   **CAID 一致性**：特權操作產生的節點與 Commit，其內容雜湊（`%id`）依然基於其最終的物理結構計算。特權操作改變的是「收斂過程」，而非「幾何指紋」。**推論（規範性）**：審計標記**不得**存放於節點值之內——任何寫入值的干預痕跡都會移動其 CAID。其歸屬為 **Commit**。
*   **透明度**：由特權操作產生的 Commit 必須在元資訊中標註其干預性質，以便下游觀測者進行信任評估。
*   **授權時點（2026-07-26 新增，規範性）**：特權**必須於施加特權效果的當下**、經 §6.1.2 之可信通道出示。若一個特權操作跨越多個階段（如「演化期標記、提交期套用」），則**每一個實際施加效果的階段都必須各自出示能力**。
    *   **意圖 ≠ 授權**：階段之間得以本地狀態（檔案、暫存區等）記錄**意圖**，但該記錄**不得**被當作授權依據。實作**必須**假定本地儲存可被非特權程式寫入（引擎得對程式開放檔案寫入能力），故單憑其存在推導特權即構成 §6.1.2 所禁之無令牌後門。
    *   **作用範圍最小化**：特權效果**僅**得施加於**明確被特權操作指名**的座標；同批次中其餘變更一律沿用普通格語義。特權不得因共處一次提交而外溢。
    *   **出示者必須涵蓋所施加者（2026-07-27 新增，規範性）**：後續階段所出示之能力，**必須涵蓋前一階段實際施加之效果**；出示**某個**能力不等於出示**該**能力。以 `#effect_override` 為例，若演化期放行之活躍標籤集為 $E$，則提交期所出示之能力集 $C$ **必須**滿足 $C \supseteq E$（同 §6.1.4 軸二）——否則將以一個**當初根本無法授權該放行**的能力，授權其固化進歷史。**推論**：階段間所記錄之意圖，其內容**必須足以讓後續階段做此判定**（僅記「發生過」的布林值不足）。
    *   **標記必須反映事實而非旗標（2026-07-27 新增，規範性）**：審計標記所斷言者，**必須**是實際發生之干預，**不得**僅因能力在場或特權操作被呼叫即標記。以 `#effect_override` 為例，其定義為「強制將**含副作用**節點標記為 `#pure`」；對本已為 `#pure` 之節點施用，**無任何效果被覆寫**，故該次提交**不得**被標記，亦**不得**因此要求能力。斷言未曾發生之干預，與隱匿已發生之干預，同屬**會說謊的審計面**。

#### 6.2.1 `#gc`:回收不可達之位元組 **[Core Requirement,2026-07-29 新設]**

`#squash` 與 `#rollback` 使物件離開可達鏈,而在此之前**沒有任何東西回收它們**——實測:五次提交後一次 `#squash`,11 個物件中 7 個不可達、**60% 的位元組**成為垃圾,而儲存**變大了**。本節規定如何把它們拿掉。

**可達性之根(MUST)**:

1.  `HEAD` 所指之 Commit;
2.  自各 Commit 之 `parent`,遞移;
3.  自各 Commit 之 `root`,及該值樹中任意深度之每一個位址。

**此外皆非根。** 尤其:

*   **`CommitMeta.abandoned` 不是根(MUST NOT,本弧裁定)**。被 `#rollback` 放棄之 HEAD,其**內容**成為可回收。
*   `staged` 之內容為內聯值、不以位址指涉物件儲存,故它**不提供**可達性;但它**不得**被刪除。
*   `architects.json`、`pin_pending`、`effect_pending` 承載斷言與意圖,非位址。

> **「放棄邊不是根」之理由,與其代價**。此裁定承 §6.2 `#rollback` 條之「**細節可失,事實不可失**」:事實是記於 `CommitMeta.abandoned` 的那個位址,**它不會消失**——`oo log` 永遠印得出來。消失的是它所指之內容。
>
> 代價有二,**皆須向操作者浮現,不得埋沒**:
> *   審計行成為**一個可能解析不到的名字**。實作**必須**標示之(例如 `(content collected)`),且該標示**必須**由當下的儲存查詢決定,**不得**改用回收時寫下的旗標——旗標是關於「位元組是否存在」的第二個真相來源,而位元組本身才是真相。
> *   **回收之後,`#rollback` 是單向的**。實作**必須**在**動手之前**告知此事。

**回收本身也是特權(MUST)**:`#gc` 需要 `#gc` 能力(CLI `--grant gc`)。

> §6.2 原推論曾言回收者「得為機械且無特權」,其理由是:`#squash` 已經替「使之不可達」付過特權的代價,其後的清掃對**意義**是恆等的。**本弧使該理由失效**:放棄邊既非根,回收就會銷毀「一個已被記錄之事實所指之內容」,並使 `#rollback` 由可逆變為不可逆。**那不是對意義的恆等變換。** 故清掃回到與 `#squash`、`#rollback` 同一道閘——**「遺忘不得自動發生」由能力格執行,而非仰賴無人去呼叫它**。

**其餘義務**:

*   **絕不自動發生(MUST NOT)**:不得於提交、初始化、開啟、背景或任何操作之副作用中回收。
*   **不可解碼者不是垃圾(MUST)**:解不開的物件**可能是損壞但可達的物件**,屬 **[REAL_03](./REAL_03_CAID_Protocol.md)** §6.6 之完整性事件,**必須回報而不得掃除**。**掃除你讀不懂的東西,是讓一次損壞變成一次刪除。**
*   **只動物件儲存(MUST)**:僅得移除 `.oo/objects/` 之下未被標記者。
*   **冪等**,且對無垃圾之儲存**須明言其為零**,不得以沉默作答。
*   **本地性**:可達性按構造是本地的。全域 GC **原則上不可能**——無全域 HEAD 即無全域可達性根(disc 025);此處回收之物件,可能是全世界僅存的一份。實作**應**於報告中明示此事。
*   **並發**:引擎**不**鎖定工作區。`#gc` 與其他寫入者並行可致資料遺失;實作**必須**聲明其預期獨佔使用,而**不得**佯稱有所保障。

**這條紅線覆蓋到哪裡為止(MUST,2026-07-29 新增)**:「遺忘不得自動發生」治的是**使已記錄事實的內容成為不可達**。它**不覆蓋整個 `.oo/`**。

判準有三,須同時成立才落入本條:

1.  該內容曾被**提交**進歷史;
2.  有**已記錄的事實**指名它(`parent` 鏈、Commit 的根值樹、或 `CommitMeta.abandoned` 之類的審計行);
3.  移除它使某個既有操作**由可逆變為不可逆**。

三者皆不成立者,自動移除**得**於無能力下發生。判例:**耐久對等目錄**(REAL_02 §5.1.2)之被取代記錄——它從未被提交、無任何已記錄事實指向它、清掉它不使任何 `#rollback` 變為不可逆。它是網路快取,不是歷史。

> 寫下這條界線,是因為 §6.2 的紅線措辭強而位置顯眼,而 `.oo/` 底下此後會住進愈來愈多**不是歷史**的東西。一條被過度外推的紅線,結果是每一個快取都得出示能力才能清理自己——那不會使任何事更誠實,只會使「特權」一詞變得廉價。
>
> 反向的誤讀同樣要防:**「它只是快取」不是自動移除的理由,判準才是。** 一份被提交的值不因有人稱之為快取而離開本條。

### 6.3 儲存信任邊界 (Store Trust Boundary) 【核心規格義務，2026-07-26 新增】

§6.1.2 禁止無令牌後門、§6.2 要求審計標記與授權時點——但這些閘全都裝在**操作**上。若語言層能以路徑觸及引擎儲存（`.oo/`），則每一道閘都可被繞過：直接改寫 `HEAD` 即得 `#rollback` 之效果而不需其能力，且**留下的審計痕跡比合法路徑更少**。本節將 §6.2 授權時點條款推廣至儲存本身。

#### 6.3.1 儲存的兩層

引擎儲存**不是一層而是兩層**，而兩層需要的機制**恰好互斥**：

| 層 | 內容 | 自我認證 | 所需機制 |
| :--- | :--- | :---: | :--- |
| **物件層** | 內容定址物件（CAID → 值/Commit） | **是**——位址即內容 | **驗證**；不需權限 |
| **斷言層** | `HEAD`、暫存區、意圖記錄、白名單等指標與宣稱 | **否**——是宣稱，非內容 | **認證**；無從驗證 |

物件層不需要任何權限系統：偽造在定義上不可能——不信任寫入者，重算位址即可（這正是全球格與 peer 交換的運作方式，見 **[REAL_02](./REAL_02_Ouroboros_Protocols.md)** §3 解析瀑布）。斷言層相反：`HEAD` 是「我在哪」這個**索引性**事實，沒有東西可拿來對照，是唯一真正需要信任的部分。

**還有第三種東西，而它正因為是第三種而不在儲存裡【2026-07-27 補】**：操作者的**私鑰**。它既非物件（無從驗證：位址不會告訴你這把鑰匙該是誰的）亦非斷言（無從認證：它不宣稱任何事），它要的是**隱蔽**——而隱蔽是內容定址與格論框架完全無話可說的那個性質。既然 `.oo/objects` 正是**設計來被對等點取用、被連同倉庫複製**的成品，秘密就不得住在其中：它住在工作區之外，見 **[REAL_01](./REAL_01_Ouroboros_Engineering.md)** §7.5。

#### 6.3.2 規範條款

*   **路徑定址之拒絕（MUST）**：語言層的檔案系統原語（讀、寫、附加、存在性查詢，以及任何以檔案系統路徑為參數者）**必須**拒絕落入引擎儲存的路徑。判定**必須**在解析 `.`、`..` 與符號連結**之後**進行，並以**路徑元件**為單位比對；**不得**以字串前綴比對（`.oo_peer_a`、`.oomisc`、`foo.oo` 皆非儲存）。
*   **無條件（MUST）**：本邊界**不受任何能力解鎖**。§6.1.4 能力格治理的是格與歷史操作、以及對外撥號（2026-07-30 擴充之軸一第三類），**不治理儲存的物理位元組**。若特權能開此門，特權程式即可偽造 §6.2 所依賴的審計紀錄，該保證將自我閉環。
*   **拒絕之可辨識性（MUST）**：拒絕**必須**坍縮為 `_|_` 並帶 `#store_boundary`（**[TAG_REGISTRY](./TAG_REGISTRY.md)** §1.5），**不得**回傳與尋常結果同形之值。存在性查詢尤然：拒絕與「檔案不存在」若無法區分，該面即不成其為審計面（同 §6.2 審計可查驗性）。
*   **邊界作用於「路徑定址」，非作用於儲存內容**：以 **CAID** 定址取得或存入物件的語言層介面**不在**本邊界之內，且**不應**被納入——物件層自我認證，無可保護之物。被禁止的是**以路徑指涉儲存**，因為路徑不是身分。
*   **引擎自身不受限**：引擎經其儲存介面之存取不經此邊界。本邊界是**語言表面**的邊界。
*   **操作者私鑰亦在界內（MUST）【2026-07-27 新增】**：語言層的檔案系統原語**必須**同樣拒絕**操作者身分檔**之路徑（**[REAL_01](./REAL_01_Ouroboros_Engineering.md)** §7.5）。該保護**不得**依賴其路徑恰好含有儲存目錄名之元件——預設位置 `~/.oo/identity` 固然因此被順帶涵蓋，但覆寫後的路徑可以不含該元件，而**憑巧合成立的保護不成其為保護**。拒絕之判定同樣須在解析符號連結之後進行（否則以連結指向私鑰即可繞過），且**同一目錄下的其他檔案不受影響**——被拒絕的是那個路徑，不是那個目錄。

#### 6.3.3 誠實範圍聲明【規範性】

實作**必須**如實陳述本邊界的涵蓋範圍，**不得**以其暗示更強的保證：

*   **涵蓋**：以語言撰寫之程式，經語言層原語對儲存的路徑存取。
*   **不涵蓋**：帶外竄改（另一個進程、shell、同步工具、編輯器）。能寫入儲存者通常亦能替換引擎二進位，故本邊界對此類對手**不提供任何保證**。防守帶外竄改所需者為**驗證**（物件層，見 **[REAL_03](./REAL_03_CAID_Protocol.md)**）與**認證**（斷言層，見 **[REAL_01](./REAL_01_Ouroboros_Engineering.md)** §7），二者與本邊界正交。
*   **已知代價**：元件式保留名意味著**位於任何名為儲存目錄之目錄底下的工作區，其語言層檔案存取將全數被拒**，而非僅該目錄本身不可及。此為明知之取捨——換得的是無需 base_dir、無 TOCTOU 窗口、且前綴陷阱在結構上不可能發生。

#### 6.3.4 設計理由

安全工程的「不一致 = 攻擊訊號 → 拒絕」與 `n/` 的「衝突不是錯誤、模糊是誠實」看似對立，實則作用於**不同階數**：

*   **0 階（身分層）**：這些位元組是不是它宣稱的那個東西？此處 `n/` **毫不留情**——CAID 精確相等，無模糊、無容差。
*   **≥1 階（語義層）**：在東西確實是它自稱的那個之後，它們彼此同意嗎？此處**分歧是內容**，不是錯誤。

**0 階的不留情，正是買下 ≥1 階那份寬容的代價。** 敢說「衝突是資訊」，是因為從不需要懷疑那些衝突的東西是不是它們自稱的東西。工程手段不是束縛誠實，而是**保證誠實是真的誠實**。

**推論（非規範，記錄）**：局部自洽而與全球格不合的歷史，在本框架下**不是錯誤而是障礙**（非平凡上同調類，階 ≥ 1）——引擎的職責不是在本地判定謊言，而是使分歧可量測。

### 6.4 設計理由

特權模式的存在不是鼓勵繞過格論，而是承認現實：有時開發者需要強制修復一個引擎無法自動解決的邏輯衝突，或對已知正確的值進行直接注入（如從數據庫載入的快取）。

*   **安全管理**：特權 Token 的發放、生命週期與撤銷機制不屬於語言規格，詳見 **[REAL_02](./REAL_02_Ouroboros_Protocols.md)**。
