# SYNTAX_12：演化管道、條件收斂與上下文 (Pipe, Ternary & Context)

> [!NOTE] 定位
> 本章為**語法細則**（規範性，位階在 SPEC 之下；見 **[SYNTAX_00](./SYNTAX_00_Conventions.md)**）。文法上位規範見 **[SPEC_14](./SPEC_14_Formal_Grammar.md) §2.3**（L13 `|>`、L14 `? :`）與 §2.4（`context = "$"`）；語義以 **[SPEC_07](./SPEC_07_Logic_and_Pipe.md) §1.2、§4** 與 **[SPEC_04](./SPEC_04_Navigation_and_Duality.md)** 為準。本章釘死 **`|>`、`? :`、`$`／`^` 的寫法**。（2026-07-05 新寫；同日 `$` 規則 **P1–P5** 定案、三角落全數解除——SPEC_07 §4.2 已依此重寫。）

---

## 1. 語法 (Syntax)

```ebnf
pipe_expr    = { join_expr ~ (!field_start ~ "|>" ~ join_expr)* }               ;; Level 13
ternary_expr = { pipe_expr ~ (!field_start ~ "?" ~ pipe_expr ~ ":" ~ pipe_expr)? } ;; Level 14
context      = @{ "$" }                                                          ;; primary
```

| 寫法 | 意義 |
| :--- | :--- |
| `input \|> /f` | 態射演化（≡ `/f input`，可鏈式） |
| `input \|> { …$… }` | **結構演化**：右側 `{}` 為臨時轉換器，`$` 指向管道輸入 |
| `input \|> #tag` | 原子演化：與原子強制交集 |
| `cond ? a : b` | 條件收斂（糖，展開見 §2.3） |
| `$`／`_.` | 上下文錨點／根宇宙（`^` 僅屬路徑面——SYNTAX_03；規則見 §2.4） |

---

## 2. 語義 (Semantics)

1. **`|>` 是 L13、左結合、對 `|` 分配。** `a |> /f |> /g` ≡ `(a |> /f) |> /g`；`(A | B) |> /f ≡ (A |> /f) | (B |> /f)`（疊加態平等演化，SPEC_07 §4）。演化即提交：中途 `_|_` 則整鏈立即中斷、級聯坍縮（%cause 鏈保留）。
2. **三種右值形態**（SPEC_07 §4.1）：態射／轉換器 Combo／原子。容器輸入的自動升寫（`%fmap`、Cocoon 隔離、`%max_lifting_depth`）是語義層行為，見 SPEC_07 §4.4，本章不重述。
3. **`? :` 是分派糖**（SPEC_07 §1.2）：`cond ? a : b` ≡ `cond |> { #true: a, #false: b, _: _|_ }`——條件須收斂至 `@bool`，非布林輸入落 `_` 分支 → `_|_`。
4. **`$` 規則（P1–P5，2026-07-05 定案；詳 SPEC_07 §4.2）**：

   | # | 規則 |
   | :--- | :--- |
   | P1 | **重綁點唯一**：只在演化邊界重綁（`\|>` 與態射應用）；裸容器永不重綁 |
   | P2 | **管道不可穿透**：無跨管道溯源（`^` 僅路徑面）；外層上下文顯式傳遞——`{val: …, ctx: $} \|> { … $.ctx.name … }` |
   | P3 | **自由 `$` ＝ 開放項**：可定義可儲存；觀測時由最近包圍演化動態綁定；無綁定觀測 → `_\|_`（`%cause: #no_context`）；CAID ＝ 含 `$` 的語法幾何 |
   | P4 | **只指輸入**：不指涉構建中欄位（sibling 用裸名）；tuple 輸入用 `$.0`／`$.1` |
   | P5 | **內插不建作用域**：`${…}` 內的 `$` 與字串外同步 |

## 3. 範例 (Examples)

```nlang
;; 結構演化＋顯式傳遞（P2：不穿透，外層上下文放進輸入）
user: { name: "Alice" }

user |> {
    greeting: "Hello, " + $.name              ;; $ = user
    action: { act: "Login", user: $ } |> {
        msg: `Action: ${$.act}, User: ${$.user.name}`
    }
}

;; 開放項與銜尾蛇一行式（P3；正典測試向量）
s: "Logic" |> { a: $ }        ;; {a: "Logic"}
w: { x: $.s }                  ;; 開放項：自由 $，合法儲存
_: w.x                         ;; _|_ (%cause: #no_context)
v: <<_.>> |> <<_.>>            ;; 根宇宙以自身為轉換器
_: v.w.x.a                     ;; "Logic"（路徑導向觀測；v 全量觀測 → %fuel 視界）

;; 條件收斂
grade: score >= 60 ? #pass : #fail

;; 演化中的匿名態射需括號（SYNTAX_11 §4.2）
r: data |> (x -> x + 1)
```

## 4. 邊界情況 (Edge Cases)

1. **巢狀三元必須括號。** L14 的分支是 `pipe_expr`（L13），**不含**裸三元：`a ? b : c ? d : e` 非法，須寫 `a ? b : (c ? d : e)`。（同理分支內的 `->` 也需括號——L15 鬆於 L14。）
2. **三元的 `:` vs 欄位的 `:`。** 由 `!field_start` 與「單行鍵」規則（SYNTAX_03 §4.9）區分：`k: cond ? a : b` 中第二個 `:` 屬三元（`b` 前的 token 不構成 field_key+`:` 同行模式）。混淆風險高的場合**應**括號整個三元。
3. **`|>` 與 `|` 一字之差。** `|`（L12 聯集）比 `|>`（L13）緊：`1 | 2 |> /f` ≡ `(1 | 2) |> /f`。混用時**應**顯式括號（SPEC_14 §4 範例 A 官方建議）。
4. **`$` 是完整的 primary。** 可導航（`$.val`）、可入約束（`@{ $ & !(..0) }`，SPEC_07 §5.3）、可入內插（`${$}`）。`$` 後的 `.` 是一般 postfix（坍縮讀取，SYNTAX_07 §4.6 適用）。
5. **分派分支值中的 `$` ＝ 被匹配的輸入。** `/fib` 的 `@int: … ($ - 1) …`——因為 `input |> /Logic ≡ /Logic input`（SPEC_07 §4.1），態射應用本身就是一層演化，分支值的 `$` 即繫於該層。
6. **內插不建立作用域。** `` `…${$}…` `` 的 `$` 與字串外完全同步（SPEC_07 §4.2.3）；要取外層須在內插內寫 `^^.`。
7. **Tuple 輸入配態射演化，不配結構演化。** tuple 是**密封**數值 Cocoon（SYNTAX_04 §2.5），而結構演化 `|>` `{}` 的語義是合併新欄位——對密封容器新增欄位正確坍縮 `_|_`（`%cause: #missing_key`）。故 `$.0`／`$.1` 位置輸入（P4）的正典搭配是態射：`(1, 2) |> (p -> $.0 + $.1)` ✓；`(1, 2) |> { s: $.0 + $.1 }` → `_|_` ✗。要**擴充**欄位須先**顯式拆封**——正典寫法唯一：`{ ...t } |> { s: $.0 + $.1 }`（密封預設受尊重、拆封必須顯式；引擎**不**自動展開——隱式拆封＝效應帳目隨輸入種類隱形變動）。效應面無陷阱：tuple 本就不屏蔽效應（SYNTAX_04 §2.5，2026-07-06 裁決），拆封前後帳目一致。（2026-07-06 引擎 #16 實作時釘死——兩規則各自成立，交點行為此前無家。）

> **已定案（2026-07-05，P1–P5）**：原三個待裁角落全數解除——(1) 裸 Combo **不**重綁（P1；SPEC_07 舊 §4.2.2 Level-3 註為 errata）；(2) 無包圍演化的 `$` 於觀測時 → `_|_ %cause: #no_context`（P3；開放項可儲存——不觀測不坍縮）；(3) `^` 僅存路徑面、無作用域面（P2）——跨管道一律顯式傳遞。
> **語義後果：路徑導向（惰性）觀測是語義要求而非最佳化**——`v: <<_.>> |> <<_.>>` 的路徑投影有限、全量觀測自我迴歸至 `%fuel` 視界；引擎必須按需收斂（GUIDE_03；ENGINE_SYNC #16）。
> **信任註記**：開放項被誰 pipe 就被誰綁定（上下文注入）——LADD 來源的開放項對策（如 `%open` 自省標記）屬 REAL／ORDER 排程。
