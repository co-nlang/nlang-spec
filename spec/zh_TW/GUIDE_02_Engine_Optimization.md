# n/ Engine Optimization Guide - 熱帶優化與啟發式策略 (Optimization & Heuristics)

> [!NOTE]: [Standard / 非規範性建議]  
> [!NOTE]: 本指南提供 Ouroboros 引擎實作者進階的優化建議與啟發式策略。這些機制並非規格書的強制要求，但能顯著提升在複雜邏輯宇宙中的收斂效能。

---

## 1. 熱帶幾何優化 (Tropical Geometry Optimization)

熱帶幾何（Min-plus 代數）為 `n/` 的格論運算提供了一套高效的數值映射方法。實作者可以將邏輯約束的「複雜度」轉化為空間中的「厚度」。

### 1.1 語義映射 (The Tropical Mapping)

引擎可將格論運算映射至熱帶半環 $(\mathbb{R} \cup \{\infty\}, \min, +)$：

| 格論運算 | 熱帶對應 | 說明 |
| :--- | :--- | :--- |
| **聯集 `|`** | **$\min$** | 在多個分支中選擇「厚度」最小（最容易收斂）的路徑。 |
| **合併 `&`** | **$+$** | 資訊的疊加等價於幾何厚度的累積。 |
| **萬有集合 `_`** | **$0$** | 無厚度，無資訊量。 |
| **空集合 `_|_`** | **$\infty$** | 無限厚度，邏輯不可達。 |

### 1.2 熱帶剪枝 (Tropical Pruning)

當觀測路徑觸及視界邊緣時，引擎可利用熱帶幾何的單調性進行提早截斷：
*   **路徑評估**：在展開一個複雜的聯集分支前，先估計其熱帶厚度 $W_{branch}$。
*   **截斷條件**：若 $W_{branch} > \text{Remaining } \%fuel$，則引擎可以直接判定該分支在當前視界下不可觀測，從而跳過耗時的統一化（Unification）細節。
*   **語義安全**：這符合 `#blur` 策略的語義，因為它僅是加速了對 `#incomplete` 狀態的判定。

## 2. 啟發式路徑搜尋 (Heuristic Search)

在大規模 Combo 合併中，搜尋順序決定了收斂速度。

### 2.1 A* 搜尋策略
建議引擎實作 A* 演算法來進行邏輯收斂：
*   **$g(n)$ (實際開銷)**：已消耗的 `%fuel`。
*   **$h(n)$ (啟發式估計)**：目標節點的熱帶厚度預估。
*   **優先權**：優先探索 $f(n) = g(n) + h(n)$ 最小的路徑，這能最快找到原子坍縮點。

### 2.2 結構化快取 (Isomorphic Memoization)
*   **熱帶指紋**：除了對 CAID 進行快取，引擎可對特定路徑的「熱帶厚度」進行快取。這有助於在重複存取相似邏輯結構時，立即跳過已知會耗盡燃料的深層路徑。

## 3. 引擎實作技巧 (Implementation Tricks)

### 3.1 向量化統一化 (SIMD Unification)
對於兩個具備大量相同 Key 的 Cocoon（繭）進行合併時：
*   **Bitmask 對齊**：利用 SIMD 指令集（如 AVX-512）同時對多個欄位進行型別相交判定。
*   **分桶處理**：將 Data 欄位與 Logic 欄位分開處理，因為 Data 欄位通常具備更穩定的熱帶厚度。

### 3.2 惰性合併 (Lazy Merging)
對於尚未被觀測路徑觸及的聯集分支，引擎應保持其為「潛在狀態 (Potential)」，僅計算其熱帶指紋而不觀測實際的幾何合併。這在處理大型標準庫（如 `~%Math`）時至關重要。

---

## 4. 參考指標 (Metrics)

建議引擎提供效能分析指標（Profile Metrics）：
*   **`%optimization_gain`**：反映熱帶剪枝減少的節點展開總量。
*   **`%cache_hit_ratio`**：反映 CAID 重定向與熱帶指紋的命中率。
