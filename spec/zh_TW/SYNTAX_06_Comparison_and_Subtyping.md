# SYNTAX_06：比較、子型別與集合運算 (Comparison, Subtyping & Set Operations)

> [!NOTE] 定位
> 本章為**語法細則**（規範性，位階在 SPEC 之下；見 **[SYNTAX_00](./SYNTAX_00_Conventions.md)**）。文法上位規範見 **[SPEC_14](./SPEC_14_Formal_Grammar.md) §2.3**；比較／合併／子型別的*語義*以 **[SPEC_01](./SPEC_01_Foundation_and_Lattice.md)**、**[SPEC_06](./SPEC_06_Unification_Logic.md)** 為準；「衝突 `_|_` 不是錯誤」範式見 **[APP_03](./APP_03_Paradigm_Comparison.md)**。本章釘死**兩個比較家族、子型別判定、集合運算（`|` 聯集／`\` 差集），以及 `_`／`_|_` 在比較下的行為**。（2026-07-05 W1-3：集合運算自「無家」狀態併入本章。）

---

## 1. 語法 (Syntax)

比較運算子（Level 11；合併 `&` 為 Level 10、比其**緊**）摘自 **SPEC_14 §2.3**：

```ebnf
cmp_expr = { meet_expr ~ (!field_start ~ cmp_op ~ meet_expr)? } ;; Level 11
cmp_op   = { "<=" | ">=" | "==" | "!=" | "=" | "<" | ">" }
join_expr = { cmp_expr ~ (!field_start ~ join_op ~ cmp_expr)* }  ;; Level 12: 聯集 | ／ 差集 \
join_op   = { "|" | "\\" }
;; 相鄰優先級（由鬆到緊）：… \ (L12) > cmp_op (L11) > & 合併 (L10) > + - (L9) …
;; & 比 cmp 緊（與 C 相反）——故 (A & B) = A 無需括號。
```

**兩個乾淨分離的家族：**

| 家族 | 運算子 | 判什麼 | 塌縮？ |
| :--- | :--- | :--- | :--- |
| **格論／集合關係** | `<` `<=` `=` `>=` `>` | 子型別／集合包含與相等 | **否**（疊加態適用） |
| **原子比較** | `==` `!=` | 原子值相等／不等 | **是**（須先塌縮） |

> **注意**：`cmp_op` **非結合**（至多一個）——`a == b == c`、`a < b < c` **非法**。`<=>` **不在** `cmp_op`（poset，見 SYNTAX_10）。結構態 `<<x>>` 用雙角括號，**不佔用** `<`／`>`（見 SYNTAX_07），故 `<`／`>` 純為比較。

---

## 2. 語義 (Semantics)

1. **格論／集合關係（`<` `<=` `=` `>=` `>`）——不塌縮，疊加態適用。** 這族判的是**集合（型別）關係**：`<=`／`>=` 子集／超集（子型別）、`<`／`>` 真子集／真超集、`=` **集合相等**（兩集合元素相同）。因為比的是集合本身、不需塌縮成單一原子，故**型別／疊加態也適用**（`@int = @int` → `#true`）。子型別刻畫：`A <= B` 當且僅當 `(A & B) = A`（`&` 比 `=` 緊，無需括號）。「資訊愈多 ＝ 子集愈小」。
2. **原子比較（`==` `!=`）——須先塌縮。** `==` 把兩側**塌縮為原子**再比值；疊加態無從塌縮、即無從比較（得 `_`）。所有 `()` 等價；`#tag` 同名才等價；數字依值（見 SYNTAX_02）。
3. **`=`（集合相等）vs `==`（原子相等）的關鍵差異。** `=` 問「兩集合元素是否相同」（不塌縮，疊加態適用）；`==` 問「塌縮後是否同一原子」（須塌縮）。對已塌縮的原子兩者一致（`1 = 1` 與 `1 == 1` 皆 `#true`）；對型別／疊加態**只有 `=` 適用**；對 Combo，`=` = 固化後外延結構等值（§4 #11）、`==` = 家族誤用 → `_|_ #conflict`（§4 #12）。（`=` 即「雙向子型別」的乾淨布林版——直接回傳布林，不經 `&`-合併而坍縮，見 §4 #3。）
4. **集合運算 `|`（聯集）與 `\`（差集）——L12，最鬆的集合層。** 與 `&`（合併／交集，L10）同屬集合層、皆**不塌縮**；`|` 擴大可能性、`\` 剔除可能性。同級**左結合**：`a | b \ c` = `(a | b) \ c`。（歷史註：差集原以 `-` 書寫；`-` 回歸算術減法後改用 `\`，見 SYNTAX_02 §4.3。）
5. **不是數值大小比較。** `<`／`>`／`<=`／`>=` 判型別包含、不判原子大小——`3 < 5` 不是「3 小於 5」（見 §4 #9）。數值大小**留給標準庫態射**：`~%Math./lt`／`/lte`／`/gt`／`/gte`（SPEC_09 §3，2026-07-20 立法；引擎舊數值序偏差同日退役）。（設計見 `discussion/004`：「多載語義」提案未採納——判大小需先判型別，而子型別判定正是 `n/` 判型別之法。）語義以 **SPEC_06／SPEC_01** 為準。

## 3. 範例 (Examples)

集合關係（不塌縮，疊加態適用）：

```nlang
_: @int = @int                ;; #true（集合相等）
_: {a: 1} <= {a: @int}        ;; #true（子型別：資訊更多 = 子集更小）
_: {a: @int} <= {a: 1}        ;; #false
_: {name: "Alice"} <= {name: @str, age: @int}  ;; #false（開放世界：左側缺 age）
```

原子比較（須塌縮）：

```nlang
_: () == ()          ;; #true
_: #true == ()       ;; #false（Tag ≠ Unit）
_: 1 == 1            ;; #true
```

## 4. 邊界情況 (Edge Cases)

> 逐條釘死比較層的行為。`==` vs `=`（塌縮 vs 不塌縮）與「斷言即衝突」是最易誤解之處。

1. **`==`（原子）有吸收律；`=`（集合）沒有。** 原子比較會塌縮，故 `_`／`_|_` 依吸收律傳播：
   ```nlang
   _: _ == _            ;; _   （資訊不足以判定）
   _: _ == _|_          ;; _|_ （吸收律：與「無」比較皆衝突）
   _: _|_ == _|_        ;; _|_
   ```
   `_|_` 黑洞：`==`／`!=` 任一側收斂為 `_|_` → 整式 `_|_`（`%cause` 合併兩側，見 REAL_04）。**集合關係 `=`／`<=` 不塌縮、不吸收**：`_|_ = 3` → `#false`（空集合 ≠ `{3}`），是乾淨布林。
2. **子型別的極值。** `_|_ <= x` 恆 `#true`（Bottom 是萬物子集）；`x <= _` 恆 `#true`（萬物是 Top 子集）；`_ <= _|_` → `#false`。
3. **`=` 回傳乾淨布林；`_|_` 來自 `&`-合併、不來自集合關係本身。** 早期以 `(A <= B) & (B <= A)` 判相等：不等時 `#true & #false → _|_`（`&` 合併相異原子）。`=` 是此式的**乾淨版**——直接回傳 `#true`／`#false`。但若刻意以 `&` **斷言**（如同座標重複賦值），不成立仍坍縮為 `_|_`（範式：斷言失敗 → 衝突而非布林偽，見 APP_03；純布林防火牆見 SPEC_09 `~%Logic`）。
4. **`<=>` 已入 `cmp_op`（L11 槽，非鏈式）——但屬序位軌。** 回傳**序位標籤聯集**（`#lt`／`#gt`／`#eq`／`#un`，非嚴格如 `#lt | #eq`），永不回傳布林；細則見 **SYNTAX_10**（2026-07-05 定案）。詞法最長匹配：`<=>` 先於 `<=`。
5. **原子用 `==`、集合／型別用 `=`。** 非原子（Combo／型別）的相等用 `=`（集合相等，Combo 細則見 #11）；`==` 僅適用可塌縮的原子——誤用於不可塌縮 Combo → `_|_ #conflict`（#12）。
6. **混血節點：原子 `&` Combo。** 資料原子與資料 Combo 合併，產生既有值又有欄位的**混血節點**：
   ```nlang
   x: 1 & { name: "Alice" }   ;; x == { %val: 1, name: "Alice", %kind: #data }
   ```
   觀測 `x` → `1`（讀 `%val`）；`x.name` → `"Alice"`（進座標空間）。混血節點在 `==` 下塌縮至 `%val` 後照原子家族比（#12）。
   **值語境統一律**（2026-07-13 裁定，G6）：「讀 `%val`」不限觀測顯示——**一切值語境**同律：觀測（坍縮態）、算術運算元（`x + 1` → `2`）、態射應用／管道之引數強迫（`x |> inc` → `2`）、原子比較（#12）。塌縮遞迴（坍縮態顯示中的巢狀混血子節點同樣讀 `%val`）。**但**：座標導航（`x.name`）進座標空間不塌；`=` 家族比外延結構**不剝殼**（`(3 & {note: "n"}) = 3` → `#false`，#11 與 #12 各答各的問題）；無 `%val` 之普通 combo 在算術／原子比較下照舊 `_|_`（剝殼只認 `%val`）。要看**完整節點**（含 `%val`）用結構態 `<<x>>`（SYNTAX_07 觀測對偶）。
7. **`%kind` 防火牆：異類合併 → `_|_`。** 不同前綴／本體論類別的節點合併，即便幾何相同，也因 `%kind` 衝突而坍縮：
   ```nlang
   y: a & @b   ;; #data & #type → %kind 衝突 → _|_
   ```
8. **`&` 比 cmp 緊（與 C 相反）。** 合併 `&`（Level 10）比比較（Level 11）**緊**，故 `A & B = A` 即 `(A & B) = A`——子型別定義式**無需**括號。（C 的 `&` 比 `==` 鬆是著名陷阱；`n/` 因合併是主運算、且子型別倚賴它而刻意調緊，見 SPEC_14 §2.3。）
9. **集合運算比比較鬆——`(a \ b) = c` 需要括號。** L12 鬆於 L11，故 `a \ b = c` 解析為 `a \ (b = c)`，幾乎不會是本意；混用集合運算與比較時**應**顯式加括號（同 SPEC_14 §4 範例 A 對 `|`／`|>` 的建議）。
10. **`3 <= 5` → `#false`（乾淨布林，不是大小、也不是衝突）。** `<=` 問「`{3}` 是否 ⊆ `{5}`」——相異原子的集合不互含：`(3 & 5) = 3` 即 `_|_ = 3` → `#false`（空集合 ≠ `{3}`）。因 `=` **不塌縮、不吸收**，結果是乾淨 `#false`（**非** `_|_`）。數值大小須用標準庫態射。
11. **combo 等值：`=` = 固化後外延結構等值。**（2026-07-13 裁定）`A = B` 於 Combo ⟺ 兩側先**求值固化**（惰性殘影不得殘留），而後六軸（data／rules／types／meta／system／local）、closed 旗、relations **逐欄比對**；巢狀欄位遞迴用**同一等值關係**；欄位書寫順序不參與（集合觀）。幾何等價式：`A = B` ⟺ `A & B ≡ A` 且 `A & B ≡ B`。**效果標籤與來源軸參與等值**——與聯集冪等去重（SPEC_01；conformance L1-28）採**同一個**等值關係：全引擎唯一等值，cmp 與去重不得分家（`{a: 1}@IO = {a: 1}` → `#false`，正如二者聯集不去重）。
    視界運算元:固化撞視界產生之 `#blur` 依 SPEC_08 §3.2.2 #6 二段律
    (同 CAID → `#true`;其餘吸收,不得 `#false`)。
    ```nlang
    _: {a: 1} = {a: 1}          ;; #true（外延結構等值）
    _: {a: 1, b: 2} = {b: 2, a: 1}  ;; #true（書寫順序不參與）
    _: {a: {b: 1}} = {a: {b: 1}}    ;; #true（巢狀遞迴同關係）
    ```
12. **combo 遇 `==` = 家族誤用，大聲失敗。** `==` 僅適用可塌縮原子（#5）。運算元**塌縮後仍非原子**（無 `%val` 之 Combo）→ `_|_ #conflict`——**不得默默 `#false`**（默默 `#false` 是把「不可比」謊報為「比過了、不等」）。混血節點（帶 `%val`，#6）塌縮至原子後照原子家族比：`(3 & {note: "n"}) == 3` → `#true`。`!=` 鏡像（家族誤用同樣 `_|_ #conflict`，**不是** `#true`）。
13. **序 × `#blur`:隨 `=` 二段律。**(2026-07-20 裁定,序關係波 W3)集合關係家族
    (`<`/`<=`/`>`/`>=`)之運算元含 `#blur` 時,依 #11 之視界二段律同法:**同 CAID**
    →同一集合的自反答案(`<=`/`>=` → `#true`、`<`/`>` → `#false`);**其餘**→吸收
    原樣(視界內未定;**不得** `#false`、不得 `#conflict`——把「視界內看不清」謊報
    為「比過了」與「不可比」同罪)。
14. **固化防火牆。** 一切比較家族（`==`／`!=`／`=`／`<`／`<=`／`>`／`>=`）的運算元於判定前**必須固化**；**span 與符號拼寫不得影響任何語義判定**——等值是**值**的性質，不是**來源**的性質（同值綁定 `x: {a: 1}`、`y: {a: 1}` 之 `x = y` 與行內字面量同判）。此條為引擎義務的法典化。
