# SYNTAX_03：路徑與賦值 (Paths & Assignment)

> [!NOTE] 定位
> 本章為**語法細則**（規範性，位階在 SPEC 之下；見 **[SYNTAX_00](./SYNTAX_00_Conventions.md)**）。文法上位規範見 **[SPEC_14](./SPEC_14_Formal_Grammar.md) §2.2、§2.4**；語義以 SPEC 為準；「賦值即交集」「萬物寫入 root」等範式背景見 **[APP_03](./APP_03_Paradigm_Comparison.md)**。本章釘死**座標如何命名、如何賦值**。前綴鍵（`@a:`／`/a:`）見 **SYNTAX_05**；容器結構見 **SYNTAX_04**。

---

## 1. 語法 (Syntax)

賦值的基本單位是**欄位 (field)**：一個鍵接一個表達式。以下摘自 **SPEC_14 §2.2、§2.4**：

```ebnf
field      = { (field_key ~ ":" ~ expr) | spread_expr }   ;; spread-as-field 見 SYNTAX_04 §4.8
field_key  = { anon_set | path | named_key | quoted_key | tag }
named_key  = @{ (prefix? ~ ident) | numeric_key }
numeric_key = @{ numeric }
quoted_key = @{ "\"" ~ (!"\"" ~ ANY)* ~ "\"" }   ;; 含空白或運算子的鍵

path        = { (root_path | parent_path | bare_path) ~ ("." ~ named_key | "[" ~ expr ~ "]")* }
root_path   = @{ "_." }       ;; root 錨定
parent_path = @{ "^"+ ~ "." } ;; 上溯父層
bare_path   = @{ named_key }  ;; 相對當前容器
```

| 形式 | 寫法 | 意義 |
| :--- | :--- | :--- |
| 欄位賦值 | `key: expr` | 把 `expr` 綁到座標 `key` |
| root 賦值 | `_: expr` | 寫入 root（`_:` 是「root 這個鍵」） |
| 點路徑鍵 | `a.b.c: expr` | 巢狀座標（等價巢狀 Combo） |
| root 錨定路徑 | `_.a.b` | 從 root 起算的絕對路徑 |
| 上溯路徑 | `^.x`、`^^.x` | 上溯一／二層父容器 |
| 索引存取 | `a[expr]` | 動態鍵 / 位置存取 |
| 數字鍵 | `0: …`、`1: …` | 位置座標 |
| 引用鍵 | `"my key": …` | 含空白／運算子／數字開頭的鍵 |
| 標籤鍵 | `#adult: "Adult"` | tag 作座標——分派表慣用（值域按標籤分支） |

---

## 2. 語義 (Semantics)

1. **賦值是把約束綁到座標，不是命令式寫入。** `key: expr` 在當前容器的座標 `key` 上*累加*一條約束。`n/` 是宣告式的——欄位**順序無關**（最終都交集進同一個幾何）。
2. **萬物可寫入 root。** `_: expr` 寫到 root；概念上整個程式就是把一堆東西交集到 root。只要不去**觀測**就不會坍縮；即使觀測 root，得到的 `_|_` 也代表**衝突**而非錯誤（範式見 APP_03，吸收律見 SYNTAX_06，成因追蹤用 `%cause`，見 REAL_04）。
3. **點路徑即巢狀座標。** `a.b.c: v` 與巢狀 Combo `{a: {b: {c: v}}}` 等價（見 SYNTAX_04）。
4. **路徑錨定有三種起點。** `_.` 從 root 絕對起算；`^+.` 相對上溯父層；裸鍵相對當前容器。

---

## 3. 範例 (Examples)

### 直覺對照：路徑 ≈ 作業系統檔案路徑

`n/` 的路徑與 OS 檔案路徑**概念一致**——這正是「語義作業系統」的由來，差別只在符號：

| n/ | Unix | 意義 |
| :--- | :--- | :--- |
| `a.b.c` | `a/b/c` | 路徑分隔（`.` ≈ `/`） |
| `_.a.b` | `/a/b` | 絕對路徑（`_.` ≈ 前導 `/`，從 root 起算） |
| `a.b` | `a/b` | 相對路徑（相對當前 Combo） |
| `^.x` | `../x` | 上一層父容器 |
| `^^.x` | `../../x` | 上兩層 |

直覺對應：**Combo ≈ 目錄、座標值 ≈ 檔案**。唯一的關鍵差異是——`n/` 的「寫入」是**交集**而非覆寫（見邊界 #2），且只有在**觀測**時才會坍縮。

### root 與基本賦值：

```nlang
_: ()                 ;; 寫入 root
a: #true
a.b: #false           ;; 點路徑
a: {
    b: {
        c: #success   ;; 等價 a.b.c: #success
    }
}
```

巢狀路徑混寫：

```nlang
a.b.c.d: {
    e.f.g: "Hello"
    h: { i: "World!" }
}
```

## 4. 邊界情況 (Edge Cases)

> 逐條釘死路徑／賦值層曾經模糊的寫法。`_` 與「賦值即交集」是 `n/` 最易誤解之處。

1. **三種 `_` 形，務必分清。** `_`（單獨）是 **Top 原子**（SYNTAX_02）；`_:` 是**對 root 這個鍵賦值**（`_` 作為鍵名 + `:`）；`_.x` 是**從 root 錨定的路徑**。三者形似而義異：`_: x` 寫入 root，`_.x: y` 寫入 root 下的 `x`，而表達式裡單獨的 `_` 是 Top。
2. **賦值是交集，不是覆寫（重要；語義依據 [SPEC_03](./SPEC_03_Combo_System.md)）。** 對**同一座標**重複賦值會**交集 (`&`)**、不會覆寫：

   ```nlang
   a: 1
   a: 2        ;; a == 1 & 2 == _|_（衝突，非「a 變成 2」）
   ```
   驗證模式正是利用這點：`a: @int` 與 `a: 1` 交集為 `1`（符合則保留）。需要「取代」語義時，須在新容器中重新觀測，而非就地覆寫。
3. **欄位順序無關。** 因所有欄位最終交集進同一幾何，`{a:1 b:2}` 與 `{b:2 a:1}` 完全等價；不存在「先後執行」的順序語義。
4. **上溯層數由 `^` 個數決定；過度穿透 (overshoot) 寫入「虛空」，`_|_` 只在觀測時現形。** `^.x` 上溯一層、`^^.x` 兩層，以此類推。當 `^` 數超過嵌套層數時路徑無有效目標——但**賦值本身不觀測**：把值寫到一個解析不到父層的路徑，只是寫入「虛空」，**不**在賦值當下報錯（呼應「不觀測就不坍縮」）。真正的 `_|_`（附 `%cause: #out_of_horizon`，含 `actual_depth`／`requested_depth`）在**觀測**該路徑時才現形（**SPEC_07 §4.2.3**）。實務上 REPL 模式會觀測回傳值，故使用者通常會直接看到 `_|_`。`^` **僅有路徑面**（容器上溯）——**不**跨管道（P2，2026-07-05 定案；SYNTAX_12 §2.4）；管道內取外層上下文一律顯式傳遞。
5. **數字鍵 vs 數字字面量。** 鍵位的 `0:`／`1:` 是**位置座標**（`numeric_key`）；出現在值位的 `0`／`1` 是整數原子（SYNTAX_02）。`0: 0` 合法——左為鍵、右為值。
6. **何時需要引用鍵。** 鍵名含空白、運算子或以數字起首（非純數字鍵）時，**必須**用 `"…"`：`"my key": 1`、`"a+b": 2`。純識別碼鍵**不應**多餘加引號。
7. **`a[expr]` 索引 vs `[…]` list。** 緊接在路徑後的 `[expr]` 是**索引存取**；獨立出現的 `[…]` 是 **list 字面量**（容器，見 SYNTAX_04）。位置決定解讀，兩者**不得**混淆。
8. **點在鍵名 vs 點在路徑。** `a.b: v` 的 `.` 是**路徑分隔**；若需要「名字裡真的有點」的鍵，**必須**用引用鍵 `"a.b": v`（與路徑 `a.b` 語義不同：前者單一座標、後者巢狀）。
9. **鍵與冒號必須同行（單行鍵限制）。** `field_key` 與其 `:` **必須**位於同一詞法行（SPEC_14 §1.1）；冒號前換行會使鍵被讀成**原子**而非欄位起點（值可以換行縮排接在冒號後）。這是 `!field_start` 邊界保護的決定論前提。
10. **標籤鍵是合法座標；內插鍵不是。** `#tag: v` 合法（分派表：以標籤原子為座標分支）。**內插字串不得作鍵**（`` `k${i}` ``: v 非法）——動態鍵會破壞座標的靜態可定址性；需要動態座標時用 `a[expr]` 索引存取。（2026-07-05 裁決：tag 鍵自引擎收編為正典；interp 鍵不收編。）
