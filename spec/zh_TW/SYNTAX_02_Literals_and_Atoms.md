# SYNTAX_02：字面量與原子 (Literals & Atoms)

> [!NOTE] 定位
> 本章為**語法細則**（規範性，位階在 SPEC 之下；見 **[SYNTAX_00](./SYNTAX_00_Conventions.md)**）。文法上位規範見 **[SPEC_14](./SPEC_14_Formal_Grammar.md) §2.4、§3**；語義以 SPEC 為準；「衝突 `_|_` 不是錯誤」等範式背景見 **[APP_03](./APP_03_Paradigm_Comparison.md)**。本章只釘**葉節點（原子與純量字面量）**的寫法；容器（`{}`、`[]`、tuple）見 **SYNTAX_04**，比較運算見 **SYNTAX_06**。

---

## 1. 語法 (Syntax)

原子與字面量是表達式的**葉節點**。以下摘自 **SPEC_14 §2.4**（為上位文法，本章不改寫）：

```ebnf
atom = { bottom | tag_start | tag_end | top | unit
       | float_lit | int_lit | regex_lit | path_lit | bytes_lit
       | uri_lit | time_lit | multiline_str | str_lit | tag }

bottom    = @{ "_|_" }          ;; Bottom（空集合 @{}）
top       = @{ "_" }            ;; Top（@any）
unit      = @{ "(" ~ ")" }      ;; Unit
tag       = @{ "#" ~ ident }    ;; 具名標籤原子
tag_start = @{ "#_|_" }         ;; 序位錨點：Start
tag_end   = @{ "#_" }           ;; 序位錨點：End
int_lit   = @{ "-"? ~ numeric }
float_lit = @{ "-"? ~ numeric ~ "." ~ numeric ~ (("e"|"E") ~ ("+"|"-")? ~ numeric)? }
str_lit       = @{ "\"" ~ (!"\"" ~ ANY)* ~ "\"" }
multiline_str = @{ "\"\"\"" ~ ( ("\\" ~ "\"\"\"") | (!"\"\"\"" ~ ANY) )* ~ "\"\"\"" }
interp_str    = ${ "`" ~ interp_part* ~ "`" }       ;; `…${expr}…`
;; 型別字面量：r" p" b" u" t"
regex_lit = @{ "r\"" ~ … }   path_lit = @{ "p\"" ~ … }   bytes_lit = @{ "b\"" ~ … }
uri_lit   = @{ "u\"" ~ … }   time_lit = @{ "t\"" ~ … }
```

| 字面量 | 寫法 | 種類 |
| :--- | :--- | :--- |
| Unit | `()` | 原子（無標籤單位） |
| 標籤 | `#name` | 原子（具名單位） |
| 整數 | `42`、`-7` | 原子 |
| 浮點 | `3.14`、`-2.0e8` | 原子 |
| 複數 | `2+3i`、`1.5-0.5i`、`-i` | 原子（SPEC_02 §2.2；只出現在表達式位置，不作 range 邊界） |
| 單行字串 | `"hello"` | 原子 |
| 多行字串 | `"""…"""` | 原子 |
| 內插字串 | `` `hi ${name}` `` | 原子（觀測時求值） |
| 型別字面量 | `r"…"` `p"…"` `b"…"` `u"…"` `t"…"` | 原子（正則／路徑／位元組／URI／時間） |
| Top | `_` | 格論極大（集合 `@any`，非資料原子） |
| Bottom | `_\|_` | 格論極小（空集合 `@{}`，非資料原子） |
| 序位錨點 | `#_\|_`（Start）、`#_`（End） | 特殊標籤（Enum，見 SYNTAX_10） |

## 2. 語義 (Semantics)

1. **原子是收斂的葉值。** 原子之間的同一性：所有 `()` 皆等價；兩個 `#tag` 等價**當且僅當**標籤名相同；數字依數值比較。完整的 `==`／`!=` 規則見 **SYNTAX_06**（本章只定原子本身，不展開運算子）。
> **`_|_ (%cause: #x)` 是文件記法，不是正準列印形（2026-09-12，D65）。**
> 本規範各處以該寫法**談論**「一顆成因為 `#x` 的 ⊥」，它出現在註解與散文裡，
> **文法從未定義它**——`bottom` 只有上面那一個裸原子。
> **正準列印形是裸 `_|_`**，成因走診斷註解層（`;; %cause: #x`，
> [SPEC_11](./SPEC_11_Reflection_and_Synthesis.md) §3.4），
> 其正式觀測通道為 `.%cause`。
> **⟹ 引用本規範的輸出時，請以裸原子為準。**
> 〔量 2026-09-12〕該記法在本規範共 **12 處**，全部位於註解、虛擬碼或**有日期的歷史紀錄**中
> ——**歷史紀錄不改寫**，它們對其日期是準確的。

2. **`_` 與 `_|_` 是格論極值，不是資料原子。** 文法上它們是 `atom` token，但本體上 `_` = `@any`（Top）、`_|_` = `@{}`（Bottom，空集合）。它們在觀測／比較下的行為（資訊不足、吸收律）見 **SYNTAX_06**；「`_|_` 是衝突不是錯誤」的範式見 **APP_03**。
3. **型別字面量攜帶剖析期型別。** `r"…"`／`p"…"`／`b"…"`／`u"…"`／`t"…"` 是**原始 (raw)** 內容（不做內插），其前綴在剖析期即標定型別。
4. **內插在觀測期求值。** `` `…${expr}…` `` 中的 `${expr}` 於觀測時收斂後嵌入；其餘字元為字面文字。

## 3. 範例 (Examples)

核心原子：

```nlang
a: ()           ;; Unit
b: #success     ;; 具名標籤
c: -123         ;; 負整數（單一原子）
d: 3.14         ;; 浮點
e: "Hello"      ;; 字串
f: `Hi ${b}`    ;; 內插字串
g: """
   多行
   字串
   """
```

原子同一性（節選；完整表見 SYNTAX_06）：

```nlang
_: () == ()          ;; #true（所有 Unit 等價）
_: #true == ()       ;; #false（Tag 與 Unit 為不同原子）
_: #true == #true    ;; #true
_: #true == #false   ;; #false
_: 1 == 1            ;; #true
```

## 4. 邊界情況 (Edge Cases)

> 逐條釘死原子層曾經模糊的寫法。

1. **`()` vs `{}` vs `@{}` 的三方區分。** `()` 是 **Unit 原子**；`{}` 是**開放的空 Combo**（非原子，仍可被合併出資訊，見 SYNTAX_04）；`@{}` 即 `_|_`（**Bottom，空集合**，不含任何可能性）。三者**嚴禁**混用：`() == {}` 為 `#false`（原子 vs 容器），`@{}` 與 `_|_` 為同一物。
2. **`#_|_`／`#_` ≠ `_|_`／`_`。** `#_|_`（tag_start）與 `#_`（tag_end）是**具名標籤原子**，作為 Enum 的序位錨點（Start／End）；`_|_`（bottom）與 `_`（top）是**格論極值**。兩組形似而本體不同，**不可**互換（細則見 **SYNTAX_10**）。
3. **負號與減法（`-` 逐位置釘死）。** `n/` **有**中綴減法：`add_op = "+" | "-"`（SPEC_14 §2.4，L9）。（歷史註：早期 `-` 被**差集**佔用、當時無中綴減法；差集已改用 `\`（L12，見 QUICK_REFERENCE 優先級表），`-` 回歸算術。）規則：
   - **無空白的 `a-1` 不是減法**——識別碼允許連字號（kebab-case，SPEC_14 §2.2），`a-1` 是**單一識別碼**；識別碼後的減法**必須**以空白隔開（詳見 **SYNTAX_01 §4.8**）。
   - **有空白隔開時，運算元後的 `-` 一律是減法**：`a - 1` 與 `a -1` **皆為**減法——表達式層以前瞻（`apply_expr` 的 `!add_op`）保證 juxtaposition 不吞 `-`。要把負數當作態射的 juxtaposition 參數，**必須**加括號：`/f (-1)`。
   - **表達式起始／運算子之後、緊貼數字的 `-` 是負號**：`x: -123` 得負數原子（字面量內建）。`-` 與數字之間**不得**有空白——`- 123` 為**非法**（負號只存在於字面量內部）。
   - **已裁（2026-07-05，W1-1）**：負號 canonical = **字面量內建**（`int_lit`／`float_lit`／`complex_lit` 之 `"-"?`）；`unary_op` 僅餘 `!`（負號已自 unary 移除，SPEC_14 §2.3 同步）。理由：保住 atom 位置的負數（range 邊界 `-5..5`、序關係），並徹底消滅雙軌。識別碼取負**非原語**：寫 `0 - x` 或 stdlib 態射。
4. **浮點兩側皆須有數字。** `float_lit = numeric "." numeric`，故 `1.` 與 `.5` **非**合法浮點；須寫 `1.0`、`0.5`。
5. **三種字串、各有其用。** `"…"` 單行字串；`"""…"""` 多行字串（內部以 `\"""` 跳脫三引號）；`` `…` `` 內插字串。**`${…}` 只在反引號內插值**——出現在 `"…"` 中為字面文字，不會被求值。
6. **標籤名遵循識別碼規則。** `tag = "#" ~ ident`，故標籤名不得以數字起首（`#1` 非合法標籤）；需要數字或含空白的標籤語義時，改用其他構造（見 SYNTAX_03 引用鍵 / SYNTAX_10 Enum）。
7. **型別字面量不內插。** `u"http://${host}"` 中的 `${host}` 是字面字元，不求值（型別字面量為 raw）。需要動態組字串時用內插字串再轉型。
8. **numeric 僅十進位、無底線分隔。** `numeric = ASCII_DIGIT+`：**無** `0x`／`0o`／`0b` 進位字面量；**無**底線分隔——`1_000` 不是單一數字（會切成 `1` 與識別碼 `_000` 的並列），**嚴禁**如此書寫。
9. **指數需完整浮點形式。** `float_lit` 要求小數點在先（兩側有數字）方可接指數：`1e5` **非**合法浮點（會切成 `1` 與識別碼 `e5`）；須寫 `1.0e5`。
10. **複數字面量是無空白的單一 token。** `2+3i`、`1-2i` 各是**一個**複數原子；`2 + 3i`（帶空白）則是「`2` 加 `3i`」的加法表達式（值相同、AST 不同）。`3i`、`-i` 合法；`a-2i`（無空白、識別碼起首）依 §4.3 是**識別碼** `a-2i`。**`i` 起首的識別碼不受複數侵蝕**（2026-07-06 補齊，SPEC_14 尾端護欄）：`io`、`it`、`i2`、`i-1` 皆為識別碼；裸 `i`／`-i` 仍為虛數單位，`i - 1`（帶空白）是「虛數單位減一」。
11. **字串無跳脫序列。** `str_lit`／`quoted_key` 的文法為 `(!"\"" ~ ANY)*`——**沒有** `\"`、`\n` 等跳脫；單行字串**無法**表示 `"` 字元本身。需要引號的內容用多行字串（其唯一跳脫為 `\"""`，用於內含三引號）；換行等控制字元直接以字面字元寫入。

    > **跨參照（2026-08-20）**：本款為兩者指定了同一條出路，而
    > [SYNTAX_03](./SYNTAX_03_Paths_and_Assignment.md) §1 的 `field_key` 此前**不含
    > 多行形式** ⟹ 該路徑對鍵並不存在。已於同日補入 `multiline_key`（SYNTAX_03 §5 #12）。

12. **印出必為合法源碼（MUST，2026-08-20 新設）。** 任何印出 n/ 源碼的介面，
    其輸出**必須**可被本規格的文法讀回，且**必須**讀回同一個值。
    **不得**輸出實作內部的型別名稱或除錯表示。
    > **判例（實測，v0.26.1）**：多行字串印為 `MultilineStr("a\"b")`——一個
    > **實作 enum 的 debug 形式**，且攜帶本語言單行字串所沒有的 `\n`／`\"` 跳脫
    > ⟹ 讀不回去。**同族病徵在鍵側**：見 SYNTAX_03 §5 #11。
    > 二者為同一條規則的兩面——**輸入端接受、輸出端沒有對應的寫法**。
    > **正準形**：多行字串**必須**印為 `"""…"""`，其內僅有的跳脫為三引號跳脫。
